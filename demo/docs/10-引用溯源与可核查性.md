# 引用溯源：让答案可核查

RAG 相对直接问大模型的最大优势就是可核查：答案里每一句关键论断，能指出它来自哪份文档的哪一段。做不好这一条，企业场景基本没法用——没人敢拿一个说不出依据的回答去做决策。

**可用的引用要做到四件事**：

1. **粒度到片段，不到文档**。指向"《差旅制度》"没有核查价值，要能跳到第 3 页那段原文。所以每个片段必须携带文档标题、页码或原文起止偏移，前端据此高亮定位。
2. **编号由组装阶段统一分配**。材料进上下文时按最终顺序编号，模型只被允许引用这些编号。让模型自己写文档名或链接，它一定会编造。
3. **生成后要校验**。模型会给出不在材料里的角标编号，或者整段没有角标。服务端要做一次校验：无效编号剔除，并要求"没有依据的内容不得写成结论"。这一步很便宜，但显著减少假引用。
4. **原文与展示内容分开存**。喂给模型的往往是清洗、去重、拼好表头的版本，用户点开引用要看的是原始文字。两者混用会出现"引用内容页面上根本找不到"的尴尬。

**角标丢失是最常见的实现错误**：流式输出时按 token 增量渲染，模型生成的 `[3]` 可能被拆成多个片段送到前端，正则匹配不上就原样显示甚至被吞掉。要么在流结束后统一解析角标，要么用不会跨 token 的分隔标记。

**一个容易忽略的产品细节**：引用不是越多越好。把整段材料原样列出来当"依据"，用户会误以为答案逐字来自原文，而实际模型做了改写和归纳。工程上更诚实的做法是只给"支撑该结论的片段"，并在界面上区分"原文引用"和"模型归纳"。
