# 混合检索与 RRF 排名融合

多路召回之后必须把两路结果合成一份有序列表。最直觉的做法是把两路分数加权平均，但这几乎总是错的：向量相似度分布在 0 到 1 之间、集中在 0.7 到 0.9 这一小段；全文相关度分数动不动就是十几几十。两边不归一化直接相加，等于让分数尺度大的那一路说了算，另一形同虚设。而归一化本身又依赖当次结果集，换一个问题尺度就变，参数根本调不稳。

业界因此普遍用**倒数排名融合（RRF，Reciprocal Rank Fusion）**。它完全不看分数，只看名次：某个候选在某一路里排第几名，就贡献 `权重 / (k + 名次)` 这么多分，各路相加得到融合分。`k` 是一个平滑常数，常用取值 60——它的作用是压住第一名的优势，避免头部候选过度集中。

**这个公式有三个好处**：尺度无关（两路谁分布怎样都不影响）、无需训练、参数只有权重和 `k`，可解释也可调。

**权重怎么给**：常见起点是向量 0.7、全文 0.3（本项目的默认值正是 0.7/0.3，`k=60`）。语义为主、关键词为辅的语料适合这个配比；反过来，术语密集的手册、法规类语料可以把全文权重提到 0.5 以上。改权重必须用固定评测集验证，不能凭感觉。

**要注意的两件事**：

- RRF 只看名次，所以**每一路自己取多少候选很重要**。某一路只取 top-10，另一路取 top-100，融合窗口就是 110 个去重候选，实际参与排序的名次分布被窗口大小左右。调召回窗口比调融合权重影响更大。
- 同一块被两路同时命中会天然获得更高融合分，这是设计意图（双路佐证），但也意味着如果全文路失效只剩向量路，融合仍会正常出结果——**问题被掩盖了**。所以两路各自的命中数量要单独打日志，别只看融合后的结果。
