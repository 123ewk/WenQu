# 相似度阈值：怎么判断"知识库里根本没有"

检索永远会返回 top-K 条结果——哪怕语料里毫无相关内容，向量最近邻照样给你凑出 K 个来。这是 RAG 最危险的失败模式：**没有问题相关的材料，却硬答**。答案看起来专业、语气确定，还挂着引用角标，用户完全没有判断依据。

解法是在召回之后加一道**相似度阈值**：余弦相似度低于门槛的候选直接丢弃，全部丢完就返回"知识库中未检索到相关内容"，让模型走拒答分支，而不是硬编。

**阈值定多高是个取舍**：

- 定低了，噪声块进上下文，模型开始拿不相关的段落拼答案，产生"有依据的胡说"。
- 定高了，稍偏的表述（同义改写、口语提问）被误杀，用户反复换说法才问得出来，体感是"这东西不认我说的话"。

中文语料配 1024 维嵌入时，实践中常见的可用区间在 0.3 到 0.5。本项目的默认值是 0.35——一个偏保守但不太误杀的位置。关键是这个数**必须用评测集定，不能用别人的数**。做法：准备一批"库里确实有答案"和一批"库里没有答案"的问题，扫一遍阈值看两条曲线的交点，前者看命中率、后者看误答率。

**两个容易忽略的点**：

1. **阈值只能用在向量路上**。全文路的分数是相关度排名分，尺度完全不同，拿同一个阈值去卡它会把全文路结果全清空。
2. **拒答要真的拒**。如果提示词里同时给了模型"参考以下资料"和一串无关资料，模型倾向于强行综合出一段话。所以无命中时不该把资料段塞进提示词，并在系统提示里明确"没有材料就回答不知道"。

比阈值更彻底的方案是让模型自己判断材料是否切题（把"是否可回答"作为生成前置步骤），但那要多花一次调用，一般作为阈值之后的二期优化。
