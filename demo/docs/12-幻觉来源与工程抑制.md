# 幻觉从哪来，以及工程上能压住多少

幻觉（hallucination）指模型输出听起来合理但没有依据的内容。在 RAG 系统里它比裸聊天更隐蔽，因为答案往往还挂着引用角标，看起来完全可信。

**四类主要来源**：

1. **材料不足，模型补全**。检索没命中却仍然生成了完整回答——本质是阈值和拒答没做好。这类占比最高，也最容易治。
2. **材料冲突**。多份文档口径不一致（新旧版本同时入库是最常见成因），模型把两个数字混成第三句话。解法在数据侧：入库时管版本、同主题只留生效版本，而不是指望提示词里那句"以最新为准"。
3. **跨段拼接**。A 段说条件、B 段说结论，模型把不属于同一前提的东西缝在一起。材料之间的分隔结构越清晰、每段带自己的标题和出处，这类错误越少。
4. **参数知识与检索知识打架**。模型"记得"的东西和文档写的不同时，它可能偏向自己的记忆。要明确"以资料为准，即使与你所知不同"，并把资料放在靠近问题的位置。

**工程上真正有效的四个手段**：相似度阈值加拒答、稳定的材料分隔结构与出处标注、温度调低（事实问答场景常见 0 到 0.3）、生成后做引用一致性校验。其余如"让模型反思一遍"这类做法会额外增加一到两次调用，只在高风险场景值得。

**评测要单独看幻觉指标**。只看"答案准不准"会把"没答出来"和"编错了"混为一谈，前者是可挽回的、后者是致命信任事故。业界常用的是带忠实度维度的评测框架（如 RAGAS 的 faithfulness，或英伟达那套 0 到 4 分的答案准确性量表），关键是标注集里必须有一批"库里没有答案"的问题，专门量误答率。
