# 检索质量怎么量：召回率、MRR 与 nDCG

改一个参数之前要先能说清"怎么算变好了"。检索阶段的评测和最终答案的评测是两件事，必须分开量——很多团队只端到端看答案质量，结果永远不知道是检索没捞到还是模型没用好。

**四个基础指标**：

- **命中率 / 召回率@K（Recall@K）**：标注了"正确答案所在片段"的问题里，有多大比例在前 K 条结果中出现了它。这是最该先看的数，因为它直接决定后面所有环节的天花板——没召回，重排和生成都救不回来。
- **MRR（平均倒数排名）**：第一个正确结果排第几，取倒数再对全部问题求平均。它衡量"用户/模型要多远才能看到对的东西"，对首屏体验尤其敏感。
- **nDCG@K**：考虑多级相关性（完全相关、部分相关、无关）的排序质量指标。语料有"主次文档"之分时比前两个更合适，代价是要标注更细。
- **精确率@K**：前 K 条里有多少是相关的。K 取得大时它能反映"上下文被塞了多少噪声"，和召回率配套看。

**标注集怎么建**：从真实提问日志里抽样，覆盖三类——库里有答案、库里部分有、库里完全没有。第三类最关键也最容易被省略，它专门用来测误答率。规模上，几百条就足以看出参数趋势；上千条的收益主要在于分主题定位。

**必须固化的三件事**：问题集与标注锁定为版本化文件；每次跑只改一个变量；指标和查询日志一起留档。做到这三条，调参才从"玄学"变成"实验"。
