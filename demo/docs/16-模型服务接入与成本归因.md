# 模型服务接入：路由、降级与配额

企业 RAG 系统几乎不会只调一家模型服务。接入层的工程价值在四件事上：统一接口、按用途路由、失败可降级、花费可归因。

**统一接口**。不同厂商在流式格式、工具调用写法、鉴权头、错误码、超时行为上都有差异。做法是在应用层定义一个自己的窄接口（补全、流式补全、嵌入、重排四类），厂商差异在网关里适配，业务代码永远只见窄接口。否则每换一个模型就要改遍全链路。

**按用途路由**。嵌入、检索重排、生成、摘要这四类任务对模型的要求完全不同：嵌入模型一旦选定就要和索引绑死（换模型必须重建），生成模型可以按空间或按会话配置，摘要类任务用便宜的短上下文模型即可，因为它对质量的影响远小于对成本的敏感。把所有任务都路由到最贵的旗舰模型，是成本失控最常见的来源。

**失败与降级**。要区分三种情况：限流（可退避重试）、上游错误（可换备用模型）、参数非法（必须立即失败并暴露给用户）。把参数非法也吞进重试里，会得到"请求卡了半天最后报未知错误"的糟糕体验，还会白烧配额。重试要设上限并带抖动，避免同一时刻大量请求同步重试把上游彻底打死。

**配额与成本归因**。用量记录要落到"谁、在哪个空间、问的哪次"这个粒度，同时记录输入输出标记数。只有总数没有归因，成本失控时找不到责任人。配额耗尽的失败也要计入，不能只统计成功调用，否则你看不到真实需求。

**超时预算要在入口定死**。一次问答包含检索、可能的重排、可能的多轮工具调用，各阶段都得有独立超时，且总和小于前端等待上限。没有阶段预算的系统，一个慢的外部服务就能把整条链路拖死。
