# 嵌入模型与向量维度：选型要看四件事

嵌入（embedding）模型把一段文字映射成一个固定长度的浮点向量，语义相近的文字在向量空间里距离也近。RAG 的召回质量有一半由它决定。

选型时真正要看的是这四件事：

**一、语种匹配**。中文语料必须用对中文优化过的模型，否则"报销制度"和"差旅标准"这种近义在向量空间里根本不相邻。跨语种检索（中文问、英文料）要显式选支持多语的模型，不能指望翻译一层。

**二、维度与成本的权衡**。常见维度有 768、1024、1536、3072。维度越高表达力越强，但存储和计算线性上涨：一百万个块在 1024 维浮点下就是约 4GB 原始向量，还没算索引开销。很多团队在中文场景选 1024 维，是因为它在效果和成本之间是个可接受的折中，而不是因为它"最准"。

**三、距离度量要和归一化配套**。绝大多数模型输出的是单位向量，此时余弦距离和内积等价，用哪个都行；一旦模型不保证归一化，用内积就会被向量长度污染，出现"长段落总是更相似"的假象。选度量之前先看模型说明。

**四、最大输入长度**。嵌入模型都有截断上限（常见 512 或 8192 个标记）。超过部分被静默丢掉，块切得比上限还大就等于白切。这也是分块参数必须和嵌入模型一起定、不能分开调的原因。

**两个高频坑**：

- **换模型必须全量重建索引**。不同模型的向量空间完全不兼容，新旧混在一起检索出来的相似度毫无意义。所以向量表要带模型标识字段，切换时按模型分批重建，别指望兼容。
- **查询侧和文档侧用同一套预处理**。如果入库时做了清洗（去多余空白、去页眉），查询时不做，两者的向量分布就会错位，命中率莫名其妙下降。
