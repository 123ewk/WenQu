## 2. 档位判定与裁剪结论

按基准「开工前必问」判定:**精简档**(内部工具起步)但**保留空间级 RBAC 与数据隔离**(用户明确要多空间,项目约束优先于档位默认)。

**保留的基准条目**:

- 01:两条核心数据流形态、幂等清理、队列单一事实源、死信闭环、状态机常量、错误分级重试、fail-open 白名单、扩展点"新增 Provider ≤3 处"。
- 02:配置分层与三态开关、双错误码体系、日志脱敏、迁移纪律、VERSION 单一真源、非 root 镜像。
- 03:四层测试、快/专项/发布三层 CI 门禁、契约测试(先做 API 契约 + 错误码注册扫描)。
- 04:JWT+令牌表、空间 RBAC 数值阶梯、API Key 哈希+加密、AES-256-GCM 凭据加密、上传四层限制、解析服务 Token 强制、提示注入分层对策。
- 05:单库三合一、分块默认参数、RRF 融合、模型协议统一、compose profiles、备份恢复。
- 06:与多租户无关的全部 P0 项(14 项翻转、备份演练、冒烟、上线七步)。

**裁剪掉的基准条目**(完整登记见第 11 节):Redis 队列多池、Redis 事件日志后端、多检索引擎矩阵、K8s/helm、OIDC/SSO、Agent 代码沙箱、图数据库、网页抓取数据源。

## 3. 总体架构

### 3.1 服务拓扑(最小生产集:5 个容器)

```
                     ┌─────────────────────────────────────────────┐
   用户 ── HTTPS ───▶│  web(nginx:React SPA + 反代 /api、/docs 关闭)│
                     └───────────────┬─────────────────────────────┘
                                     │ 仅此端口对外
                     ┌───────────────▼──────────────┐    gRPC+Token   ┌────────────────┐
                     │  server(FastAPI 单体)        │◀══════════════▶│ parser(独立进程)│
                     │  · API handler 层            │                │ PDF/Word/Excel │
                     │  · pipeline worker(asyncio) │                │ /PPT/Markdown  │
                     │  · Agent 运行时(垂直包)      │                │ +表格抽取       │
                     └──────┬──────────────┬────────┘                └────────────────┘
                            │              │
                  ┌─────────▼─────┐   ┌────▼──────────┐
                  │ postgres      │   │ minio(S3 兼容)│
                  │ ·业务/元数据   │   │ ·原始文档      │
                  │ ·pgvector 向量│   │ ·解析产物      │
                  │ ·tsvector 全文│   └───────────────┘
                  │ ·tasks 任务表 │
                  └───────────────┘
```

### 3.2 核心数据流 1:文档入库流水线(异步,秒~分钟级)

```
上传(MinIO) → 建文档记录(pending) → 入 tasks 表
  → 解析任务:小文件本地快路径 / Office/PDF 走 gRPC 解析服务(慢路径,按格式路由)
  → 分块(画像器 → recursive/标题/表格感知 → validator 兜底)
  → 批量向量化(嵌入 API,带并发预算) → 写 chunks(向量+tsvector 同事务)
  → 异步后处理扇出(摘要/推荐问题 各一个任务)
```

三条硬规则(基准底线):

1. 处理函数先做**状态幂等检查**,重处理前先**清理旧分块/旧索引**再写新(先删后写)。
2. 队列拓扑单一事实源:`app/infrastructure/queue/topology.py` 集中定义全部任务类型、并发数、超时,同时驱动 worker 构建与运维观测接口。
3. 永久性错误(格式不支持、解析鉴权失败)打 `skip_retry` 标记直接进失败态,避免重试空转。

文档状态机(常量,禁止裸字符串):`pending → parsing → chunking → embedding → completed / failed`。

### 3.3 核心数据流 2:检索问答流水线(流式,亚秒级首 token)

编排为**洋葱式插件链**,阶段顺序由声明式编排表声明:

```
加载会话历史 → 查询理解(改写,M2 可只透传) → 并行检索(向量 ∥ 全文)
  → 加权 RRF 融合(k=60, w_v=0.7, w_k=0.3,按空间可配) → [可选 rerank] → topK 收敛
  → 组装上下文(分通道包裹+净化,见第 8 节) → LLM 流式生成 → 引用组装 → SSE 推送
```

MVP 允许硬编码直调这条链(基准偏离条款),但**必须按阶段边界拆函数并留编排注释**,M3 升级为插件链。

### 3.4 server 内模块划分(混合式:技术层主干 + 领域垂直包)

> **实现后修正**:本节原规划的 `api/handler/`、`infrastructure/`、`models/`、`agent/`、`common/`
> 五个目录在 V1 实现时**简化为下方形态**(精简档:避免为单一实现建立空壳分层)。
> 下方为 M2 交付后的**实际布局**,后续新增能力(如 M4 的 agent)按需补目录。
> 逐文件台账与职责见 `docs/V1交付台账.md` §2。

```
server/src/app/
├── main.py                  # 薄入口:建容器、装配、错误处理器、中间件
├── worker.py                # 后台 worker 入口(入库任务循环 + 陈旧 claim 回收 + 维护任务)
├── api/
│   ├── deps.py              # 依赖装配(仓储/服务/网关构造注入 + 认证守卫)
│   ├── denied_audit.py      # 被拒操作审计(独立会话,与请求事务解耦)
│   └── routes/              # HTTP 入口,按资源一文件(auth/users/spaces/knowledge/
│                            #   retrieval/conversations/chunking/models/health)
├── application/
│   ├── chunking.py          # 分块器(无外部依赖的纯函数,便于单测)
│   ├── service/             # 业务用例,按实体分文件
│   └── repository/          # 持久化,查询普遍携带 space_id 谓词
├── core/                    # 横切能力:config/db/security/errors/logging/
│                            #   storage(对象存储)/model_catalog/model_client/parser_client
└── domain/                  # 实体(ORM)、状态机/角色/动作常量、错误码、仓储与网关 Protocol
```

**依赖方向**:`routes → domain/interfaces(Protocol) → service → repository + core`。
服务层只依赖 Protocol(定义在 `domain/interfaces.py`),不依赖具体实现;
装配统一在 `api/deps.py` 用构造函数注入,不在 import 期产生副作用。
模型客户端与对象存储的接口与实现同处 `core/`(基准豁免,单一实现时不额外分层)。


### 3.5 扩展点纪律

每类外部能力(检索引擎、embedding、rerank、chat 模型、对象存储、解析引擎)一个接口 + 一个工厂。注册机制全项目**只用一种风格:工厂 switch + 常量表**。合格线:新增一个 Provider 改动 ≤3 处(新适配文件 + 工厂 case + 常量注册)。

## 4. 技术选型(ADR 摘要)

> 每项按基准要求写:理由 + 重新评估条件 + 退出成本。完整论证随代码进 `docs/adr/`。

### ADR-1 检索后端:Postgres 单库三合一(pgvector + 应用层中文全文)

- **选型**:PostgreSQL 16 + pgvector(向量)+ tsvector 全文(应用层 jieba 分词后写入 `tsvector`,查询侧同样分词)+ pg_trgm 兜底模糊。
- **候选对比**:ParadeDB pg_search(BM25 质量好但中文分词与镜像成熟度需验证,作为演进备选);zhparser 扩展(需编译安装,私有化镜像维护成本高);Elasticsearch/Milvus(组件数量+1,备份迁移成本翻倍,当前量级严重过配)。
- **重新评估条件**:向量数 >5×10⁷,或全文检索质量实测不达标,或并发 >50 QPS。
- **退出成本**:统一 Engine/Repository/Service 三层检索接口 + 注册表;切库=新增一个引擎 Provider,数据重嵌入/重建索引即可。
- **红利**:向量与业务数据同库同事务;备份简化为「pg_dump + MinIO」两方(基准要求的三方中向量库与关系库合一)。

### ADR-2 任务队列:Postgres DB 队列,不引入 Redis(偏离基准默认,已登记)

- **选型**:`tasks` 表 + `SELECT ... FOR UPDATE SKIP LOCKED` 认领 + 陈旧 claim 回收(超时未心跳的任务重新入队)+ 死信态 + 启动恢复。
- **理由**:基准明确「量小(<1000 任务/天)可只用 DB 队列一种」。本项目日任务量约几十~几百,远低于阈值;砍掉 Redis 少一个有状态服务 = 少一份口令管理、备份、监控与故障面。
- **tradeoff**:轮询间隔带来秒级调度延迟(入库本就是分钟级流水线,可接受);队列吞吐上限低(个位数十 OPS,当前量级足够)。
- **重新评估条件**:日任务 >1000,或解析积压常态化 >5 分钟,或需要秒级任务时效 → 引入 Redis 类队列,但 tasks 表兜底与死信语义保留不变。

### ADR-3 流式输出:SSE + append-only 事件日志(memory 后端)

- **选型**:模型层 `ChatStream()` → 进程内事件总线 → append-only 事件日志(ring buffer,per 会话)+ offset 增量拉取,前端 `fetch` 流式读取。**事件日志后端做成接口**(memory / Redis 两实现),当前用 memory。
- **理由**:单副本部署下 memory 后端满足断线续流;Agent 长任务(分钟级)必须有续流能力,不能直通 SSE。
- **重新评估条件**:扩多副本 → 事件日志切 Redis 后端(接口已就绪,这是多副本的硬前置条件,见第 9 节)。
- **⚠️ 实现状态(M2 交付后核实)**:本决策**尚未落地** —— 代码中无事件日志模块、无 offset/resume 路由;M2 的 SSE 是"模型流直通客户端"的简化形态。断线后客户端只能重新拉 `GET /conversations/{cid}/messages` 恢复(消息已落库,内容不丢,但**流式过程不可续**)。
  影响:第 9 节验收项「流式回答中途断网重连 → 续流不重复不丢失」当前**不满足**,须随 M4(Agent 长任务)补齐;在那之前**前端不得依赖续流**。
  为何未在 M2 补齐:交互式问答通常秒级完成,续流收益低;真实驱动是 Agent 长任务(分钟级)与多副本。

### ADR-4 模型接入:OpenAI 兼容协议 + 变换钩子;网关为可选 profile

- **选型**:统一 OpenAI 兼容客户端,厂商差异用请求变换钩子(ShapeRequest)吸收;内置模型清单走声明式 YAML(models.yaml / prompts.yaml);后台任务(向量化/摘要)按模型做**并发预算信号量**(供应商限速的 50% 起配),只限后台不限交互问答。
- LiteLLM 类自建网关作为 compose `profiles: [gateway]` 可选服务,默认不启用(当前只有 1-2 个上游,直连更简;上游 ≥3 家或需要统一计费/限流时启用)。
- 本地模型(Ollama)一等支持:同一 OpenAI 兼容协议,`不可用时仅告警不阻断` 可配。

### ADR-5 分块:默认参数 + 画像自适应 + validator(表格感知为一级需求)

- 基线:recursive 切分,chunk ≈512 token,overlap 15%(公开基准背书的单旋钮配置)。
- 画像器检测结构信号:标题层级 → 标题切分带面包屑上下文头;**Excel/CSV → 表格感知策略**(sheet 概述块 + 按行组分块,保留表头进每块)——用户场景表格占比高,这是本项目分块的重点投入。
- validator 兜底:输出异常(如 200 个单行 chunk)判坏自动落层重切。
- 父子分块(检索命子块、返回父块)放 **M3** 实现(精简档允许延后,登记);实时分块预览调试接口 M2 就做(调优刚需)。
- 已知取舍写进文档:切换分块策略不自动重建索引,需手动触发重解析。

### ADR-6 前端:Vue 3 + Vite + TS + Element Plus + Pinia(用户既定偏好)

- 选型理由:用户偏好 Vue;Element Plus 是 Vue 生态管理后台型 UI(上传、列表、配置、会话)成熟度最高的组件库;Pinia + Vue Router 为 Vue 官方推荐组合;`vue-tsc` 类型检查进 CI。
- 服务端状态用 TanStack Query for Vue(可选,M1 评估);SSE 用 fetch-stream 封装 composable。
- 契约优先:OpenAPI 由后端生成,前端类型从契约导出(`openapi-typescript`),避免手写接口类型漂移。

### ADR-7 解析服务:独立 Python 进程,gRPC 接入

- 理由:解析是 CPU 密集、易崩(脏文档),与 API 服务隔离;Python 解析库生态最全(PyMuPDF / python-docx / openpyxl / python-pptx / markdown-it)。
- proto 是跨进程契约,生成物入库 + 一键再生成脚本 + 契约测试钉住。
- 生产强制 Token 认证(常数时间比较),TLS 启用时缺配置 fail-fast 拒绝启动。

## 5. 数据模型概要(Postgres)

关键表(全部 Alembic 管理,up/down 成对):

| 表 | 要点 |
|----|------|
| `users` | bcrypt 密码哈希;is_superuser |
| `refresh_tokens` | **只存 SHA-256 哈希**(基准反模式禁令);user_id、过期、撤销位 |
| `spaces` | 多空间根实体 |
| `memberships` | (space_id, user_id, role);role 数值阶梯 Owner=40 > Admin=30 > Editor=20 > Viewer=10 |
| `knowledge_bases` | space_id;embedding_model、embedding_dim、RRF 参数(空间级可配覆盖) |
| `documents` | kb_id、space_id(冗余)、status 状态机、source 对象存储 key、error_code、file 类型 |
| `chunks` | document_id、**space_id(冗余,租户谓词直查)**、parent_id(父子分块,M3)、content、embedding `vector(1024)`(维度随 KB 配置)、tsv、metadata;KB 级记录 embedding 模型,换模型=KB 级重建索引任务 |
| `conversations` / `messages` | messages 存引用 JSONB(chunk_id + 原文摘录 + 分数),支撑引用溯源回链 |
| `tasks` | DB 队列:type、payload(jsonb,含 trace_id)、status(pending/running/succeeded/failed/dead)、max_retry、timeout_s、claimed_by、claimed_at、run_after、retry_count、last_error |
| `api_keys` | SHA-256 哈希列(查找用)+ AES-GCM 加密明文列;capabilities;KB 范围 |
| `audit_logs` | 动作类型分类、actor、space_id、detail、保留期自动清扫 |

## 6. 工程规范

### 6.1 仓库布局(monorepo,子产品独立工程文件)

```
my_rag/
├── VERSION                  # 版本单一真源
├── Makefile                 # 自文档化(help 目标)
├── docker-compose.yml       # 标准形态(生产模板,含 profiles)
├── docker-compose.dev.yml   # 开发形态:只起 postgres/minio,应用本机热重载
├── server/                  # 主 API 服务(pyproject.toml + uv.lock)
├── parser/                  # 解析服务(独立 pyproject + uv.lock,proto 同处)
├── web/                     # 前端 Vue3+Vite+TS(package.json + 独立 lockfile)
├── deploy/                  # .env.example(生产)、备份脚本、runbook
└── docs/                    # 本文档、adr/、runbook/、api 契约
```

依赖纪律:宽声明 + 锁安装(`uv sync --locked` / `npm ci`);lockfile 全部提交;CI 校验锁与清单一致。

### 6.2 配置管理

- 优先级:**环境变量 > YAML > 代码默认**(注释明文);`.env.example` 按主题分组(部署/存储/检索/模型/解析/认证/可观测),每变量带用途注释与启用状态标注。
- 启动 `ValidateConfig` 校验失败**拒绝启动**;布尔开关三态(`未配置 ≠ false`),关键安全开关(RBAC 强制、解析服务 Token)**未配置视为开启强制**(fail-closed)并打一次性启动告警。
- 分工:env 承担部署差异/密钥/开关;YAML 承担结构化业务配置(模型清单、prompt 模板、Agent 预设)。**密钥永不进 YAML**。
- compose `env_file` 只挂主服务,parser 显式写自己的 environment。

### 6.3 错误处理

- 双错误码:内部数值码分段(1000-1999 通用 / 2xxx 认证 / 3xxx 知识库与文档 / 4xxx 会话问答 / 5xxx Agent / 6xxx 模型调用);前端稳定字符串码(`AUTH_REQUIRED`、`KB_NOT_FOUND`…)做 i18n 映射,契约="加码不破坏、改码需协调前端"。
- 统一响应壳 `{success, error: {code, message, details}}`;非领域错误一律 500 兜底且不泄漏内部信息。
- 后台任务显式声明 MaxRetry 与 Timeout;失败闭环 = 死信落库 + 用户可见状态翻 failed。
- fail-closed 清单:配置校验、迁移失败、解析服务认证缺失——全部阻断;允许 fail-open 的场景逐一显式列出并注释(初期清单:限流器故障放行)。

### 6.4 日志与可观测

- 私有 logger 实例;`request_id` 经 context 注入全链路;开发文本格式,生产 JSON 格式选项。
- 脱敏三件套:字段正则清单(password/token/api_key/secret)、URL query parse-then-redact、用户可控字符串过滤控制字符。LLM 请求/响应调试日志独立开关、独立目录、7 天自动过期。
- `GET /health`(静态探活)、`GET /system/info`(版本/commit/迁移状态,排障第一入口)、`GET /metrics`(Prometheus:请求数/延迟、队列深度、死信数、模型调用失败率——生产硬要求)。
- 追踪 OTLP 协议,trace 从 HTTP 头 → 任务 payload → worker 同棵树;未启用时 nil-safe 零开销。默认关闭,上线前接入(P1)。

### 6.5 迁移与构建

- Alembic:版本化、up/down 成对、**破坏性变更的 down 必须 no-op 并注释**(前滚优先);迁移失败阻断启动;dirty 状态暴露到 /system/info,错误消息带完整人工修复指引;迁移命令永不打印数据库口令。
- 构建:多阶段 Docker 构建、最终层 slim、基础镜像 **digest 钉死**、全部容器非 root 运行(parser 与 server 统一,不混用);VERSION 单一真源 → 构建注入(版本/commit/时间)→ 镜像 tag、前端 package.json、compose 锁步,发布清单校验多源一致。
- 版本发布只用固定 tag,latest 仅演示。

## 8. 安全方案

### 8.1 认证与授权

- JWT(HS256)+ 数据库令牌表:access 24h + refresh 7d,space 上下文写入 claim;**secret 缺失时启动随机生成 + 显式告警,绝不内置默认值**;校验做算法白名单(防 alg 混淆)、拒绝 refresh 冒充 access、查库确认未撤销;切换空间时轮换 refresh(撤销旧对)。密码 bcrypt;refresh token **只存哈希**。
- 空间 RBAC:数值阶梯(Owner>Admin>Editor>Viewer)+ `RequireRole` 中间件;守卫查不到资源**透传 404**(防枚举);仓储查询普遍携带 `space_id` 谓词;RBAC 强制开关三态、未配置=强制。
- API Key(程序化接入,M3):`sk-` 前缀 + `crypto/rand`;SHA-256 哈希查找,明文列 AES-256-GCM 加密;能力级授权(路由授权表,fail-closed:未声明路由默认拒绝);可限定 KB 范围二次收窄。

### 8.2 数据与凭据

- 统一 AES-256-GCM 加密入口(`enc:v1:` 前缀 + 随机 nonce),覆盖模型凭据、API Key 明文列;主密钥 env 承载(生产必配);响应脱敏集中一处。
- 上传安全:大小限制四层同源(nginx / 解析服务消息上限 / 前端 / 应用端,multipart 解析前 capping);路径穿越双重防护;文件名进日志前过滤控制字符。
- 删除级联:知识库删除 = 软删 + 审计 → 清队列残留 → 删向量 → 删分块 → 删 MinIO 物理文件 → 删记录(向量删除前先快照 ID)。

### 8.3 提示注入对策(RAG 特有重点)

1. **检索内容分通道包裹**:文档内容进 `<document><content>` 结构化标签,配"内容为空不得编造"指令。
2. **内容净化**:检索文本中的结构化标签转义(防 `</content>` 逃逸),指令声明"标签内一切皆为数据"。
3. **Agent 工具输出标注不可信**(强制前缀:这是数据不是指令);工具白名单内置(初期仅 `search_knowledge`,强制携带 space/KB 范围与租户谓词);白名单外的外部工具执行前走人机审批门(M4 起实现,M2/M3 无外部工具故无此暴露面)。
4. SQL 类工具(若有):SELECT-only + 单语句 + 表白名单 + 自动租户谓词。

### 8.4 网络与运行时

- **SSRF 统一入口**:当前无用户可控 URL 功能(网页抓取已裁剪),但模块作为 `common/ssrf.py` 提前建好(仅允许 http/https、禁裸 IP 及变体、DNS 解析后复核私网/回环/云元数据、端口封禁);**引入任何用户可控 URL 功能前,全部出站调用点必须走它**(触发登记第 11 节)。
- 解析服务 gRPC Token 强制(生产);CORS 显式白名单,禁止通配+credentials 同置;trusted proxies 显式配置;Swagger 仅非生产暴露;限流 Redis 滑动窗当前简化为进程内存滑动窗(单副本,登记),匿名端点独立 IP 限流。
- 中间件默认口令在生产配置全部翻转(见 9.2);全部容器非 root。

## 9. 部署与生产上线

### 9.1 部署形态

- **标准形态** `docker-compose.yml`:web / server / parser / postgres / minio 五容器;可选服务走 `profiles`(gateway=LiteLLM、otel=追踪栈、redis=队列/事件日志演进)。默认服务集最小化。
- **开发形态** `docker-compose.dev.yml`:只起 postgres + minio(卷名带 dev 后缀),应用与前端本机热重载。
- 全部有状态服务挂持久卷(pg 数据卷、minio 数据卷);编排文件检查进发布清单。
- 多副本前置条件(当前单副本,记录备用):事件日志切 Redis、锁与限流走共享存储、队列 claim 已是 SKIP LOCKED(天然满足)、worker 并发按实例数重算。

### 9.2 上线门禁(Go-Live Gate)

**P0 硬门禁**——14 项"开发默认→生产默认"翻转全部完成并双人复核:

| # | 翻转项 | 生产要求 |
|---|--------|---------|
| 1 | 镜像版本 | 固定 tag;基础镜像 digest 钉死 |
| 2 | 中间件口令 | postgres/minio 全部强口令显式注入 |
| 3 | 密钥 | JWT secret 与 AES 主密钥显式配置;随机兜底视为未配置 |
| 4 | RBAC | 显式开启强制(fail-closed),无 membership 不提权 |
| 5 | CORS | 显式白名单 |
| 6 | 解析服务认证 | gRPC Token 强制配置 |
| 7 | API 文档 | Swagger 非生产模式才暴露 |
| 8 | 反代信任 | trusted proxies 显式网段 |
| 9 | 端口暴露面 | 仅 web 入口对外;pg/minio/parser 绑内网 |
| 10 | 沙箱 | 不启用(本项目无代码执行) |
| 11 | 有状态卷 | 全部持久卷 |
| 12 | 迁移 | 失败阻断启动;升级前自动备份 |
| 13 | 日志 | 落盘+轮转+脱敏;LLM 调试日志默认关 |
| 14 | 依赖 | 漏洞审计进 CI;security-only 更新策略 |

**备份恢复**:runbook 覆盖 pg_dump(含向量与全文索引)+ MinIO 数据两方(单库三合一红利);**上线前完成一次"全量备份 → 清空 → 恢复 → 冒烟"演练**,总耗时记入 runbook 对照 RTO(4h)。

**上线七步**:预检(P0 全绿)→ 翻转(双人复核)→ 迁移(自动备份→迁移→/system/info 确认非 dirty)→ 冒烟(下方清单)→ 观测(人为制造一次死信验证告警链路)→ 交付(runbook+回滚预案)→ 48h 复盘。

**冒烟清单七条**:

- [ ] PDF/Office/Markdown/表格 四类文档各传一篇,全部走到"已完成"
- [ ] 故意上传坏文件 → 状态变"失败"且死信可见、可重试
- [ ] 检索问答答案带正确引用;关掉知识库再问 → 兜底回复而非报错
- [ ] 流式回答中途断网重连 → 续流不重复不丢失
- [ ] 建 API Key → KB 范围限定生效 → 范围外被拒 → 审计有记录
- [ ] 非管理员访问管理接口 → 404 且审计有拒绝事件
- [ ] 重启 server 容器 → 任务自动恢复、无任务卡 processing、无配置告警

**SLO 初值**(P1,可带病上线须登记):问答端到端成功率 ≥95%;入库 24h 完成率 ≥99%;检索 P95 ≤1.5s(不含生成)。

## 11. 基准偏离与不适用项登记表

> 基准规则:裁剪不是免检,每项登记触发补齐的规模阈值。

| # | 基准默认 | 本项目决策 | 理由 | 触发补齐条件 |
|---|---------|-----------|------|-------------|
| 1 | Redis 类队列 + DB 兜底 | 仅 Postgres DB 队列(ADR-2) | 日任务 <1000,砍组件 | 日任务>1000 或解析积压>5min |
| 2 | 事件日志(SSE 续流) | **M2 未实现**(无模块/无 resume 路由,见 ADR-3 实现状态);M4 随 Agent 长任务补齐 | 交互式问答秒级完成,续流收益低;真实驱动是 Agent 长任务与多副本 | M4 必达;在此之前前端不得依赖续流 |
| 3 | 限流用 Redis 滑动窗 | 进程内存滑动窗 | 单副本 | 多副本或限流需跨实例一致 |
| 4 | 集成测试用 SQLite 内存库 | testcontainers 真 Postgres | pgvector/tsvector/SKIP LOCKED 方言 SQLite 无法代表;真服务替身高保真 | 无(长期) |
| 5 | 父子分块默认开 | M3 实现,M2 关 | MVP 提速;精简档允许 | M3 必达 |
| 6 | rerank/查询改写 | 默认关,显式选配 | 基准即如此,费用与延迟诚实化 | 有标注评测集后评估 |
| 7 | 沙箱/代码执行 | 不实现 | 无需求;Agent 仅内置只读工具 | 需要代码执行时,只允许容器后端且 opt-in |
| 8 | 网页抓取数据源 | 不实现 | 用户明确暂不需要 | 引入时:SSRF 统一入口必须先行 |
| 9 | K8s/helm、OIDC、图数据库、多引擎矩阵 | 不适用 | 规模远未到 | 各自触发阈值见 ADR-1 与基准 05 |
| 10 | LiteLLM 网关一等公民 | compose profile 可选,默认直连 | 当前 1-2 个上游 | 上游 ≥3 家或需统一计费限流 |
| 11 | 问答流水线插件链 | M2 硬编码直调(留阶段边界),M3 插件化 | MVP 提速,基准偏离条款允许 | M3 必达 |
| 12 | 检索阈值 | 向量路最小余弦相似度 0.3(`APP_RETRIEVAL_MIN_SCORE` 可调) | 无阈值时任何问题都拿 top-K 噪声块,"知识库无相关内容"分支永不触发,诱发无依据作答 | 有标注评测集后按实测调整(非补齐项) |
| 13 | 检索融合算法 | RRF 排名融合(k=60,权重 0.7/0.3) | 免疫 pgvector 余弦与 ts_rank 的量纲差异,无需分数归一化 | 引入 rerank 后按其分数重排 |
| 14 | API Key 表含 AES-GCM 加密明文列 | **不存明文**,只存 SHA-256 哈希 + 截断 hint(M3 实测决策) | 原型页 07 明确"完整 Key 仅创建时展示一次",系统无任何读回明文的场景;存了即成为无人读取的长期泄露面。加密能力本身已就绪(`core/crypto.py`,OPT-7) | 出现"再次查看完整 Key"类需求时,加加密明文列并回填(只对新签发的 Key 可能) |
