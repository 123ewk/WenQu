# 前端实现提示词（原型复刻 + 接口对接阶段）

> 使用方式：把本文档整体交给负责前端实现的 AI。它取代上一阶段"只出设计稿"的任务，进入真实编码阶段。

---

## 一、你的角色与任务

你是 WenQu（文档知识库 RAG 平台）项目的前端工程师。上一阶段已产出 9 张静态 HTML 原型页（位于 `docs/design/`），本阶段你的任务是：

1. 用 **Vue 3 + TypeScript + Element Plus** 把原型复刻为可运行的单页应用；
2. 对接后端已上线的真实接口（M1：账号体系 + 多空间管理），**清除所有静态假数据**；
3. 后端尚未上线的功能页做成占位页，**禁止渲染假数据冒充真实功能**。

## 二、硬性边界（必须遵守）

- **只允许改动 `web/` 目录**。`server/`、`parser/`、`deploy/` 一律只读。
- `docs/api/openapi.json` 是接口契约的唯一事实来源。**发现接口缺口时，不得自行编造端点或修改契约**，记录到 `web/对接缺口清单.md`。
- 不引入 Element Plus 之外的重型依赖（状态管理用 Pinia、路由用 Vue Router、HTTP 用 Axios，这些是约定的，其余图表/富文本等库一律不装）。
- 后端**没有配置 CORS**，开发环境必须通过 Vite proxy 转发 `/api`，禁止直连跨域。

## 五、原型复刻规则

- 布局、间距、层级、文案**以原型 HTML 为准**，用 Element Plus 组件实现（ElButton/ElTable/ElDialog/ElDrawer/ElForm 等），不要手写一堆自定义组件重复造轮子。
- 原型里的静态假数据（文档列表、对话记录、成员名等）分两类处理：
  - **本阶段已对接的页面**：全部删除，数据一律来自 API；
  - **接口未上线的页面**：保留页面框架与导航入口，主内容区用空态（如 ElEmpty）显示"该功能接口将于后续版本上线"，**不得渲染假列表/假对话**。
- 交互细节按 `docs/前端设计提示词.md` 的既有决策执行：引用角标 → 抽屉查看、检索测试是知识库详情的 Tab、权限决定按钮可见性。

## 六、M1 已上线接口清单（全部可对接）

前缀 `/api/v1`。成功响应**直接返回数据本体**（没有 `{success:true}` 包装）；失败响应统一为壳：

```json
{ "success": false, "error": { "code": "SPACE_NOT_FOUND", "message": "空间不存在或无权访问", "details": {} } }
```

前端用 `error.code`（稳定字符串）做分支与文案映射，`message` 可直接展示。

### 认证（全部返回 AuthResponse）

| 端点 | 说明 |
|---|---|
| POST `/auth/register` | 注册，201，body 见 openapi（username 规则 `^[a-zA-Z0-9_-]{3,32}$`，密码 ≥8 位） |
| POST `/auth/login` | 登录 |
| POST `/auth/refresh` | 用 refresh_token 换新令牌对 |
| POST `/auth/logout` | 登出（Bearer），204 |
| POST `/auth/switch-space` | 切换当前空间（Bearer），返回**全新**令牌对 |

`AuthResponse = { user, spaces[], access_token, refresh_token, token_type: "bearer", expires_in }`，其中 `spaces[]` 每项含当前用户在该空间的 `role`。

### 用户

| 端点 | 说明 |
|---|---|
| GET `/users/me` | 当前用户信息 |
| PATCH `/users/me` | 改昵称等资料 |
| POST `/users/me/password` | 改密码，204；**后端会吊销该用户全部会话** |

### 空间与成员

| 端点 | 最低角色 |
|---|---|
| GET `/spaces` | 成员（返回 SpaceOut[]，每项含 `role` = 我在该空间的角色） |
| POST `/spaces` | 任意登录用户（创建者自动成为 Owner） |
| GET `/spaces/{id}` | 成员；非成员收到 **404** |
| PATCH `/spaces/{id}` | Admin(30)+ |
| DELETE `/spaces/{id}` | Owner(40) |
| GET `/spaces/{id}/members` | 成员 |
| POST `/spaces/{id}/members` `{username, role}` | Admin+（role 只能 10/20，不能授 Admin） |
| PATCH `/spaces/{id}/members/{user_id}` `{role}` | Admin+（只能授予严格低于自己的角色；role=40 表示**转让所有权**，转让后自己降为 Admin） |
| DELETE `/spaces/{id}/members/{user_id}` | Admin+（只能移除低于自己的成员） |
| POST `/spaces/{id}/leave` | 成员（Owner 不能退出，会收到 403，需先转让或删除空间） |
| GET `/spaces/{id}/audit-logs?limit&offset` | Admin+，返回 `{items[], total}` |

角色数值：Viewer=10、Editor=20、Admin=30、Owner=40。

## 七、认证对接细则（本阶段最容易出错的部分，逐条执行）

1. **refresh_token 是一次性的**。每次调用 `/auth/refresh` 或 `/auth/switch-space` 成功后，必须用响应中的**新 refresh_token 覆盖本地存储的旧值**；旧值立即作废，继续用旧值刷新会得到 401，造成登出死循环。
2. **401 处理链**：请求拦截器附带 `Authorization: Bearer <access_token>` → 响应 401 时，用 refresh_token 调 `/auth/refresh` → 成功则**重放原请求（最多重试一次）** → 失败则清空凭据、跳转登录页。
3. **并发 401 防抖**：页面加载常并发多个请求，同时 401 时**只允许发起一次 refresh**，其余请求挂起等待新令牌后重放（用共享的 refreshing Promise 实现）。
4. **切换空间**不能只改本地的当前空间 ID：调用 `/auth/switch-space` 后，响应是完整的 AuthResponse，必须**整体替换** user、spaces、access_token、refresh_token。
5. **改密后强制登出**：`POST /users/me/password` 成功（204）后，该用户所有会话已被后端吊销，前端必须清空凭据并跳转登录页。
6. **登录态持久化**：token 存 localStorage（键名自定义），F5 刷新后恢复登录态；路由守卫检查 access_token，无则重定向 `/login`。
7. `expires_in` 是秒数（当前 access 24h、refresh 7d）。可选优化：按它提前 5 分钟主动续期；不做也可，401 链路必须通。
8. 401 仅在 `error.code` 为 `AUTH_REQUIRED` / `TOKEN_EXPIRED`（或 HTTP 401）时走刷新流程，其它错误不触发。

## 十、工程与验收标准

1. **TS 类型**：用 openapi-typescript 从契约生成（`npm i -D openapi-typescript`，`npx openapi-typescript ../docs/api/openapi.json -o src/api/schema.d.ts`），或手写 interface 但字段必须与 openapi.json 一致。
2. **API 分层**：只有 `src/api/` 允许 import axios；组件和 Store 只调 api 函数。
3. **环境变量**：`.env.development` 设 `VITE_API_BASE_URL=/api/v1`；`vite.config.ts` 配 proxy：`/api` → `http://localhost:8000`。
4. `npm run build`（含 vue-tsc 类型检查）必须零错误。
5. **静态数据自查**：完成后全局搜索 mock / fake / dummy / 硬编码数组，已对接页面不允许存在。
6. 错误提示：统一按错误壳渲染 ElMessage；表单校验错误（422）展示字段级提示。
7. 加载态：列表类页面有 loading，接口失败有空态/错误态，不允许白屏。

### 验收冒烟路径（逐条手动走通）

1. 注册新账号 → 自动登录进入工作台；
2. 创建空间 → 出现在侧栏，自己角色为 Owner；
3. 用第二个账号注册并登录 → 加入空间 → 成员列表可见；
4. Viewer 账号登录 → 管理类按钮不可见，直接调接口验证 403；
5. 非成员直接访问空间路由 → 收到 404 语义提示并引导回列表；
6. 切换空间 → 全局状态与侧栏高亮更新；
7. 修改密码 → 被踢到登录页，旧会话全部失效；
8. 把后端 `APP_ACCESS_TOKEN_MINUTES` 临时调成 1 重启，登录后等 token 过期 → 下一次请求自动续期成功（验证第 401 链与一次性 refresh 覆盖），验完调回；
9. F5 刷新页面 → 登录态保持；
10. `npm run build` 通过。
