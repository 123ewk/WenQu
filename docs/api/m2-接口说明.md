# M2 接口说明(知识库 / 入库 / 检索 / 问答)

面向前端对接。字段以 `docs/api/openapi.json` 为准;本文说明**流程与顺序约束**,以及
M2 新增能力的前端行为约定。

新增接口前缀统一 `/api/v1`,响应成功直接是数据本体,失败仍是统一错误壳
(`{"success": false, "error": {"code": "...", "message": "...", "details": ...}}`)。

## 一、M2 新增端点总览

| 端点 | 说明 |
|---|---|
| `GET/POST /spaces/{sid}/knowledge-bases` | 知识库列表 / 创建(创建=Editor+) |
| `GET/PATCH/DELETE /spaces/{sid}/knowledge-bases/{kb_id}` | 详情 / 改名(Editor+) / 删除(Admin+) |
| `GET/POST /spaces/{sid}/knowledge-bases/{kb_id}/documents` | 文档列表(分页)/ 上传 multipart(Editor+) |
| `GET/DELETE /spaces/{sid}/knowledge-bases/{kb_id}/documents/{doc_id}` | 文档详情 / 删除(Editor+) |
| `POST /chunks/preview` | 分块预览(粘贴文本即时看分块,调参用) |
| `GET .../{kb_id}/documents/{doc_id}/chunks` | 文档分块列表(分块查看页,分页) |
| `POST /spaces/{sid}/retrieval/search` | 混合检索测试(知识库详情页"检索测试"Tab) |
| `GET/POST /spaces/{sid}/conversations` | 会话列表 / 新建 |
| `GET /spaces/{sid}/conversations/{cid}/messages` | 会话消息(含引用) |
| `DELETE /spaces/{sid}/conversations/{cid}` | 删除会话 |
| `POST /spaces/{sid}/ask` | **SSE 流式问答**(核心) |

统一错误码新增:`KB_NOT_FOUND` / `KB_NAME_TAKEN` / `DOCUMENT_NOT_FOUND` /
`UNSUPPORTED_FORMAT` / `FILE_TOO_LARGE` / `CONVERSATION_NOT_FOUND` /
`MODEL_CALL_FAILED`(502 上游失败,可重试)/ `MODEL_NOT_CONFIGURED`(503 服务端缺 Key,
重试无用,提示联系管理员)。角色门槛见 m1-接口说明的角色矩阵:
知识库与文档**增改 = Editor(20)+,删知识库 = Admin(30)+**,查看 = 任意成员。

## 二、上传文档:这是异步流程

上传接口**只负责存文件与入队**,返回的 `status` 是 `pending`;随后由后台 worker
按状态机推进:`pending → parsing → chunking → embedding → completed / failed`。

- 前端在文档列表轮询 `GET .../documents` 刷新状态即可(建议 2s 间隔、页面不可见时暂停);
- `failed` 时 `error_code` 为 `INGEST_FAILED`,提示用户"解析失败,请检查文件或重新上传";
- 上传成功即用,不需要等 completed 才能继续传下一个。

上传约束(`APP_UPLOAD_MAX_MB`,默认 50MB):支持 `pdf/docx/xlsx/pptx/md/txt`。
**旧版 `.doc/.xls/.ppt` 不支持**,返回 `UNSUPPORTED_FORMAT`,提示用户另存为新格式。
文件名字段是 multipart 的 `file`。

```bash
curl -X POST ".../spaces/$SID/knowledge-bases/$KB/documents" \
  -H "Authorization: Bearer $TOKEN" -F "file=@手册.pdf"
```

## 三、SSE 流式问答(`POST /spaces/{sid}/ask`)

请求体:`{question, conversation_id?, kb_ids?, top_k?, model_id?}`。
- 首次提问**不传** `conversation_id`,后端新建会话;`conversation_id` 从首个事件的
  `meta` 帧里拿,前端应立刻把它记下来(后续轮次与"会话历史"都用它);
- `kb_ids` 限定检索范围(不传=全空间);`top_k` 默认 6。

响应是 `text/event-stream`,每帧 `data: {json}\n\n`。**五种事件按 type 分派**:

| type | 载荷 | 前端动作 |
|---|---|---|
| `meta` | `{conversation_id}` | 记录会话 id(新会话时同步路由/侧栏) |
| `citations` | `{citations: [{index, chunk_id, document_id, kb_id, filename, excerpt, score, breadcrumb, page}]}` | 存起来备用;可先渲染为"参考资料"列表 |
| `delta` | `{text}` | **累加**到答案区(这是唯一正文来源) |
| `done` | `{message_id, cited_indexes}` | 收尾;`cited_indexes` 是被答案真正引用的编号 |
| `error` | `{message}` | 展示错误,停止 loading;**HTTP 仍是 200**(流已开始) |

另有**心跳注释帧** `: ping`(M3 起):生成等待期每隔约 15 秒一条,`data: ` 开头
的才是事件,解析时跳过其它行即可(标准 SSE 注释)。

关键点:

1. **校验失败发生在流开始前**,所以未登录 401、非成员 404、提问为空 422 都能正常拿到
   状态码,不会出现"200 里藏错误"。但模型调用失败发生在流中,只能靠 `error` 事件。
2. **引用角标**:答案里的 `[n]` 对应 `citations[n-1]`。前端把 `[n]` 渲染为可点击角标,
   点击用该条目的 `chunk_id` 打开抽屉展示 `excerpt`(M2 提供的摘录)与
   `filename/breadcrumb/page`(溯源信息)。M2 不提供"查看完整原文块"接口,
   抽屉内容就用 `excerpt`。
3. **历史消息**(刷新页面后):`GET /conversations/{cid}/messages` 返回的消息里,
   assistant 消息自带 `citations` 数组,结构同上,可直接复现角标与抽屉。
4. SSE 用 `fetch` + `ReadableStream` 读取(不能用 EventSource:它发不了
   POST 请求体和 Authorization 头);需要自定义头就必须走 fetch 流。
5. 断线:**没有续流,事件日志接口也未实现**(ADR-3 的设计尚未落地,详见架构设计 ADR-3 的"实现状态")。
   断线或刷新后,一律按第 3 点重新拉 `GET /conversations/{cid}/messages` 恢复完整消息。
   前端不得依赖 offset/resume 类能力。
   另注:流内失败(如模型未配置)会发 `error` 事件并**不再发 `done`**,前端据此停止 loading。
6. **断线时的部分答案(M3 起)**:生成中途断开,后端会把已生成的部分答案连同引用
   存为一条 assistant 消息 —— 重新拉历史能看到"答了一半"的内容,不再只剩提问。
   该条消息没有 `done` 事件对应的 `message_id` 告知前端,靠重新拉历史发现;
   部分答案可能不完整,前端可原样展示(它是真实生成内容)。

## 四、检索测试与分块预览(调优用)

- `POST /spaces/{sid}/retrieval/search`:`{query, top_k, kb_ids?, model_id?}` → 命中数组。
  每条带 `vector_rank` / `fulltext_rank`(来自哪一路、排名第几)与 `score`(RRF 融合分),
  前端可显示"双路命中"标记帮助判断检索质量。
- `POST /chunks/preview`:`{text, format}` → 分块数组(含 `tokens`/`breadcrumb`/`kind`)。
  纯调参工具,不落库;`format` 只支持 `md`/`txt`(正式入库走完整解析服务)。

## 六、本地联调提示

- 起依赖:`make compose-dev-up`(postgres + minio)
- 起解析服务:`make parser-run`(worker 依赖它,不跑则任务会重试至死信)。
  Windows 上若 50051 落在系统保留段(`netsh interface ipv4 show excludedportrange
  protocol=tcp` 可查),需换端口:`cd parser && uv run python -m parser_service.server
  --addr 127.0.0.1:50071`,并同步改 `server/.env` 的 `PARSER_GRPC_ADDR`。
- 起后台 worker:`make worker-run`(上传后不进这条,文档会一直停在 pending)
- 起主服务:`make server-run`(`:8000`)
- 向量化/问答需要真实 Key:`server/.env` 里填 `DASHSCOPE_API_KEY`(向量化)与
  `DEEPSEEK_API_KEY`(问答),未配置时上传会进死信、问答流会回 `error` 事件。
- 端到端自检:`cd server && uv run python scripts/e2e_smoke.py` —— 真 PG + 真 MinIO +
  真 gRPC parser 全链路 21 项检查(仅模型 API 打桩,故无需 Key 即可跑)。
