## 二、OPT-3 断线续流已交付(可选增强,不接不影响现有功能)

提交 `c7be07b` / `09cd50a` / `b82f793` / `3d803a0`:

1. **生成与响应解耦**:断开连接**不再终止**后端生成 —— 宽限 **5 秒**
   (`APP_STREAM_GRACE_SECONDS` 可配);期间重连取消宽限,继续生成到完整落库;
   耗尽无人回来才中止:close 上游连接 + 部分答案落库 + 流内 `done(partial=true)` 收尾。
2. **SSE 所有事件载荷带单调 `seq`**(从 1 起,按生成流独立计数;向后兼容,现有解析无需改动)。
3. **新路由** `GET /spaces/{sid}/conversations/{cid}/stream?after=<最后收到的 seq>`(SSE,
   鉴权同 messages;API Key 挂 `chat` 能力):
   - 补播 `after` 之后的缺失事件,生成仍在进行则接着实时推;已结束则纯回放(含 done);
   - **不可续**(进程重启/事件淘汰/该会话从未生成过)→ `404 STREAM_NOT_RESUMABLE`
     → 回退 `GET .../messages`(部分答案已在其中)。
4. 资源治理:已完成流 TTL 1 小时回收(`APP_STREAM_LOG_TTL`);服务关停时未完成生成落库部分答案。

### 前端可选接入的最小方案(02 页)

- **不接**:现状逻辑照旧(断线回退拉 messages);`done` 多出的 `partial` 字段可忽略;
- **接(推荐)**:SSE 断开时记下最后收到的 `seq` → 调续流路由 → 404 则回退 messages;
  补播事件按现有解析继续累加即可,**无需任何去重逻辑**(服务端按 seq 精确续)。
