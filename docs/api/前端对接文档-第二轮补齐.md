| 方法 | 路径 | 权限 | 用途 |
|---|---|---|---|
| GET | `/api/v1/models` | 登录 | 模型选择器数据源(对话选模型 / 换嵌入模型) |

### 1.3 契约缺陷修复(前端 §4 提出,均已修)

| # | 问题 | 修复后 |
|---|---|---|

| 3 | `AuditLogOut.result` 只有 `type: string` | 已改为枚举 `"success" \| "denied"`,可生成联合类型 |

> 头部有 3 条不受影响:上限值、跨字段约束、编号对照(见 §6)。

```json
  ],
  "embedding": [
    {

      "provider_key": "dashscope",
      "model": "gte-rerank-v2",

    }

  "defaults": {
    "chat": "deepseek/deepseek-chat",
    "embedding": "dashscope/text-embedding-v3",
    "rerank": "dashscope/gte-rerank-v2"
  }

```

### 前端要点

1. **`id` 是提交值**:对话传 `model_id`、知识库换模型都填 `id` 这个字符串,不要填 `model`;
2. **`provider` 是显示名**(可做下拉分组标题),`provider_key` 是内部键;
3. 只返回**已启用**的模型(`models.yaml` 里 `enabled: false` 的、如 ollama/本地推理,不会出现)—— 所以下拉里不会有"选了不能用"的项;
4. `dims` 只在 embedding、`context_tokens` 只在 chat 有意义,另一侧为 `null`,前端不必展示;
5. ⚠️ **不返回密钥,也不返回"密钥是否已配置"**。能否真正调用取决于服务端环境变量,所以选中后仍可能在调用时拿到 `MODEL_NOT_CONFIGURED`(**503**),前端需能展示该错误;
6. 换 `embedding` 模型会改变向量维度,属"需重建索引"操作 —— 建议二次确认,并提示可用 §3 的 `reparse` 重建。

## 3. 重新解析 / 重建索引(新增)

```
POST /api/v1/spaces/{sid}/knowledge-bases/{kb_id}/documents/{doc_id}/reparse
```

Editor+ 可调用。把文档重置为 `pending` 并**重新入队**(对象存储里的原文件不变)。真实响应:

```json
{
  "id": "018448b6-e69d-4c82-90bd-169600a99ec2",
  "kb_id": "d20e0b72-e6ab-45b3-b6e8-382fb54b7bda",
  "filename": "旧版.doc",
  "format": "docx",
  "size_bytes": 10240,
  "status": "pending",
  "error_code": null,
  "error_message": null,
  "created_at": "2026-09-16T15:12:33.570642Z"
}
```

### 适用场景

- **失败后重试**:`status=failed` 的文档,修好原因(如补上模型 Key)后直接重试,**不需要重新上传**;
- **重建索引**:改了分块参数或换了 embedding 模型后,对已完成的文档重建向量。

### 前端要点

1. 只能在**终结态**(`completed` / `failed`)调用;文档处于 `pending/parsing/chunking/embedding` 时返回 **409 `DOCUMENT_BUSY`**:

```json
{
  "success": false,
  "error": {
    "code": "DOCUMENT_BUSY",
    "message": "文档正在处理中,请等待完成后再重试",
    "details": null
  }
}
```

2. 成功后文档回到 `pending`,需**恢复该行的状态轮询**(与上传后的轮询同一套);
3. 与"删除后重传"的区别:不需要用户再选一次文件。

## 4. 单块全文(新增,引用抽屉用)

```
GET /api/v1/spaces/{sid}/knowledge-bases/{kb_id}/documents/{doc_id}/chunks/{chunk_id}
```

任意成员可读。真实响应:

```json
{
  "id": "d657ddab-60e0-4cd6-a7da-af990265cf8b",
  "seq": 0,
  "content": "混合检索使用 RRF 融合向量与全文两路排名。混合检索使用 RRF 融合向量与全文两路排名。混合检索使用 RRF 融合向量与全文两路排名。",
  "tokens": 137,
  "meta": {
    "kind": "table",
    "page": 3,
    "tokens": 137,
    "breadcrumb": ["产品手册库", "检索设计"]
  }
}
```

### 前端要点

1. **这是"查看完整原文块"的数据源**:SSE 的 `citations[].excerpt` 只截前 300 字,点击引用抽屉里的"查看完整原文"时用 `citations[].chunk_id` 调本接口取全文;
2. 前提是该分块所属**文档仍可见**:文档被删除后本接口返回 404(属预期,不是 bug);
3. `content` 不截断,长块直接给全量 —— 抽屉内建议限高滚动;
4. `meta.breadcrumb` 可做定位提示(如"产品手册库 › 检索设计"),`meta.page` 是来源页码(无页码概念时为 `null`)。

## 5. 空间级入库进度(新增,真闭合缺口 #8)

```
GET /api/v1/spaces/{sid}/ingestion-progress?limit=50
```

任意成员可读。真实响应:

```json
{
  "active": [
    {
      "document_id": "34b3b4b0-4f81-4164-871e-aa72b29aacad",
      "kb_id": "e9226546-2548-40d2-bcd0-6e46c90694be",
      "filename": "价格表.xlsx",
      "status": "embedding",
      "error_code": null,
      "error_message": null,
      "updated_at": "2026-09-16T15:12:23.387214Z"
    },
    {
      "document_id": "be6197b3-6ecf-4e5d-a766-1afb5d3cd3d5",
      "kb_id": "e9226546-2548-40d2-bcd0-6e46c90694be",
      "filename": "旧版.doc",
      "status": "failed",
      "error_code": "INGEST_FAILED",
      "error_message": "仅支持 pdf/docx/xlsx/pptx/md/txt(旧版 office 格式请另存为新格式)",
      "updated_at": "2026-09-16T15:12:23.387214Z"
    }
  ],
  "counts": {
    "pending": 0, "parsing": 0, "chunking": 0, "embedding": 1,
    "completed": 1, "failed": 1
  },
  "total_active": 1,
  "has_failure": true
}
```

> 说明:此前我在文档里把缺口 #8 标为"后端已提供上传接口"是**误判** —— 上传只入队,
> 后续阶段原本只能按知识库逐个轮询,顶栏需要的跨页面聚合来源不存在。本端点即为此补上。

### 字段语义

| 字段 | 含义 |
|---|---|
| `active` | 在途(`pending/parsing/chunking/embedding`)+ **近期失败**的文档;**已完成的不返回**(避免列表膨胀) |
| `counts` | 空间内各状态计数,含 `completed`;可直接算"还有几个在处理" |
| `total_active` | 未终结数量;**为 0 即"都处理完了"** |
| `has_failure` | 有失败文档时为真 → 顶栏可提示"有文档处理失败" |

### 前端要点

1. **轮询策略**:`total_active > 0` 时按 2–3s 轮询(可与文档列表共用节奏),归零后**停止轮询**;
2. 浏览器上传阶段(axios `onUploadProgress`)与本接口是两件事:上传完立刻调一次本接口,进度浮层从"上传中"切到"入库中";
3. `failed` 项的 `error_message` 可直接展示(见 §5.3 文案建议);
4. 想跳转到失败文档:用 `kb_id` + `document_id` 拼详情路由。

## 6. 其余字段扩展

### 6.1 知识库聚合统计

`KnowledgeBaseOut` 现有(真实响应):

```json
{
  "id": "e9226546-2548-40d2-bcd0-6e46c90694be",
  "space_id": "031595d7-2622-4d82-9c6f-31d46043a2f2",
  "name": "产品手册库",
  "description": "示例",
  "embedding_model": "dashscope/text-embedding-v3",
  "embedding_dim": 1024,
  "document_count": 3,
  "chunk_count": 1,
  "size_bytes": 266240,
  "index_status": "processing",
  "created_at": "2026-09-16T15:12:23.350904Z"
}
```

`index_status` 四态,正好对应原型卡片的四种状态:

| 值 | 含义 | 建议呈现 |
|---|---|---|
| `empty` | 无文档 | 灰点 / "暂无文档" |
| `processing` | 有文档在途 | 蓝点(动态)/ "索引中" |
| `ready` | 全部完成 | 绿点 / "就绪" |
| `degraded` | 存在失败文档 | 橙点 / "部分失败" |

列表与详情接口都会返回统计,**一次查询算齐**(不会逐库查询)。`size_bytes` 是原始文件体积之和,前端自行格式化(如 260.0 KB)。

⚠️ **状态优先级**:同时存在"在途"与"失败"文档时,`index_status` 取 `processing`(判序:`empty` → `processing` → `degraded` → `ready`)。
即上例中 3 篇文档(1 完成 / 1 索引中 / 1 失败)显示的是 `processing` 而非 `degraded`。
若需要"有失败"的提示,请用 §5 的 `has_failure`(那个是独立字段,不受优先级影响)。

### 6.2 文档失败原因

`DocumentOut.error_message`(真实响应):

```json
{
  "id": "be6197b3-6ecf-4e5d-a766-1afb5d3cd3d5",
  "filename": "旧版.doc",
  "format": "docx",
  "status": "failed",
  "error_code": "INGEST_FAILED",
  "error_message": "仅支持 pdf/docx/xlsx/pptx/md/txt(旧版 office 格式请另存为新格式)"
}
```

- `error_code` 是**稳定机器码**(`INGEST_FAILED`),用于分支判断;
- `error_message` 是**任务侧真实原因**,用于展示定位(如 `DASHSCOPE_API_KEY 未配置(环境变量或 server/.env 任一处)`);
- ⚠️ `error_message` **不保证面向终端用户友好**(可能是运维向的技术描述)。本系统是内部工具,建议直接展示 + 一句引导;若要给业务用户看,前端可配通用文案。
- 建议在失败行提供"重新解析"按钮(§3),用户修好原因后一键重试。

### 6.3 分块列表带 token 数

`ChunkOut.tokens`(入库时算好的整数,可能为 `null`):分块列表可显示"137 tokens";
`meta.kind` 现有取值仅 `text` / `table`(原型里的"标题"类型不存在,标题已作为**面包屑上下文**并入分块内容,检索时可见)。

### 6.6 检索测试的请求级调参

`POST /api/v1/spaces/{sid}/retrieval/search` 请求体新增**可选**覆盖参数:

```json
{
  "query": "混合检索",
  "top_k": 3,
  "kb_ids": [],
  "model_id": null,
  "vector_weight": 0.5,
  "fulltext_weight": 0.5,
  "min_score": 0.2,
  "rrf_k": 30
}
```

真实响应(单路命中示例):

```json
[
  {
    "chunk_id": "d657ddab-60e0-4cd6-a7da-af990265cf8b",
    "document_id": "ec63577e-84bd-48a3-9aad-de3d429342f3",
    "kb_id": "e9226546-2548-40d2-bcd0-6e46c90694be",
    "filename": "手册.pdf",
    "content": "混合检索使用 RRF 融合向量与全文两路排名。…",
    "score": 0.016129,
    "vector_rank": null,
    "fulltext_rank": 1,
    "meta": { "kind": "table", "page": 3, "tokens": 137, "breadcrumb": ["产品手册库", "检索设计"] }
  }
]
```

**语义:只对本次调用生效,不写回空间配置** —— 对应原型 Tab B
"以上参数仅用于本次测试,不会修改知识库默认配置"。不传则用空间级配置。

前端要点:

1. ⚠️ **`vector_rank` / `fulltext_rank` 可能为 `null`**:上例只被全文路命中,`vector_rank` 就是 `null`。
   渲染"双路命中"标记时要判空,不要假设两者都有;
2. `score` 是 **RRF 融合分**(量级约 0.016 这种小数),**不是相似度**、不可跨查询比较,别当百分比展示;
3. `vector_weight` 与 `fulltext_weight` 必须**成对提供**,且和 ≤ 1,否则 422;
4. 若用户想"把这套参数存为空间默认",再显式走 `PATCH /spaces/{id}`(Admin+)。

## 7. 错误码(本轮新增)

| 场景 | HTTP | `error.code` |
|---|---|---|
| 处理中文档重复重解析 | 409 | `DOCUMENT_BUSY` |
| 分块 id 不存在 / 不属于该文档 | 404 | `CHUNK_NOT_FOUND` |
| 检索覆盖参数:权重不成对 / 和 > 1 / 越界 | 422 | `VALIDATION_ERROR` |
| 模型未配置(服务端缺 Key,**用户无法自救**) | 503 | `MODEL_NOT_CONFIGURED` |
| 上游模型调用失败(超时/限流/错误响应) | 502 | `MODEL_CALL_FAILED` |

统一响应壳不变:`{"success": false, "error": {"code", "message", "details"}}`。

### 503 与 502 的区分(前端提示语不同)

| 码 | 谁的问题 | 建议提示 |
|---|---|---|
| `MODEL_NOT_CONFIGURED` (503) | 服务端没配好(缺 Key),**用户重试无用** | "服务尚未配置模型,请联系管理员" |
| `MODEL_CALL_FAILED` (502) | 上游临时故障(超时/限流),**重试可能成功** | "模型服务暂时不可用,请稍后重试" |

> 更正:本文早期版本把"模型未配置"写成 502 —— 那是实现缺陷期的推测值。
> 当时该异常是裸 `Exception`,实际落到 `500 INTERNAL_ERROR`(前端实测发现)。
> 现已按语义修正为 503 并纳入统一错误壳,前端可按 `error.code` 分支。

### SSE 流内失败同样会被告知

`POST /spaces/{id}/ask` 的流一旦开始(已发 `meta`),HTTP 状态码就固定为 200,
后续失败**只能**通过 `error` 事件传达。检索(含查询向量化)失败时事件形如:

```
data: {"type": "error", "message": "DASHSCOPE_API_KEY 未配置(环境变量或 server/.env 任一处)", "code": "MODEL_NOT_CONFIGURED"}
```

前端应在收到 `error` 时停止 loading 并展示 `message`;此时**不会**再收到 `done`。

## 8. 本轮**未**实现(附理由)

| 项 | 为什么不做 |
|---|---|
| 各阶段耗时(原型"12.4s") | 需在流水线逐阶段记时间戳(新表/JSONB 结构),属可观测性建设而非接口缺失,建议随 M3 流水线插件化一起做 |
| 审计按"结果"筛选 | 用 `action=access.denied` 已可等价筛出被拒记录,无需再加 `result` 参数 |
| 审计日志导出 | 产品决定不做(涉及批量数据外带与下载鉴权,价值低于其他项) |
| 分块 `meta.kind` 细分"标题" | 标题已作为面包屑进分块内容(检索可见),再标 kind 收益很小 |
| 成员头像(他人) | 需新增"按用户 id 取头像"接口;当前 `avatar_url` 只对自己有意义(§6.4) |
| 头像上限写进契约 | FastAPI 无法把运行时配置值写进静态契约,且上限可配;已在文档写明默认 2MB / 单边 4096px |
| 权重和 ≤ 1 的契约级约束 | OpenAPI 表达不了跨字段约束,只能前后端各写一份(前后端错误信息保持一致) |

## 9. 对接自检清单

1. 模型下拉能从 `GET /models` 渲染,且提交的是 `id` 字段;
2. 检索测试的滑块只进请求体,调完确认空间配置未被改(`GET /spaces/{id}` 的 `retrieval_params` 不变);
3. 双路命中标记对 `rank` 为 `null` 的情况不崩;
4. 失败文档能显示 `error_message` 并可用"重新解析"重试;重试后状态轮询恢复;
5. 顶栏进度:`total_active > 0` 时轮询,归零停止;有失败时提示;
6. 知识库卡片的四个统计与 `index_status` 四态都有对应呈现;
7. 引用抽屉的"查看完整原文块"走 §4 接口(而非只显示 excerpt);
8. 头像:上传/删除通、blob 渲染、`revokeObjectURL`、`avatar_url` 直接拼 baseURL 可用;
9. 会话可重命名;
10. `npm run build` 零错误。
