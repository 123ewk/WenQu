## 3. 分页面要点与自检点

### 3.1 全局两项(先做,#12 与 04 页失败重试联动)

**#12 顶栏入库进度**
- `active` = 在途(pending/parsing/chunking/embedding)+ 近期失败,**不含已完成**;
  `total_active = 0` 即"都处理完了";`has_failure` 独立提示"有文档处理失败"。
- 轮询:`total_active > 0` 时 2–3s 一轮,归零**停止**;浏览器上传完成立刻调一次
  (浮层从"上传中"切"入库中");跳转失败文档用 `kb_id` + `document_id`。
- 自检:上传后顶栏出现进度、完成后自动消失;失败项可点进详情。

**#2 活动空间恢复**
- F5 恢复:`AppLayout` 挂载调 `GET /users/me`,用 `current_space_id` 恢复活动空间;
- 切空间(`/auth/switch-space`)响应是完整 `AuthResponse`(含新 `current_space_id`),以后者为准,
  替代 `localStorage` 自管。
- 自检:刷新后活动空间保持;切空间后再刷新仍正确。

### 3.2 02 对话页(#6 #10 #11)

- **#6 模型下拉**:提交用 `id`(如 `deepseek/deepseek-chat`),不是 `model`;`provider` 是显示名可做分组;
  只返回已启用模型;**不返回密钥配置状态**,选中后仍可能 503 —— 503 提示"联系管理员"、502 提示"稍后重试",勿混。
- **#10 引用抽屉全文**:`citations[].excerpt` 只截前 300 字,"查看完整原文"用 `chunk_id` 调单块全文接口;
  文档删除后 404 属预期(提示"原文档已删除");`content` 不截断,抽屉限高滚动;可展示 `meta.breadcrumb` 与 `meta.page`。
- **#11 会话重命名**:`title` 1–128 字;列表按 `updated_at` 倒序,重命名后该会话会排到最前(属预期)。
- 自检:下拉能选且提交 `id`;点引用角标能看全文;重命名生效。

### 3.3 03 知识库列表(#8)

- 四字段 + `index_status` 四态对应原型四色:`empty` 灰 / `processing` 蓝(动)/ `ready` 绿 / `degraded` 橙;
- ⚠️ 优先级 `empty → processing → degraded → ready`:在途与失败并存时显示 `processing`;
  "有失败"的提示用 #12 的 `has_failure`,不要从 `index_status` 推;
- `size_bytes` 是原始文件体积之和,前端自行格式化。
- 自检:四种状态都能呈现(可造不同状态的文档验证)。

### 3.4 04 知识库详情(#6 #7 #9)

- **#9 失败原因 + 重试**:failed 行展示 `error_message`(任务侧真实原因,**可能偏运维向**,内部工具直接展示 + 一句引导);
  `error_code` 是稳定机器码,分支用它;"重新解析"按钮仅 Editor+ 显示;
  只能在终结态(completed/failed)调用,非终结态 409 `DOCUMENT_BUSY`(此时应禁用按钮);
  成功后文档回 `pending`,**恢复该行的状态轮询**。
- **#7 请求级调参**:四个可选覆盖参数**只对本次调用生效**,调完确认空间配置未被改;
  `vector_weight`/`fulltext_weight` 必须成对提供且和 ≤ 1,否则 422;
  `score` 是 RRF 融合分(约 0.016 量级),不是相似度、不可跨查询比较、别当百分比;
  `vector_rank`/`fulltext_rank` 可为 `null`(单路命中),双路标记要判空。
- **#6 换嵌入模型**:同 GET /models;换 embedding 会改向量维度 = 需重建索引,**二次确认**,
  并提示可用"重新解析"重建。
- 自检:造一个失败文档(如上传 `.doc` 旧格式)→ 看到原因 → 修好后一键重试 → 轮询恢复;
  调参测试后空间配置不变。

### 3.5 05 分块预览(#13)

- 分块列表显示 `tokens`(入库时算好,可 `null`);`meta.kind` 只有 `text`/`table`,
  **没有"标题"类型**(标题已作为面包屑并入内容)。
- 自检:列表有 token 列,类型只有两种。

### 3.6 06 空间管理(#5)

- `retrieval_params` 五参数及范围:`rrf_k` 1–1000、`vector_weight` 0–1、`fulltext_weight` 0–1、
  `min_score` 0–1(向量路最小余弦相似度)、`default_top_k` 1–50;
  **真实驱动检索,改完立即生效,无需重建索引**;
- 表单校验与后端对齐:越界 422;`vector_weight + fulltext_weight ≤ 1`(建议联动滑块);
- ⚠️ `PATCH /spaces/{id}` 的字段语义:`name` 必填;`description` **省略会被清空**(不是保持不变);
  `retrieval_params` 省略 = 不改动。**提交时把当前表单的 name/description 一并带上**,
  只想改检索参数却漏传 description 会把空间描述清空。
- 自检:保存后重进回显正确;权重和 1.8 得 422 且有字段级可读提示。

### 3.7 08 审计日志(#1)

- 筛选参数 `action` / `actor_id`(UUID)/ `since` / `until`(ISO8601,**闭区间**;
  日期控件默认给当天 00:00,要"包含整天"需把 until 设为次日 00:00);
- 响应项 `result` 是**展示枚举**(`success` | `denied`),**不是筛选参数**(筛被拒记录用 `action=access.denied`);
  `actor_name` 是操作人昵称冗余,直接展示,无需再拿 actor_id 查人。
- 自检:按动作/时间筛选有结果;当天边界记录被包含。

### 3.8 09 个人中心(#3 #4)

- **#4 头像三端点**:GET 契约类型为 `image/png|jpeg|webp`(blob 渲染 + `revokeObjectURL`);
  上传上限 2MB / 单边 4096px —— **写进前端校验**(契约表达不了运行时配置);
  `avatar_url` 值 = `/users/me/avatar`(**不带 `/api/v1` 前缀**,直接拼 baseURL)。
  ⚠️ 只能渲染**自己的**头像;成员列表不渲染他人头像(后端无按 id 取头像接口,OPT-19 触发式)。
- **#3 上次登录**:`last_login_at` / `last_login_ip` 直接展示;IP 取**直连地址**,挂网关时会显示代理 IP
  → 文案保持中性("上次登录来源"),不要写 IP 归属地/城市之类。
- 自检:上传→显示→删除全通;两字段有值。
