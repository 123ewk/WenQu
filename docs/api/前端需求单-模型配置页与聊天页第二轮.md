## 1. 需求① 重排区块标题去重(用户原话:"为什么会有两个 rerank")

### 现象

`/settings/models` 往下滚,重排这一段连着出现三个带 "Rerank" 的标题:

1. 卡片标题「重排(Rerank)」+ 开关
2. 子块标题「Rerank 重排供应商」
3. 子块标题「Rerank 重排模型」

### 根因(前端渲染叠字,不是数据重复)

`views/settings/ModelConfigView.vue:204-223` 把 `ProvidersModelsBlock kind="rerank"` 塞进了④卡内部,
而 `views/settings/ProvidersModelsBlock.vue:48-52` 的 `TYPE_LABELS.rerank = 'Rerank 重排'` 又被
子块标题模板拼了一次:

- `ProvidersModelsBlock.vue:372` → `{{ kindLabel }}供应商`
- `ProvidersModelsBlock.vue:421` → `{{ kind === 'chat' ? '对话模型' : `${kindLabel}模型` }}`

外层卡已说明"这是重排",内层再各带一遍就成三段复读。

### 改法(任选其一,推荐 A)

- **A. 区块内不再复读类别**:给 `ProvidersModelsBlock` 加一个可选 prop `hideKindLabel`(或 `titlePrefix=""`),
  ④卡内调用时置为真,两个子标题退化为「供应商」/「模型」;②③卡(对话)保持现状不动。
  顺带把 `TYPE_LABELS.rerank` 改成 `'重排'`(现在这个值还拼在别处的文案里,统一掉)。
- **B. 只改文案**:`'Rerank 重排'` → `'重排'`,接受"重排供应商 / 重排模型"两个子标题。

### 后端设计口径(不要试图"修"它)

开关与模型清单**故意解耦**:`GET /model-config/view` 的 `rerank` 只有 `{enabled, default_model}`,
模型走 `models[]` 里 `kind==='rerank'` 的行。开关是**链路开关**(PUT `rerank-switch`),模型是**目录**。
所以"开了开关但没模型"是合法状态,后端语义 = 等同关闭;`ModelConfigView.vue:212-218` 那条黄色提示
(`rerankNoDefault`)就是为此而设,**保留**。

### 验收

- 重排这一段整屏只出现一次「重排」字样(卡片标题),子块标题为「供应商」/「模型」。
- 对话那一段(区块②③)文案不变,不出现「对话模型模型」复发(注意 `71185cc` 已修过一次同类拼接,别改回去)。

类型定义见后端 `server/src/app/application/service/space_models.py:83-119`;前端类型里 `doc_url: string`

### 改法

在 `ProvidersModelsBlock.vue:493-503`(供应商类型那一项)**正下方**渲染一行链接:

- 只在**新建**态显示(`v-if="!providerDialog.editingId"`,与类型下拉同一个条件)。
- 选了类型且 `doc_url` 非空才渲染;`doc_url === ''` 不渲染、不占位。
- 文案用**通用措辞**:`打开官方文档 / 控制台获取 API Key ↗`。
  不要写死"创建 API Key"—— Ollama/vLLM 那两项指向的是模型库和文档,本地端点本来就免 Key。
- `target="_blank" rel="noopener noreferrer"`;`href` 直接用 `doc_url` 原值,**不要拼接任何用户输入**
  (尤其不能把已填的 Key 或名称拼进 URL)。
- 位置建议放在 `ProvidersModelsBlock.vue:502` 那行 `pm-hint` 里或紧随其后,别新增弹窗高度。

### 验收

- 选 DeepSeek → 出现可点链接,新标签页打开 `platform.deepseek.com/api_keys`。
- 选 OpenAI 兼容自建 → 不出现链接、无空白占位。
- 选 Ollama(本地) → 出现的文案不承诺"创建 API Key"。
- 编辑供应商时不出现该行。

## 3. 需求③ 模型名要有预设 + 支持自定义(rerank 和 LLM 都要)

### 现象

「新建模型」弹窗里「模型名」是纯输入框(`ProvidersModelsBlock.vue:560-561`),用户不知道该填什么;
旁边的「上下文窗口」反而已经有预设下拉(`CONTEXT_PRESETS`,`563-573`)。

### 两处数据源,分阶段做

- **目标态(后端交付后)**:`/model-config/types` 每一项**加法式**新增 `model_names: list[str]`
  —— 该类型下常见上游模型名的**提示清单**。登记号 **OPT-36**,详见后端文档。
- **过渡态(现在就能做)**:前端先放一份常量表(按 `type.key` 索引),文件顶部或独立
  `views/settings/modelPresets.ts`,并标 `// TODO(OPT-36):后端 /types 下发 model_names 后删掉本地常量`。
  上线后切数据源,UI 行为不变。

### 交互要求

- 控件:可自定义的下拉 —— `el-select` 加 `filterable allow-create default-first-option`,
  或 `el-autocomplete` 带建议列表。**必须允许输入任意值**,预设只是提示。
- 数据源随**所选类型**切换(`typeOptions` 已按 `kinds` 过滤,`ProvidersModelsBlock.vue:65`)。
- **编辑态**:当前值不在预设里也必须正常显示(把当前值 unshift 进选项,或用 `allow-create` 天然支持)。
- placeholder 保留"实际调上游的名字"(如 `deepseek-chat`),并明确"可自定义、不在清单里也能填"。
- 后端**不校验**模型名是否在预设内(现在也没有校验,`SpaceModelIn.model_name` 只限长度)。
  填错的表现是【测试模型】/实际调用时上游报 `model_name` 类错误,前端已有分诊提示,不变。

### 内容提醒(必须写进 UI 文案或 tooltip)

- 百炼重排**只能填 `gte-rerank-v2`(或 `qwen3-rerank`)**:`gte-rerank`(无 `-v2`)已于 2026-05-30 下线,
  填它必然拿到上游报错。类型 label 里已带 `(gte-rerank-v2)`,预设清单也要以此为准。

### 验收

- 选「DeepSeek」→ 模型名下拉出现 `deepseek-chat` / `deepseek-reasoner` 之类候选,且能手输任意值。
- 选「阿里云百炼重排」→ 候选含 `gte-rerank-v2`,**不含**已下线的 `gte-rerank`。
- 编辑一个模型名为自定义值的行 → 弹窗打开后值不丢、不报错。
- 自定义名保存成功(后端不拦);【测试模型】失败时按现有分诊提示展示。

## 4. 需求④ 聊天页去掉内置的「默认模型」这一项(留占位)

### 现状

- `views/chat/ChatView.vue:970` → `<el-option label="默认模型" value="" />`
- `selectedModelId = ''` 的含义:提交时不传 `model_id`(`ChatView.vue:456` `model_id: selectedModelId.value || null`),
  由服务端按 **空间默认 → 全局默认** 自选。
- 下拉清单来自 `GET /api/v1/models`(见 §4.2),按 `provider` 分组。

用户要求:**这一项从可选项里删掉**,占位即可(以后可能放别的功能)。

### 4.1 改法

- 删掉 `ChatView.vue:970` 那个 `el-option`。
- `el-select`(`963-974`)加 `placeholder="默认模型"` + `clearable`,并在 tooltip/`:title` 上说明
  "不选 = 由服务端按本空间默认模型回答"。清空后回到 `''` 即当前"不传 `model_id`"语义,**提交逻辑不用改**。
- `ChatView.vue:193` 的兜底文案(`?? '默认模型'`)保留 —— 它现在是 placeholder 口径的显示值,不是选项。
- 消息气泡上的模型名 `ChatView.vue:778` 这条**不要动**:
  `model_id` 为 null 表示"走了默认模型",不是缺陷(后端已登记 OPT-33,真要显示实际模型得等加法式新增
  `resolved_model_id`)。

### 4.2 "把模型配置里配好的 LLM 列出来" —— 已经是这个数据源

`GET /api/v1/models` 返回 **全局 ∪ 当前活动空间**(空间行遮蔽全局),且**只列已启用**的模型
(供应商 `enabled` 且模型行 `enabled`)。所以在配置页建好对话模型并设默认后,聊天页刷新即可看到。

- 活动空间由 **access token 里的 `sid`** 决定(不是请求头/查询参数)。前端切换空间会走
  `POST /auth/switch-space` 换 token → 之后重拉清单才对。
- `ChatView.vue:251-262` 已在 `auth.currentSpaceId` 变化时重拉 catalog(注释在 `257`),
  **这条别改坏**;换空间后如果清单没变,先确认换 token 与重拉的先后顺序,不要加前端本地缓存。
- 空清单已有引导:`ChatView.vue:179` `chatCatalogEmpty` → `976` 的「去配置」路由链接,**保留**。

### 验收

- 下拉里没有名为「默认模型」的**可选项**;未选择时框内显示占位文字。
- 不选任何模型直接问 → 正常回答(请求体里无 `model_id` 或为 null)。
- 选一个显式模型问 → 回答用该模型(这条已联调过,回归即可)。
- 在 A/B 两个空间来回切:清单内容随空间变,A 空间未配对话模型时出现「去配置」引导。
- 清空选择 → 又回到"不传 `model_id`"。

## 5. 【必须修】重排供应商按 protocol 硬编码分块 —— 上一轮后端修复引出的回归

### 问题

`ProvidersModelsBlock.vue:57-61`(注释也在 `8-9`、`57`)是这么分块的:

```
props.kind === 'rerank' ? p.protocol === 'cohere_rerank' : p.protocol !== 'cohere_rerank'
```

后端上一轮(F2)给百炼重排新增了独立协议 **`dashscope_rerank`**(它不兼容 cohere 平铺形状),
现在 `view.providers[].protocol` 可能是 `openai_compatible` / `cohere_rerank` / `dashscope_rerank`。
上面这行的后果:

1. 用户新建「阿里云百炼重排(gte-rerank-v2)」供应商 → 它的行**不出现在重排区块**(看起来像"配了但没生效");
2. 同一个行**串进对话供应商区块**(`protocol !== 'cohere_rerank'` 为真)。

### 改法(按优先级)

- **A(推荐,等后端)**:`/model-config/view` 的 `providers[]` 会加法式新增 `kinds: list[str]`
  (登记 **OPT-35**),分块改成 `p.kinds.includes(props.kind)`。前端契约影响仅一个新增字段。
- **B(今天就能做,过渡)**:`const RERANK_PROTOCOL_SUFFIX = '_rerank'` →
  `props.kind === 'rerank' ? p.protocol.endsWith('_rerank') : !p.protocol.endsWith('_rerank')`,
  并标 `// TODO(OPT-35):改用 providers[].kinds`。
- **C(不要做)**:在前端写死 `['cohere_rerank','dashscope_rerank']` 常量 —— 后端每加一个重排协议就要来改一次,
  这正是后端本轮消灭掉的复制清单(后端已改为从协议注册表派生)。

### 验收

- 新建「阿里云百炼重排」→ 只出现在重排区块;新建 DeepSeek → 只出现在对话区块。
- 新建「SiliconFlow 重排」→ 仍在重排区块(回归)。
- 两个重排供应商并存时,重排区块列全,对话区块不串。

## 6. 边界与禁测

- **不要动 API 路径、字段名、请求体形状**;本单需要的加法式字段已由后端在 OPT-35/36 里给出,
  不在范围内的字段请走回复文档提出来。
- `/model-config/*` 与 `/token-usage*` **只认 JWT**,带 API Key(无 Bearer)一律 401 —— 这是故意的,别"顺手兼容"。
- 明文 Key 只允许出现在提交那一跳:不进 `localStorage`/`sessionStorage`、不进 URL、不打日志、
  不做"复制到剪贴板"以外的持久化;`key_hint` 才是可显示的那个掩码值。
- **不要用"重排后排序没变"来判 bug**:重排只改顺序不改融合分(`score` 恒为 RRF 融合分),
  响应上看不出是否参与(后端已登记 OPT-34,当前不可观测是设计后果)。验收重排只看
  【测试模型】通过 + 开关状态与 `default_model` 正确。
- 百炼重排的 `base_url` 用类型默认值 `https://dashscope.aliyuncs.com`(只到站点根,别补 `/v1` 或 `/compatible-mode/v1`)。

## 7. 联调验收顺序(建议)

1. 区块①文案 + 区块⑤分块接线(先修回归,否则后面配了看不到)。
2. 新建供应商「阿里云百炼重排(gte-rerank-v2)」→ 出现文档链接 → `base_url` 留空取默认 → 填 Key → 保存。
3. 新建该供应商下的 rerank 模型 → 模型名下拉出现预设 → 选 `gte-rerank-v2` → 【测试模型】。
4. 自定义一个不在预设里的模型名 → 能保存;【测试模型】报上游 `model_name` 类错误(证明"不校验"成立)。
5. 打开重排开关、设为默认 → 提问一次,回答正常、无报错(不判排序)。
6. 聊天页:确认无「默认模型」可选项、占位文案正确、不选能答、选了能答。
7. 换空间(含一个未配对话模型的空间)→ 清单与「去配置」引导都对。
