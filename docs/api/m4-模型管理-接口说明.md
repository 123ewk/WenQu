# M4 · 模型管理接口说明(全局层 OPT-25 + 空间层 OPT-27)

> **机器契约**:`docs/api/openapi.json`(字段/枚举唯一事实源)。
> 本文讲流程、边界与运维要点。内置 models.yaml 已下线:**模型清单的唯一数据源是库**。
>
> 本文有两组接口,别混:
> - §1–§5 与 §7 = **全局层** `/api/v1/admin/*`(superuser 专属,运维配置入口)。
>   现有前端页面(07 等)**不需要接入本组接口**;
> - §6 = **空间层** `/api/v1/spaces/{sid}/model-config/*`(OPT-27,给前端"模型配置页"接入,
>   门槛是空间 Admin+ 而非 superuser)。
> 两层共用同一套表与协议注册表,靠 `space_id` 分层,互不越界(§6.1)。

---

## 1. 概念

- **供应商 `model_providers`**:一个可调用的 OpenAI 兼容端点 = 名称 + `base_url` +
  `protocol`(协议注册表键,当前仅 `openai_compatible`,探测用
  `GET /api/v1/admin/model-protocols`)+ 密钥(写入口 AES-256-GCM 加密落库,
  响应只给 `key_hint` 掩码,**任何接口不回显明文**)。
- **模型 `custom_models`**:挂在供应商下,`kind` ∈ chat / embedding / rerank;
  `model_id` 是对外唯一 id(如 `deepseek/deepseek-chat`,进 `/api/v1/models` 契约
  与 `/ask`、建库参数的就是它),`model_name` 是上游真实模型名。
- **默认模型**:每个 kind 至多一个 `is_default`(服务内互斥 + 库内 partial unique
  双保险);未启用的模型/供应商不能设默认。问答与入库取默认模型。
- **维度硬约束**:`chunks.embedding` 是 `vector(1024)` 定宽列 —— embedding 模型
  **必须显式声明 `dims` 且只能为 1024**,写入时拦截(422),不留到第一次入库才炸。

## 2. 权限口径

| 身份 | 结果 |
|---|---|
| 未登录 | 401 `AUTH_REQUIRED` |
| 普通登录用户(含 Admin/Owner 空间角色) | 403 `FORBIDDEN` —— 这是**平台级**配置,与空间角色无关 |
| `users.is_superuser = true` 的 JWT | 放行 |
| 任何 API Key | 401 `AUTH_REQUIRED`(端点只挂 JWT 依赖,带 Key 不带 Bearer 就是"没登录";路径也未登记进 Key 授权表,fail-closed) |

superuser 无自助开通接口:由运维直接改库(见 `docs/上线手册.md`),这是刻意的最小暴露面。

## 3. 端点一览

| 方法/路径 | 说明 |
|---|---|
| `GET /api/v1/admin/model-protocols` | 协议注册表键清单(渲染 protocol 下拉) |
| `GET/POST /api/v1/admin/model-providers` | 供应商列表 / 新建(201) |
| `PATCH/DELETE /api/v1/admin/model-providers/{provider_id}` | 改 / 删(204,级联删其下模型) |
| `GET/POST /api/v1/admin/models` | 模型列表(含停用,与公开 `/api/v1/models` 不同) / 新建(201) |
| `PATCH/DELETE /api/v1/admin/models/{model_id}` | 改 / 删(204);路径参数是**表主键 id**,不是对外 `model_id` |

密钥 PATCH 语义:`api_key` **不传 = 不改动;传空串 = 清除密钥(转本地免密钥端点,如
Ollama);传非空 = 更换**。

## 4. 校验与错误(fail-closed 清单)

| 场景 | 返回 |
|---|---|
| `protocol` 不在注册表 | 422 VALIDATION(消息列出已注册协议) |
| `base_url` 非 http(s):// 开头 | 422 VALIDATION |
| `base_url` / `api_key` 含非 ASCII 或内部空白 | 422 VALIDATION(消息含"ASCII";首尾空白自动去掉,纯空白=空串) —— 全局层与空间层同一道校验 |
| embedding 缺 `dims` / `dims ≠ 1024` | 422 VALIDATION |
| 同名供应商 | 409 `MODEL_PROVIDER_NAME_TAKEN` |
| 对外 `model_id` 已存在 | 409 `MODEL_ID_TAKEN` |
| 目标/默认设置对象未启用 | 422 VALIDATION |
| id 不存在 | 404 NOT_FOUND |

> **唯一性按层算**(OPT-27 迁移 0013):本组接口只管全局层,撞名对象是**全局层内**的
> `name`/`model_id`;某个空间里已经用了同名供应商/模型**不算冲突**,反之亦然。
> 默认标记同理:全局每种 kind 一个默认,每个空间各有一套默认。

## 5. 运行时语义(配置错了会怎样)

- 解析/问答按**请求时**的库内快照取模型:每请求(server)/每轮任务(worker)
  重读目录,改配置即时生效,无需重启。
- 删除供应商 → 级联删其下模型 → 被 KB/历史消息引用的 `model_id` 不可解析 →
  调用时 503 `MODEL_NOT_CONFIGURED`(消息点名 kind),**不静默兜底**。
- `GET /api/v1/models`(登录即可读)只列**已启用**模型 + `defaults`;
  空清单(新部署未配置)是合法状态,返回空数组 + `{}`。
- 每次增删改都写空间无关审计(`model_provider.created/updated/deleted`、
  `model.created/updated/deleted`)。

## 6. 空间层模型配置(OPT-27,给前端"模型配置页")

### 6.1 分层与遮蔽

同一张 `model_providers`/`custom_models` 表按 `space_id` 分两层:`NULL` = 全局层
(superuser `/admin/*` 管),非空 = 该空间私有层(本组端点管)。每请求(问答/检索)
或每任务(入库)现读一份**合并快照**:

- **空间行遮蔽同名全局行**:供应商按 `name`、模型按 `model_id` 遮蔽,空间层的
  `deepseek/deepseek-chat` 顶掉全局那条,改的是空间行的 base_url/Key;
- 默认值解析顺序:对话 `空间默认 chat → 全局默认 chat → 503`;向量化见 6.4;
  重排只认空间层(全局没有 rerank 挂点);
- **互不越界**:本组端点看不到也改不了全局行,反之 `/admin/*` 也动不了空间行
  (服务层每条查询带层谓词,跨层读改写一律 404);删空间/删供应商都级联,不留孤儿。

### 6.2 权限口径

| 身份 | 读(`GET` 聚合视图、`GET /types`) | 写与【测试连接】 |
|---|---|---|
| 未登录 | 401 `AUTH_REQUIRED` | 401 |
| 非本空间成员 / 空间不存在 | 404 `SPACE_NOT_FOUND`(与"没这个空间"同壳,防枚举) | 404 |
| 本空间 Viewer/Editor | 200 | 403 `FORBIDDEN`"需要空间管理员权限" |
| 本空间 **Admin(30)/Owner(40)** | 200 | 200 |
| 任何 API Key | 401 `AUTH_REQUIRED`(端点只挂 JWT 依赖,路径也未登记进 Key 授权表) | 401 |

superuser 与本组无关:平台管理员不是某空间的 Admin 时,对本组端点同样是 403/404。

### 6.3 端点一览(前缀 `/api/v1/spaces/{space_id}/model-config`)

| 方法/路径 | 门槛 | 说明 |
|---|---|---|
| `GET ""` | 成员 | 聚合视图:`{embedding, rerank, providers[], models[]}`,Key 一律掩码 |
| `GET /types` | 成员 | 供应商名字清单(13 项):`{key,label,doc_url,default_base_url,protocol,kinds}` |
| `PUT /embedding-key` | Admin+ | `{api_key}`;空串 = 清除本空间 Key |
| `POST /embedding-key/test` | Admin+ | `{api_key?}`(不传 = 测已存 Key),向内置模型发一条短文本 |
| `PUT /rerank-switch` | Admin+ | `{enabled}`;"开了就用",与是否已配模型解耦 |
| `POST /providers` | Admin+ | `{provider_type,name,base_url?,api_key?,enabled}` → 201 |
| `PATCH /providers/{provider_id}` | Admin+ | 改显示名/base_url/Key/enabled(**协议不可改**,由类型决定) |
| `DELETE /providers/{provider_id}` | Admin+ | 204,级联删其下模型 |
| `POST /providers/{provider_id}/test` | Admin+ | 取该供应商下最早的一个模型探活;没有模型 422 |
| `POST /models` | Admin+ | `{provider_id,kind,model_name,model_id?,context_tokens?,enabled,is_default}` → 201 |
| `PATCH /models/{model_pk}` | Admin+ | 改 `model_name`/`context_tokens`/`enabled`/`is_default` |
| `DELETE /models/{model_pk}` | Admin+ | 204 |
| `POST /models/{model_pk}/test` | Admin+ | chat 发一条 `ping` 取首个增量;rerank 试排两条短文档 |

写表单要点:

- `provider_type` 必须 ∈ `/types` 的 `key`(未知 422 并列出可选值);`protocol` 由它决定,
  前端不传也不改;`base_url` **留空 = 用该类型的 `default_base_url`**,填了就用填的
  (不校验厂商白名单,但**生产环境要过 SSRF 闸门**,见下);
  `api_key` 空 = 免密钥本地端点(Ollama/vLLM);
- `model_id` 不传则合成 `{供应商 name}/{model_name}`;`kind` 必须与供应商协议匹配
  (`cohere_rerank` 只挂 rerank,其余只挂 chat);
- `PATCH` 密钥语义与全局层一致:**不传 = 不动,空串 = 清除,非空 = 更换**;
- **字符口径(实测踩过的坑)**:`api_key` 与 `base_url` 只接受**不含空白的 ASCII**(422 消息含"ASCII")。
  Key 原样拼进 `Authorization: Bearer …`、地址进 URL,带进中文/空格/换行会让第一次上游调用直接 500。
  首尾空白由后端**自动去掉**再入库(粘贴带换行是常态,不该报错),掩码按去空白后的值计算;
  纯空白串等价于空串(= 清除)。供应商 `name` 与 `model_name` 允许中文(只进界面与 `model_id`);
- 模型行的路径参数是**表主键 `id`**(响应里的 `id`),不是对外 `model_id`。

### 6.4 embedding:内置锁死 + 环境门控回落

embedding **模型本体不可换**(换模型 = 已入库向量全部作废),代码内置:
`text-embedding-v3` / 1024 维 / 百炼 compatible-mode 端点。空间能配的只有它的钥匙
(`space_model_settings.embedding_key_encrypted`),因此空间层 `kind` 不含 embedding。

| `settings.env` | 空间未配 Key 时 |
|---|---|
| `dev` | **回落全局层 embedding 配置**(保住存量 dev/CI 链路),视图里 `fallback_active=true`,日志打 WARNING 带 space_id |
| `prod` | **不回落**:全局 embedding 行根本不进空间快照,入库/检索 503 `MODEL_NOT_CONFIGURED`(消息点名"该空间未配置向量化 Key"),配置页红警示引导 Admin 去配 |

空间配了 Key 后两环境行为一致:内置模型顶为该空间 embedding 默认(与 env 无关)。

### 6.5 校验与错误

| 场景 | HTTP / code |
|---|---|
| 未知 `provider_type` / kind 与协议不匹配 / chat 缺 `context_tokens` / 供应商下无模型就测连接 | 422 VALIDATION |
| `api_key` 或 `base_url` 含非 ASCII 字符或内部空白(中文、空格、换行) | 422 VALIDATION(消息含"ASCII";首尾空白不报错,后端自动去掉) |
| **`base_url` 指向内网/本机/云元数据(prod)** | 422 VALIDATION(消息以"模型服务地址不安全:"开头) |
| 空间层试图建 embedding 模型 | 422 VALIDATION(消息说明内置锁死) |
| 空间层内 `name` 或 `model_id` 撞名 | 409 `MODEL_PROVIDER_NAME_TAKEN` / `MODEL_ID_TAKEN` |
| 目标行属于全局层或别的空间 | 404 NOT_FOUND(不泄露存在性) |
| 【测试连接】上游返回 401/403 / 400/404 / **其它任意状态码** | 424 `UPSTREAM_MODEL_ERROR` + `details.reason` = `auth` / `model_name` / `network`(其它状态码也归 `network`,message 带上游 `status=…`) |
| 【测试连接】连不上(DNS/拒绝连接/超时) | 424 + `reason=network`,message "网络不通或 base_url 有误" |
| 未配 Key 就测向量化 Key | 503 `MODEL_NOT_CONFIGURED`(缺配置不伪装成上游故障) |

`context_tokens` 建 chat 模型**必填**且不可事后省略:它是 OPT-29 上下文窗口进度条的分母
(已落地,`done` 帧与 `messages` 各带 `context_used_tokens`/`context_window_tokens`)。
**全局层**历史行的该列允许为空 —— 命中这类默认模型时分子照给、分母为 null,前端显示"窗口未配置";
要出完整进度条就在空间层配一个填了窗口的 chat 模型。

**为什么空间层要挡内网地址**:任何注册用户都能自助建空间、建完就是该空间 Owner,所以空间层的
`base_url` 是"任何一个注册用户都能让服务端去访问的地址"。`core/ssrf.py` 在写入时判定
(POST/PATCH 同一道):IP 字面量按地址类别判(回环/私网/链路本地即云元数据/组播/保留),
域名解一次 DNS(任一解析结果内网即拒),`localhost`/`*.internal`/`*.local` 按名字直接拒;
**DNS 解不出来放行**(那种地址本来就连不上,拦它会把离线环境与测试一起打死)。
环境口径:dev 恒放行(本地 Ollama/vLLM 就是 127.0.0.1);prod 默认拦截,确需内网自建网关
的私有化部署由运维显式配 `APP_ALLOW_PRIVATE_MODEL_URLS=1`(内网边界交回网络策略)。
**全局层 `/admin/*` 不套本闸门** —— 那是运维自己的判断,不是用户可控输入。
已登记的残余风险:写入后域名重绑定(DNS rebinding)这一类时序攻击不在本轮范围,
彻底方案要在传输层钉 IP;详见 `docs/优化台账.md`。

### 6.6 重排在检索链路里怎么生效

`rerank_enabled=true` 且该空间有默认 rerank 模型 → 混合融合产出 top-30 候选后、
上下文组装前调 `cohere_rerank` 协议重排取 top-K;**开关关 / 没有默认模型 → 完全跳过**
(不建网关,零开销)。上游失败或超过 5s 预算 → WARNING + 回落融合顺序,**不打断问答**。

### 6.7 审计

配置写操作与探活都进本空间审计列表(`GET /spaces/{id}/audit-logs`),操作人 = 该成员:
`model_provider.created/updated/deleted`、`model.created/updated/deleted`、
`model_setting.embedding_key.updated`(`detail.configured` 只记布尔)、
`model_setting.rerank.updated`(`detail.enabled`)、`model.tested`(成功失败都留痕,
`target` = 被探的 `model_id`,`detail` = `{ok: true}` 或 `{ok: false, reason: auth|model_name|network}`;
**失败那一次走独立会话落库**,否则请求事务 rollback 会把痕迹一起丢掉 —— 探活失败正是内网/凭据
探测的取证点)。**Key 明文永不进审计与日志。**

## 8. token 用量统计(OPT-28,给前端"用量页")

### 8.1 数据从哪来

`token_usage_events` 明细表(迁移 0014):**一次上游模型调用一行**,只追加不改写。
写入点是 chat / embedding 两个网关的**外层计量壳**(`app/application/service/usage.py`),
不是埋在各调用点里 —— Agent 模式一次提问要打多次上游,逐点埋一定会漏。
入库(worker)的向量化用量归属到**文档上传者**(`documents.uploaded_by`,可为空)。

- **旁路写入**:记账用自己的会话,任何失败只打 warning,**绝不打断问答/入库**;
- **从今往后计**:不回填历史(表里没有事件 = 那会儿还没上计量);
- **两种口径不混算**:`source=upstream`(厂商回传)/`estimated`(本地估算:1 汉字 0.75、
  1 字母 0.25 token,向上取整),聚合响应把估算部分单独给 `estimated_tokens`;
- **不计费**:重排(配置开关的附带开销)、配置页【测试连接】(管理员动作,不是成员业务用量);
  全局层(`space_id` 为空、无租户上下文)的调用同样不记账。
- **调用没发生就不记账**:chat 流一字节没回、上游也没交回用量数字(连不上、鉴权被拒、
  参数被拒)时**不落行**,免得虚增;中途断流则按已吐出的部分记 `estimated`。
  embedding 侧同理 —— 只在成功返回向量后记账。

**实测记录(dev,2026-09-21,`uvicorn :8012` + 本地假 OpenAI 上游)**:一次真 `/ask`
落两行(`embedding` 走 dev 全局回落的真厂商、`chat` 走假上游并回传 `321/18/339`,
两条都是 `upstream`),汇总响应 `space_total` 与成员行一致;把 chat 上游换成一个没人监听的
端口 → SSE 正常发 `error` 帧、**chat 行零写入**;【测试连接】的 ping 确认不带
`stream_options` 且不记账(与上面的"不计费"一致)。

### 8.2 端点(前缀 `/api/v1/spaces/{space_id}`)

| 方法与路径 | 门槛 | 说明 |
| --- | --- | --- |
| `GET /token-usage?period=7d\|30d\|all` | 空间 **Admin+**(默认档 `30d`) | `space_total` + 当前花名册逐成员明细 |
| `GET /token-usage/me?period=…` | 空间任意成员 | 只看自己一份 `usage` |

`period` 是 `Literal`,未知取值 **422**(不静默回落);`period=all` 时 `since` 为 `null`。
非成员/跨空间 → 404 `SPACE_NOT_FOUND`;角色不足 → 403 `FORBIDDEN`。
**API Key 不可用**:只挂 JWT 依赖,且刻意不登记进 `api_key_auth` 能力表(与 `/model-config/*`、
`/admin/*` 同为第二道 fail-closed 防线)→ 带 Key 无 Bearer 实测 401 `AUTH_REQUIRED`。

### 8.3 汇总口径的三个"为什么不等"

1. `Σ members.total_tokens ≤ space_total.total_tokens`:差额是 `user_id` 为空
   (上传者已注销)与**已退空间/已注销成员**的既成用量 —— 成员表是当前花名册,不是历史归属人;
2. `chat_calls` 是**上游调用次数**,不是提问次数(Agent 多轮各记一行);
3. 对话与向量化的 token 混在同一个 `total_tokens` 里(V1 不给成员看成本拆分),
   要按类别看用量请用 `chat_calls` / `embedding_calls`。
