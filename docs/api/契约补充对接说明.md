## 2. 当前活动空间(缺口 #7)

**背景**:原来 token 里的活动空间对前端不可见,前端只能自己用
`localStorage.wenqu_current_space_id` 维护。现在契约直接返回,建议**改为以契约值为准**
并删除自维护逻辑(否则会出现"前端以为在 A 空间、token 实际在 B"的错位)。

### 字段语义

| 场景 | `current_space_id` |
|---|---|
| 注册 / 登录(尚未选择空间) | `null` |
| `POST /auth/switch-space` 之后 | 该空间 id |
| `POST /auth/refresh` | 延续当前 refresh token 绑定的空间 |
| `GET /users/me` | 从 access token 推导,与 token 一致 |

### 真实响应示例

`GET /api/v1/users/me`(已切到某空间):

```json
{
  "id": "ca80cce3-cf63-495a-aa96-2f36c403a547",
  "username": "cap66f5c8",
  "nickname": "样例用户",
  "created_at": "2026-09-16T14:44:38.913688Z",
  "current_space_id": "4f00ba64-31cb-4063-a907-8aa7ad062840",
  "last_login_at": "2026-09-16T14:44:39.240117Z",
  "last_login_ip": "testclient",
  "avatar_url": null
}
```

### 前端要点

1. **F5 恢复**:`AppLayout` 挂载时调 `GET /users/me`,用返回的 `current_space_id`
   作为当前空间;为 `null` 时跳空间选择/工作台;
2. **切空间**(`/auth/switch-space`)响应是完整 `AuthResponse`,其中 `current_space_id`
   即新空间 —— 用响应整体替换本地状态即可,无需额外推断;
3. ⚠️ `/auth/switch-space` 的 body **必须带 `refresh_token`**(一次性轮换):

```json
{ "space_id": "4f00ba64-...", "refresh_token": "<本地存的 refresh_token>" }
```

4. 该值与 `spaces[]` 里的角色配合使用:空间相关按钮仍按 `spaces[]` 中该空间的 `role`
   渲染(见 `m1-接口说明.md` 角色矩阵)。

## 3. 个人中心

### 3.1 上次登录(缺口 #9)

`UserOut.last_login_at` / `last_login_ip`:

- 语义是"最近一次**成功**登录"(注册即登录,所以注册后立即查也非空);
- **失败登录不改写**这两个字段(失败次数由审计 `auth.login_failed` 承载);
- 前端可把原来基于 `created_at` 的"加入天数"替换/补充为"上次登录时间"。

⚠️ **IP 取值边界(重要)**:`last_login_ip` 目前取**直连客户端地址**,
尚未解析 `X-Forwarded-For`(这是设计文档登记的 Go-Live 翻转项 #8,
需要配置可信代理网段后才开启,以防伪造 IP)。所以:

- 本机/内网直连访问:显示真实客户端 IP,可正常展示;
- **若前面挂了 Nginx/网关**:该字段会显示代理的 IP,而非用户真实 IP。

前端如需展示"上次登录 IP",建议按此实际情况给出中性文案(如"上次登录来源"),
避免让用户困惑。后端开启可信代理解析后行为会变正确,届时不需要前端改动。

### 3.2 头像(缺口 #6)

| 方法 | 路径 | 说明 |
|---|---|---|
| `POST` | `/api/v1/users/me/avatar` | multipart,字段名 `file`;返回更新后的 `UserOut` |
| `GET` | `/api/v1/users/me/avatar` | 返回图片字节(带 `Content-Type`) |
| `DELETE` | `/api/v1/users/me/avatar` | 204,清空头像 |

约束:

- 格式 **PNG / JPEG / WEBP**;大小默认 **2MB**(环境变量 `APP_AVATAR_MAX_MB` 可调);
- 后端按**内容真实解码**校验,不信任文件名 —— 把任意字节改名成 `.png` 也会被拒;
- 单边像素上限 4096(防解压炸弹)。

`UserOut.avatar_url` 语义:有头像时为 `"/api/v1/users/me/avatar"`,无头像为 `null`。

> ⚠️ **最容易踩的坑**:读取接口需要 `Authorization` 头,**不能直接写进 `<img src>`**
> (浏览器发 `<img>` 请求不会带 axios 头)。正确做法是取 blob 渲染:

```ts
// 组件内
const avatarObjectUrl = ref<string | null>(null)

async function loadAvatar() {
  if (!authStore.user?.avatar_url) return
  const blob = await api.get('/users/me/avatar', { responseType: 'blob' })
  avatarObjectUrl.value = URL.createObjectURL(blob)
}

onUnmounted(() => {
  // 必须回收,否则内存泄漏(每换一次头像泄漏一个对象 URL)
  if (avatarObjectUrl.value) URL.revokeObjectURL(avatarObjectUrl.value)
})
```

上传用 `FormData`,并让 axios 自行设置 `Content-Type`(不要手写 multipart 边界):

```ts
const fd = new FormData()
fd.append('file', file)            // file 来自 el-upload 的 raw
await api.post('/users/me/avatar', fd)
// 上传成功后重新拉取 /users/me 或直接用响应里的 avatar_url 重建预览
```

错误处理:

- `415 UNSUPPORTED_FORMAT`:非图片或格式不支持 → 提示"请上传 PNG/JPEG/WEBP 图片";
- `413 FILE_TOO_LARGE`:超大小或像素超标 → 提示上限。

## 4. 审计日志增强

接口:`GET /api/v1/spaces/{space_id}/audit-logs`,**Admin(30)+** 可读。

### 4.1 筛选(缺口 #1)

新增查询参数,可自由组合:

| 参数 | 说明 |
|---|---|
| `action` | 按动作类型精确匹配;**非法值返回 422**(不是静默返回空) |
| `actor_id` | 按操作人 UUID 筛选 |
| `since` | 起始时间,ISO8601,**闭区间** |
| `until` | 结束时间,ISO8601,**闭区间** |
| `limit` / `offset` | 分页(原有);`total` 是**筛选后**的总数 |

```bash
GET /api/v1/spaces/{sid}/audit-logs?action=space.updated&since=2026-09-01T00:00:00Z&limit=50
```

前端要点:

1. **动作类型下拉不要手写枚举**:`openapi.json` 的 `AuditAction` schema 里有完整值列表
   (17 个,含 `access.denied`),从契约生成,避免后端加动作后前端漏项;
2. **时间范围两端都是闭区间** —— 用户选"到 9 月 30 日"时,当天 23:59 的记录不会漏。
   提示:日期控件通常给的是当天 00:00,若要"包含整天",前端应把 `until` 设为
   所选日期的 `23:59:59.999`;
3. `total` 随筛选变化,分页组件要基于它重算。

### 4.2 结果字段(缺口 #3)

响应项新增 `result`,取值 `"success"` / `"denied"`:

- 历史数据(本次变更前写入的)全部为 `"success"`,所以**老记录不会显示成异常**;
- `"denied"` 表示"有操作意图但被权限/认证拦下",此时:
  - `action` 恒为 `"access.denied"`;
  - `detail` 含原始 `method` / `path` / `code` / `message`。

真实被拒记录示例(某个 Editor 试图改空间名被 403):

```json
{
  "id": "95af6dae-43f4-46cf-b405-31c67836f992",
  "actor_id": "9234386d-0d7c-4385-938d-cc2213c7d5d9",
  "actor_name": "O",
  "action": "access.denied",
  "target": "PATCH /api/v1/spaces/76c6d2bb-2ba9-4ede-aaba-18d5d9af1600",
  "result": "denied",
  "detail": {
    "code": "FORBIDDEN",
    "path": "/api/v1/spaces/76c6d2bb-2ba9-4ede-aaba-18d5d9af1600",
    "method": "PATCH",
    "message": "权限不足"
  },
  "ip": "testclient",
  "created_at": "2026-09-16T14:44:50.092902Z"
}
```

前端可直接用 `result` 渲染成功/拒绝圆点,不必从 `detail` 里猜。

> 说明:`denied` **只记录 403 越权** 以及登录/注册接口的 401 失败。
> 普通的 401(未登录、token 过期)不落审计 —— 否则 token 轮换会把审计表刷成噪声。

### 4.3 操作人昵称(缺口 #4)

响应项新增 `actor_name`(操作人昵称冗余):

- 原来前端要自己用 `GET /members` 建 `actor_id → 昵称` 映射,操作人已退出空间时还会
  退化成短 UUID;现在直接读 `actor_name` 即可;
- 操作人不存在(账号已删除)时为 `null`,前端兜底显示短 UUID 或"已注销用户"。

## 5. 空间级检索参数(缺口 #5)

`SpaceOut.retrieval_params` 暴露,且 `PATCH /spaces/{id}` 可修改(**Admin+**)。

真实 `SpaceOut`(新建空间的默认值):

```json
{
  "id": "4f00ba64-31cb-4063-a907-8aa7ad062840",
  "name": "样例空间",
  "description": "d",
  "role": 40,
  "retrieval_params": {
    "rrf_k": 60,
    "vector_weight": 0.7,
    "fulltext_weight": 0.3,
    "min_score": 0.3,
    "default_top_k": 6
  },
  "created_at": "2026-09-16T14:44:39.310290Z"
}
```

### 各参数含义

| 参数 | 范围 | 含义 |
|---|---|---|
| `rrf_k` | 1–1000 | RRF 融合的平滑常数(设计文档基准 60) |
| `vector_weight` | 0–1 | 向量路权重 |
| `fulltext_weight` | 0–1 | 全文路权重 |
| `min_score` | 0–1 | **向量路最小余弦相似度**;低于它的候选直接丢弃 |
| `default_top_k` | 1–50 | 问答/检索**未显式传** `top_k` 时的取值 |

> ✅ 这些参数**真实驱动检索**,不是仅存储的配置:
> `min_score` 会过滤掉低相似候选(`min_score` 调高 → 召回更少但更准;
> 调高到接近 1 可能召回为空,问答会走"知识库无相关内容"分支);
> `default_top_k` 决定不传 `top_k` 时的返回条数。改完**立即生效,无需重建索引**。

### 校验规则(前端表单需对齐)

- 各字段取值范围见上表,越界 422;
- **`vector_weight + fulltext_weight` 之和不得超过 1**,否则 422。

真实 422 响应(权重和 1.8):

```json
{
  "success": false,
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "请求参数不合法",
    "details": [{
      "type": "value_error",
      "loc": ["body", "retrieval_params"],
      "msg": "Value error, vector_weight 与 fulltext_weight 之和不能超过 1",
      "input": { "vector_weight": 0.9, "fulltext_weight": 0.9 },
      "ctx": { "error": "vector_weight 与 fulltext_weight 之和不能超过 1" }
    }]
  }
}
```

前端建议:表单里做同样的"权重和 ≤ 1"校验,并给出可读提示;或提供一个
"向量/全文权重"联动滑块(两者此消彼长),从交互上避免非法组合。

其余既有规则不变,但有两点**字段语义不同,容易踩**:

| 字段 | 省略时 |
|---|---|
| `name` | **必填**,省略 → 422 |
| `description` | 有默认值 `""`,**省略会被重置为空字符串**(不是"保持不变") |
| `retrieval_params` | 省略 = **不改动**原参数(与上两者不同) |

所以前端提交检索参数时,应把当前表单里的 `name`/`description` **一并带上**;
只想改检索参数却漏传 `description`,会把空间描述清空。

## 6. 本次涉及的错误码

| 场景 | HTTP | `error.code` |
|---|---|---|
| 头像格式不支持 / 伪装扩展名 | 415 | `UNSUPPORTED_FORMAT` |
| 头像超大小或像素超标 | 413 | `FILE_TOO_LARGE` |
| 检索参数越界 / 权重和 > 1 / 非法 `action` | 422 | `VALIDATION_ERROR` |
| 非成员访问空间审计 | 404 | `SPACE_NOT_FOUND` |
| 角色不足(如 Editor 改空间) | 403 | `FORBIDDEN` |
| 未带 token 读头像 | 401 | `AUTH_REQUIRED` |

统一响应壳不变:`{"success": false, "error": {"code", "message", "details"}}`。

## 7. 对接自检清单

1. 登录/注册后 `current_space_id` 为 `null` → 引导选择空间;
2. 切空间后 token、`spaces[]`、`current_space_id` 整体更新;F5 后活动空间保持;
3. `/auth/switch-space` 请求带了 `refresh_token`,且成功后覆盖本地 refresh token;
4. 个人中心显示"上次登录",头像上传/替换/删除都通;头像经 blob 渲染且已
   `revokeObjectURL`;
5. 审计页筛选(动作/操作人/时间)可用;`total` 随筛选变化;结果列区分成功/拒绝;
6. 空间设置页检索参数表单可读可改;权重和 >1 时前端先拦、后端也兜底;
7. 全局搜索确认已对接页面无假数据(与本轮无关,但保持约定)。
