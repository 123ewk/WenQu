## 1. §11.7 核心口径核对:全部属实

事件顺序 `meta→tool_call→tool_result→citations→delta→done`、`seq` 单调、`output` ≤2000 字截断、
`ok:false` 循环继续、agent 模式空 `citations` 正常路径、`agent_steps` 字段与契约一致、
迁移 0011、开关默认关字节级兼容 —— 与后端交付(`510ddcc`…`534f60c`)及集成测试逐条一致,无异议。

契约基线核对(本轮实测):`openapi.json` 仍为 **34 路径 / 50 方法**;审计接口**只有**
`GET /spaces/{space_id}/audit-logs`。前端文档提到的 `audit-records` 与 `prompts` 字段在当前
后端源码与全部 `docs/api/*.md` 中 grep **零命中** —— 那是更早旧提法,现状与 v2.4 登记一致,无需处理。

## 2. 观察 1(模型选择器不持久化):裁决 = 产品决定,登记触发式 OPT-24

后端语义确认:契约**没有**"用户默认模型"字段,`/ask` 不传 `model_id` 时取服务端默认模型,
这一语义 V1 内不变。是否给用户配"个人默认模型"属产品决定,已登记进优化台账触发式区
(**OPT-24**,`docs/优化台账.md` §2):动手时会是 `UserOut` 加法式增字段 + 设置接口,
**先出契约变更说明再实现**。在此之前前端维持"选择器组件本地状态、F5 复位",不需改动。

## 3. 观察 2(F5 后活动空间回退丢失):后端语义不变,修复在前端

后端裁决:`current_space_id = null` 的语义就是"**用户从未主动选过空间**"。登录/注册时后端
**不会**把"第一个空间"写进去 —— 前端内存回退是展示便利,不是用户选择,后端不代为持久化。

因此这是前端侧缺陷(L0 既有,非 OPT-10 引入),修法二选一:

- **推荐**:F5 `bootstrap` 发现 `current_space_id` 为 null 且 spaces 非空时,**静默调一次
  `POST /auth/switch-space`**(回包含新双令牌与 user,走既有 `applyAuth` 整体替换链路即可)。
  好处:与手动切空间语义统一、服务端落盘、跨设备一致。注意 refresh token 一次性轮换已由该链路覆盖;
- 次选:仅把回退值落盘到本地(不动服务端)。实现更轻,但 `GET /users/me` 的
  `current_space_id` 仍为 null,换浏览器/设备会复现,属半修。

后端接口层面无需任何配合改动。修复后请把 v2.4 §11.7 该条状态更新为"已修 + 提交号"。
