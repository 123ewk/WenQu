## 一、这次新增了什么(前端可以开工的部分)

### 1. API Key 全套接口 —— 页面 07 从"占位空态"变为可对接 ⭐ 本次最大增量

| 端点 | 说明 |
|---|---|
| `GET /api/v1/spaces/{space_id}/api-keys` | 列表(含已吊销),Viewer+ |
| `POST /api/v1/spaces/{space_id}/api-keys` | 创建,**完整明文 Key 只在这次响应里出现一次** |
| `DELETE /api/v1/spaces/{space_id}/api-keys/{key_id}` | 吊销(幂等 204),Editor+ |

- 能力只有两个值,与原型页 07 的两个勾选项一一对应:
  `chat` =「对话检索」(允许调 /ask 与 /search);`documents` =「文档管理」。
- `kb_ids` 空数组 = 「全部知识库」;非空 = 只能碰这些库。
- **程序方怎么用 Key**:请求头带 `X-API-Key: sk-live-...`(不是 Bearer)。
  Key 冒充不了人:用 Key 访问用户资料、成员管理等接口一律被拒。
- 新错误码(都走统一错误壳,前端按 code 分支渲染):
  - `401 API_KEY_INVALID` —— Key 无效/已吊销,重试无用;
  - `403 API_KEY_CAPABILITY_DENIED` —— Key 没这个能力;
  - `403 API_KEY_SCOPE_DENIED` —— 请求的知识库在 Key 范围外。
- 逐字段契约、页面检查单:**见 `docs/api/m3-api-keys-接口说明.md`(必读)**。

### 2. 对话页(SSE)两个向后兼容的小变化

- **心跳帧**:流里会出现 `: ping` 注释行(生成等待期约 15 秒一条)。
  **前端解析时跳过所有不以 `data: ` 开头的行即可**,现有解析逻辑大概率不用改;
  它的作用是防 nginx 这类代理把"安静"的流掐断。
- **断线不再丢答案**:以前生成中途断线,重新拉历史只剩提问;现在已生成的部分答案
  会存成一条 assistant 消息,重拉 `GET /conversations/{cid}/messages` 就能看到
  (可能不完整,但它是真实生成内容)。仍然**没有续流**,断线恢复逻辑不变。

### 3. 审计日志页(08):新增 3 个动作值

`user.updated`(改昵称)、`user.avatar_uploaded`、`user.avatar_deleted`。
筛选下拉里的选项随之多 3 个;旧动作值不变,完全向后兼容。

### 4. 个人中心(09):一个小行为修正

`PATCH /users/me` 现在会校验昵称**非空**(空白昵称返回 `422`),并且这一步会进审计。
前端如果有"清空昵称再提交"的交互,现在会被 422 挡住,属预期行为。

### 5. 前端无需改动、但值得知道

- 新增统一错误码 `CREDENTIAL_KEY_MISSING`(503)/`CREDENTIAL_DECRYPT_FAILED`(500),
  正常使用不会遇到,不要求渲染。
- 契约测试现在有 CI 门禁:任何新端点/新错误码不上测试清单就合不进来 ——
  **以后 `openapi.json` 里出现的每个端点都是"过了门禁"的**,可以放心当作对接依据。
