# OPT-47 设计实现文档：产品导览（登录后的 8 步自动带看）

状态：已交付，本地真机跑通（`make demo-run ARGS="--tour"` 7 步全过）。第 8 步（Token 用量）与两处高亮修正在
2026-09-26 人工点验后补上，**尚未重跑脚本驱动**（见 §7 备注）。生产未发布——它在前端分支上，要随下一次发版上去。

## 1. 背景与目标

OPT-46 的自动演示脚本（`demo_run.py`）是**准备环境**用的：建空间、建档位、发 Key、上传文档，跑一次就够。
面试现场要的是另一件事：讲解人把浏览器打开、把地址给面试官，**面试官自己点两下就能看完整个系统怎么用**——
他不会去读 README，也不会照着脚本敲命令。

所以导览做在产品里，不做在脚本里：脚本注入的高亮层只有我那台电脑跑着脚本时才存在。

## 2. 需求边界（已拍板决策）

| 决策 | 内容 |
|---|---|
| 落地位置 | 前端（`web/src/components/tour/` + `stores/tour.ts`），不是脚本 |
| 触发 | 仅演示账号登录成功后弹知情窗，点「开始导览」才走；点「我自己看」直接进系统 |
| 步骤 | 8 步：空间 → 模型配置 → 权限档位 → 知识库 → 分块预览 → 提问 → Token 用量 → 收尾 |
| 模型配置那一步 | **只展示不填**：现场填厂商 Key 会把注意力带偏，还会让明文闪过输入框 |
| 提问那一步 | 3 条问题，一条链路一个点（整体链路 / 分块参数 / 嵌入维度权衡） |
| 是否锁页面 | 不锁。遮罩与卡片都不吃点击，随时可跳过、可自己点侧栏 |

## 3. 与现状的区别、能带来什么、代价

- **与现状的区别**：OPT-46 的脚本是"我演给你看"，导览是"它自己会演"。两者共用同一批页面钩子，但导览不建任何数据。
- **效果**：给一个陌生地址 + 演示账号，30 秒内页面自己开始带看，讲解人只负责说话。
- **代价**：前端多了 3 个文件、7 处 `data-tour` 属性；提问那一步会真的产生 3 条会话记录（演示空间，无所谓）；
  页面结构改了要同步锚点——但锚点找不到时卡片会居中并如实提示，**不会卡住流程**。

## 4. 实现拆解

- `components/tour/steps.ts`：步骤表（标题、大白话正文、路由、锚点、闸门）。分块那一步的路由是**函数**，
  运行时查演示库 → 挑一篇**最大**的已完成文档（`size_bytes`）。注意这条挑法**不解决"列表看着空"**：
  演示库 23 篇实测每篇只切出 1~3 块（素材都是 1.4~2.2KB 的短笔记），所以高亮框必须连详情栏一起框（见 §5 坑 4）。
  文案里的 `{docs}` / `{questions}` 由 `TourOverlay.fmt()` 换成真实数字，种子数据改了导览不会还在报旧数。
- `stores/tour.ts`：状态机（`consentPending / running / index / askQueue / askDone`）。
  `enter(i)` 先解析并跳到路由，再在需要闸门的步骤上 `startAsking()`。
- `TourOverlay.vue`：知情弹窗 + 高亮框（`.hole` 用超大 `box-shadow` 挖洞）+ 卡片。
  卡片优先放高亮框下方，放不下翻到上方；上下都放不下（整屏级高亮）时贴视口底部。
- 触发点：`LoginView.onLogin` 成功后，仅当 `demo.enabled && 用户名==演示账号` 时 `tour.armConsent()`。
- 锚点：`space-switcher`、`tour-models`、`tour-groups`、`tour-kb`、`tour-chunks`（分块抽屉的"列表+详情"整块）、
  `tour-chat`（对话输入框）、`tour-usage`（Token 用量页整块）。
- 提问：`ChatView` 监听 `tour.askQueue`，**复用页面自己的 `onSend()`**，答完一条 `reportAskDone()` 一次。

## 5. 四个真机才暴露的坑（都改过代码或改过断言，别改回去）

1. **自动提问会静默打空**。导览翻页的瞬间 `ChatView` 刚挂载，模型清单还在路上，`selectedModelId` 是空串；
   这时调 `onSend()` 会被它自己的前置校验挡回去（直接 `return`，连用户气泡都不落），
   而循环照样 `reportAskDone()`——结果是**一条没问，进度却走到 3/3**。第一次彩排实测：0 条回答、13 秒"完成"。
   修法：发之前 `waitSendable()` 等页面真能发问；等不到就 `reportAskSkipped(原因)`，把原因写在卡片上并放开这一步。
   宁可少演一步，不能假演一步。
2. **锚点重试窗口太短**。权限档位页在 `loading` 期间整张表不在 DOM 上，原来 8×150ms（约 1.2s）等不到，
   脚本驱动时这一步稳定掉进"锚点没命中"兜底。放宽到 20×200ms（约 4s）。
   顺带在卡片上加 `data-step`：外部驱动由此认出"哪一步有提问闸门"，不必在前端之外再抄一份步骤清单。
3. **验收弹窗"关没关"只能判可见性**。`el-dialog` 关掉后节点仍留在 DOM 里（`count()` 还是 1），
   按"元素不存在"断言会误判成 bug。要么判 `visible`，要么加 `destroy-on-close`。
4. **高亮框要框"有内容的那一块"，而且要躲开卡片**（人工点验时发现的，脚本驱动看不出来）。第五步原来只框
   `.chunk-list`（分块抽屉左 40%），实测框是 384×1093；而演示文档每篇只切出 1~3 块，框里九成是白的。
   叠加第二条：卡片"放不下就贴顶"正好落在那 2 个分块上，把它们整个盖住 —— 用户看到的就是一个空白框。
   修法：锚点上移到 `.drawer-body`（列表 + 详情整块，实测 960×1134，占视口 75%），卡片在上下都放不下时贴视口底部。
   教训：**headless 驱动只能证明"流程走通了"，证明不了"画面好看"**；导览这类东西必须有人拿眼睛过一遍。

## 6. 怎么跑

```bash
# 本地（后端 :8000 + 前端 :5173 + 演示数据已 make demo-seed）
cd server && APP_DEMO_PASSWORD=*** uv run --with "playwright==1.60.0" python scripts/demo_run.py --tour
# 生产：同一份脚本换地址
WENQU_BASE_URL=http://106.53.41.116 APP_DEMO_PASSWORD=*** ... scripts/demo_run.py --tour
```

人自己用：登录页填演示账号 → 登录 → 弹知情窗 → 点「开始导览」。不需要任何脚本。

## 8. 明确不做（及理由）

- **不做多路径导览**（比如再演一遍 Agent 模式）：一条线讲清"要准备什么 + 一次真实问答"就够，选项越多讲解越像配置向导。
- **不在导览里建/改数据**：只读 + 提问。建空间那套已经在 OPT-46 脚本里，现场再建一个空空间只会留下垃圾。
- **不做引导遮罩锁屏**：锁了就没法回答"我能自己点点看吗"。
- **不做 i18n / 步骤可配置**：这是演示用的东西，配置化是凭空加抽象。
