# OPT-46 设计实现文档：演示模式（一键体验 + 自动演示脚本）

> 状态：**已交付（后端 + 前端 + 脚本），待生产真机验证**。负责人：后端 + 前端（本功能明确豁免"只做后端"的范围限制）。
> 迁移：**无**（不新增表、不加列，演示身份全部来自配置）。

## 1. 背景与目标

面试/讲解时要向别人展示这条链路（数据从哪来、怎么被问到），手工点一遍既慢又容易漏步骤，也没法证明"一个新用户第一次进来真的能跑通"。

目标三件事：
1. **准备料**：一个能直接登录的演示账号 + 一个已经塞好文档的知识库，观众不用等入库。
2. **入口**：登录页上有一个"一键体验"提示，告诉观众该点什么、密码在哪。
3. **自动走一遍**：外部脚本驱动**真浏览器**（不是接口打点），按新用户路径自动点：登录 → 建空间 → 建权限档位 → 签发 API Key → 看知识库 → 按预写问题自动提问，并把每一步截图存盘。

## 2. 需求边界（已拍板决策）

| # | 决策点 | 结论 |
|---|--------|------|
| D1 | 演示路径 | **新用户真实路径**：chat 落地页 → 创建空间 → 创建权限档位与 API Key → 展示知识库 → 自动提问 |
| D2 | 模型配置 | **不在演示里配**：种子账号直接用已经配好的模型（配模型要厂商 Key，不适合当着观众填） |
| D3 | 知识库素材 | **仓库自带 22 篇自写文档**（`demo/docs/`，主题是大模型应用工程；实测每篇 573–793 个非空白字符、平均 693）+ `demo/questions.json` 20 条预写问题。注：口头要求是"每篇约 400 字"，实际按"要能撑起一段有逻辑的论述"写到了 700 字左右 —— 要压回 400 字得重写，尚未拍板 |
| D4 | 数据怎么来 | **混合：预录为主 + 一个真跑入口**。22 篇提前种好（向量化要几分钟，不能让观众等）；`--live` 时现场再上传 1 篇（`demo/现场入库演示稿.md`）并等它真的走完解析→分块→向量化→检索→回答 |
| D5 | 账号与开关 | **`APP_DEMO_MODE` 开关 + 种子账号**（不引入独立"游客"体系，复用现有注册/登录/RBAC） |
| D6 | 交付面 | **后端 + 前端 + 脚本都做** |
| D7 | 演示场地 | **生产服务器**（106.53.41.116），要让面试官在自己电脑上打开就能看 |

## 3. 与现状的区别、效果、代价（大白话）

- **区别**：以前"演示"= 手工点，或者写一堆假数据脚本直接往库里塞。现在数据是经**真接口**灌进去的（注册→建空间→上传→入库 worker→向量化），演示脚本点的是**真浏览器**，所以演示跑绿 = 这条链路真的通。
- **效果**：一条命令出截图（默认 `-n 6` 是 13 张：7 个流程步 + 每条问题 1 张）+ 命中率统计；投屏时不需要讲解人记住点哪里；换人讲解也不会漏步骤。
- **代价 / 风险（会不会影响现有运行）**：
  1. **开关关着时零影响**：`APP_DEMO_MODE=0`（默认）时 `/demo/status` 只回 `enabled=false`，其余字段空，前端什么都不显示，不新增表、不改任何既有链路。
  2. **多一个免登录端点**：它是公开可读的，能让人在没登录时就知道"这个站点开了演示、演示账号叫什么名、库里有几篇文档"。生产开这个开关就是把这几样信息公开 —— 所以演示密码必须是一个**只用在这里**的密码（不复用其它账号），且用完可以关掉开关。
  3. **演示账号是真人账号**：它能看到自己那个空间的成员列表，如果被别人登录进去改了什么，重跑 `make demo-seed` 是幂等的（按名字复用，不会重复建）。
  4. **截图里有新签发的 API Key 明文**：脚本故意不打印也不写盘 Key 值，但演示时要给观众看"明文只出现这一次"，所以那张截图（`demo-out/`，已进 `.gitignore`）里带着明文 Key。**处置**：这把 Key 名字带时间戳、只为演示签发，讲完吊销或直接不管（它只有演示空间的范围）；对外分享截图前先删这张图。
  5. **playwright 不进依赖锁文件**：CI 永远不跑演示，把它塞进 `pyproject` 只会拖慢每次 CI 安装。用 `uv run --with` 按需拉，版本钉死（见 §6）。

## 4. 配置项（`server/src/app/core/config.py`）

| 环境变量 | 默认 | 说明 |
|---|---|---|
| `APP_DEMO_MODE` | `0` | 总开关。关时状态接口只回 `enabled=false` |
| `APP_DEMO_USERNAME` | `demo` | 种子账号用户名（注册时占用，别人注册不到这个名字） |
| `APP_DEMO_PASSWORD` | 空 | 种子账号密码，**至少 8 位**；接口永不返回它，只有两个脚本从环境变量读 |
| `APP_DEMO_SPACE_NAME` | `演示空间` | 种子空间名。改名 = 换一套演示数据（旧数据不会被 `--purge` 误删） |
| `APP_DEMO_KB_NAME` | `大模型应用工程知识库` | 种子知识库名 |

## 5. 实现拆解

### 5.1 后端：`GET /api/v1/demo/status`（免登录）

`server/src/app/api/routes/demo.py`。返回 `enabled / username / space_name / kb_name / document_total / document_ready / ready`。

- **为什么单独一个接口**：脚本要在"还没登录"时就知道演示入口在不在、数据好了没，这三件事用已登录接口都问不到。
- **`ready` 用最保守的判据**：演示空间里 `completed > 0` 且 `completed + failed == total`（一篇都没失败、也没有还在入库的）。半成品知识库宁可不显示入口，也别让观众看到 21/22。
- 身份全部来自配置：**不新增表**，所以没有迁移、没有回滚负担。
- 已登记进 `tests/test_openapi_contract.py::REQUIRED_PATHS`，`docs/api/openapi.json` 已重导。

### 5.2 种子脚本：`server/scripts/seed_demo.py`

经 HTTP 打真接口（默认 `http://127.0.0.1:8000`，可用 `WENQU_BASE_URL` 指到别的机器），依次做：注册/复用 demo 账号 → 建空间 → 建知识库 → 上传 `demo/docs/*.md` → 轮询等到全部 `completed` → 写 3 条跨会话记忆（OPT-45 的记忆接口，让演示一进来就有"记得之前结论"的样子）。

- **幂等口径**：账号按 username 复用（不改密码）、空间/知识库按名字复用、文档按文件名跳过、记忆按正文去重 → 重复跑安全。
- `--dry-run` 只打印计划；`--purge` 只删配置里那个名字的演示空间（账号保留），其它空间一律不碰。
- 前提缺哪个就在哪一步报错并给出可执行的下一步（例如"server 没启动""开关没开""没有可用的 embedding 模型"）。
- **httpx 必须 `trust_env=False`**：本机开着系统代理时，httpx 默认连 `127.0.0.1` 也丢给代理，拿到一个含义不明的 502，把"服务根本没起来"这个真问题盖掉（实测踩过）。

### 5.3 前端：登录页演示入口

`web/src/api/demo.ts` + `web/src/views/login/LoginView.vue`。`onMounted` 调一次 `/demo/status`，调用失败（老服务 404）就当没有演示。

- `enabled=true` 且 `ready=true` → 显示"一键体验"（带空间名与已就绪篇数），点「填入演示账号」把用户名填进登录框（`demo-fill`），密码留空由讲解人输入。
- `enabled=true` 且 `ready=false` → 标题「演示数据未就绪」（`demo-not-ready`）+ 入库进度 `document_ready/document_total` +「需要先在服务端执行 make demo-seed」。
- **密码不走接口，前端拿不到**（见 §5.1 口径）。

### 5.4 自动演示脚本：`server/scripts/demo_run.py`（Playwright）

只用 `data-testid` 定位（前端在演示路径上补齐了钩子），步骤：打开登录页 → 登录 → 新建空间 → 新建权限档位 → 签发 API Key → 展示知识库 →（`--live`：现场上传并入库一份文档）→ 回对话页 → 提问 N 条。

- 每步打印 `[完成]/[失败]` + 耗时，截图写到 `demo-out/`（文件名 `NN-步骤.png`，张数 = 流程步 7 张 + 提问条数；失败时多一张 `failed.png`）。
- **提问全部走页面**（`chat-input` + `chat-send`），不走 `/ask` 接口 —— 否则演示的是脚本，不是产品。
- 每条问题按 `demo/questions.json` 的 `expected`（文档标题主干）对照引用命中情况，跑完打印「提问 X 条，其中命中期望引用 Y 条」。
- 前置 `preflight()` 会把"跑不起来"翻译成人话：没设 `APP_DEMO_PASSWORD` / 服务没这个端点（说明演示模式还没上线）/ 开关没开 / 数据没播种。
- 浏览器启动失败 → 退出码 2，并提示先跑 `make demo-browser`。

### 5.5 Makefile 目标

| 命令 | 作用 |
|---|---|
| `make demo-seed` | 播种演示数据（需服务端 `APP_DEMO_MODE=1`，且 server / worker / parser 都在跑） |
| `make demo-seed-purge` | 清理演示空间（演示账号保留） |
| `make demo-browser` | 装一次演示用浏览器内核（playwright chromium，约 150MB） |
| `make demo-run` | 跑自动演示，可带 `ARGS="-n 5 --headed"` |

## 6. 怎么跑

### 6.1 生产（面试场地，目标形态）

1. 服务器上 `/home/ubuntu/wenqu/.env` 加两行：`APP_DEMO_MODE=1`、`APP_DEMO_PASSWORD=<至少 8 位，只用于此处>`。
2. 走一次正常 CD 发布（手动 `workflow_dispatch` + 版本号复述），让新镜像带上 OPT-46。
3. 从讲解机播种（脚本是 HTTP 的，指过去即可）：
   ```bash
   WENQU_BASE_URL=http://106.53.41.116 APP_DEMO_PASSWORD=... \
     cd server && uv run python scripts/seed_demo.py
   ```
   这一步会真的走 22 篇文档的向量化，要等几分钟；跑完 `/demo/status` 的 `ready` 才为 `true`。
4. 浏览器打开站点应能看到登录页的演示入口；要自动跑：
   ```bash
   make demo-browser
   WENQU_BASE_URL=http://106.53.41.116 make demo-run ARGS="--headed -n 6"
   ```

### 6.2 本地

后端 `make server-run` + `make worker-run` + `make parser-run`，`.env` 里 `APP_DEMO_MODE=1` 与 `APP_DEMO_PASSWORD`，`make web-dev` 起前端（默认 `http://127.0.0.1:5173`，`demo_run.py` 的 `_base_url()` 默认就是它），然后 `make demo-seed && make demo-run`。要打生产镜像那套就 `WENQU_BASE_URL` 指过去。

### 6.3 参数

`-n/--limit`（默认 6 条）、`--headed`（显示窗口，投屏用）、`--no-shots`、`--full-page`、`--timeout-ms`（等元素，默认 30s）、`--answer-timeout`（等单条回答，默认 180s）、`--live`（现场入库）、`--ingest-timeout`（等入库，默认 300s）。

**playwright 版本必须钉死**：每个 playwright 小版本只认对应型号的 chromium 内核（1.60 → build 1223，1.62/1.63 → 1243）。Makefile 里 `PLAYWRIGHT ?= playwright==1.60.0`，想换版本要同时确认内核装得上（`make demo-browser` 的下载会失败，表现为脚本"找不到浏览器"）。

## 8. 明确不做（及理由）

| 项 | 理由 |
|---|---|
| 演示里自动配置模型（填厂商 Key） | 要当着观众填密钥，且失败面大；种子账号直接用已配好的模型（D2） |
| 站点内"播放预录视频"的播放器 | 演示面是真浏览器 + 真站点，预录视频会失去"这是live系统"的说服力；`--live` 那一条就是真跑 |
| 游客临时空间（不落库的隔离沙箱） | 要新增身份体系与迁移，收益只是"少一个演示账号"，不值 |
| 把 playwright 写进 `pyproject` 依赖 | CI 不跑它，进锁文件只会拖慢每次 CI 安装（用 `uv run --with` 按需拉） |
| 演示脚本自动删除它建的空间/档位/Key | 保留才对得上观众："您刚才看到的这些是真的建进去了"；重名时按名字复用，不会滚雪球。真要清另跑 `make demo-seed-purge` |
| 在页面上动态生成 `data-testid`（如按空间名拼） | 中文动态 id 既难维护也没必要，列表项改按文本定位 |
