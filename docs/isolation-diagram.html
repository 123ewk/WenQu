核心思想：空间（Space）即租户边界
所有资源表都冗余带 space_id，检索与管理 SQL 一律按 space_id 过滤；用户必须通过 memberships 成为空间成员（带数值角色）才能访问。两条防线：服务层做成员/角色守卫，仓储层做租户谓词强制。
① 数据模型：一层套一层，全部挂在空间之下
spaces 空间（租户边界）
空间级检索参数可配（RRF k / 向量权重 / top_k），即"配置也按租户隔离"
├─ memberships：user × space → role（Viewer 10 < Editor 20 < Admin 30 < Owner 40，数值比较）
knowledge_bases 知识库 （space_id 外键；(space_id, name) 唯一）
documents 文档 kb_id + space_id 冗余（租户谓词直查、不走 join，基准 04）
chunks 分块 document_id + space_id 冗余（ix_chunks_space 索引）；embedding 向量 + tsv 全文列
├─ conversations / messages：space_id（问答不越空间，引用溯源也带空间）
└─ permission_groups：空间内的权限档位（能力集 + kb_ids 范围）；api_keys 只留 space_id + 归因 + group_id（OPT-41 起 Key 不再自带权限，能力一律来自所绑档位）
② 一次检索请求的守卫链路（retrieval 热路径）
POST /api/v1/spaces/{space_id}/retrieval/search （空间 id 来自 URL 路径，不是前端自选）
▼
① 认证 get_current_actor
JWT → user + sid（令牌绑定的活动空间）；X-API-Key → 以创建者身份行事 + 路由授权表 fail-closed（表外路由直接拒）
▼
② 服务层守卫 _require_member（RetrievalService.search）
非成员 / 空间不存在 → 404「空间不存在」（防枚举，不泄露空间存在性）；角色 < Viewer → 403
▼
③ 仓储层租户谓词（强制，两条路都带）
vector_search：WHERE chunks.space_id = :space_id AND embedding IS NOT NULL
fulltext_search：WHERE chunks.space_id = :space_id AND tsv @@ tsquery
kb_ids 可选：空间内再收窄；跨空间检索 M2 直接拒绝
▼
④ 两路 top-K 候选 → RRF 融合 → 阈值截断 → 带引用返回
返回的 chunk 全部来自本空间，天然满足"检索结果不越租户"
③ 横向的附加隔离措施
对象存储隔离
MinIO key = {space_id}/{kb_id}/{uuid}/{filename}；删 KB 按 {space_id}/{kb_id}/ 前缀清理，无孤儿文件
会话隔离
access token 带 sid（活动空间）；切空间 = 轮换 refresh token（旧对立即作废），切换时同样成员校验（404）
API Key 二次收窄
Key 所绑档位的 KB 范围签发时校验属于本空间；请求 KB 与档位范围求交，空交集 403，绝不静默降级；创建者被移出空间，Key 立即失效
审计留痕
audit_logs 记录 actor + space + action + result；越权尝试记 access.denied，denied 也入审计
