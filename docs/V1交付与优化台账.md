## 1. V1 范围与"完整链路"的定义

**V1 = M1(账号与空间)+ M2(核心 RAG 闭环)后端全链路 + 前端 L0 对接。**

"完整链路跑通"指下面这条链路端到端可用(已由冒烟脚本实测,见 §3):

```
注册/登录 → 建空间(多租户隔离) → 建知识库 → 上传文档
  → [异步] 解析 → 分块 → 向量化 → 索引
  → 混合检索(向量 ∥ 全文,RRF 融合)
  → 流式问答(SSE)→ 答案带引用 → 引用可回溯到原文块
```

**V1 明确不包含**(不影响"链路完整"的判定,属后续优化,见 §4):
Agent 工具调用、父子分块、API Key 程序化接入、SSE 断线续流、多副本、rerank。

## 4. 后续优化台账

> 编号规则:`OPT-xx`。新增优化项统一加在这里(每条必须写清:来源、为什么现在不做、
> 什么条件下必须做、归属里程碑)。**未列入本表或 §11 的工作,视为不在计划内。**

### 4.1 已定里程碑内的项

| # | 优化项 | 来源/理由 | 触发/归属 |
|---|---|---|---|
| OPT-1 | **SSE 断线保存部分答案** | 2026-09-17 实测:断线后库中只剩 user 消息,已生成的部分答案永久丢失(用户看到"问题孤零零挂着") | **M3 顺手做**(低成本、不动契约) |
| OPT-2 | **SSE 心跳帧**(`: ping` 注释行) | 流目前纯静默;前置 nginx 默认 `proxy_read_timeout 60s` 可能掐断慢流 | **M3**;Agent 长任务(分钟级)为硬需求 |
| OPT-3 | **事件日志 + offset 续流**(ADR-3) | 设计已定但**未实现**(无模块/无 resume 路由) | **M4 必达**;多副本时必须切 Redis 后端。实现时需一并验证:断线后上游模型连接是否及时释放(未验证,存在泄漏疑虑) |
| OPT-4 | **父子分块**(检索命子块、返回父块) | 精简档允许延后;会改变引用载荷形态 → 前端引用抽屉需回归 | **M3** |
| OPT-5 | **问答流水线插件链化** | V1 为硬编码直调(留了阶段边界);可能影响 SSE 事件形态 | **M3** |
| OPT-6 | **API Key 程序化接入** | 唯一仍占位的原型页(07);需 `sk-` 前缀 + SHA-256 查找 + 能力级路由授权表(fail-closed)+ KB 范围收窄 | **M3** |
| OPT-7 | **凭据加密完善**(AES-256-GCM 明文列) | `APP_MASTER_KEY` 已预留;API Key 落库前必须先有它 | **M3**(与 OPT-6 同批) |
| OPT-8 | **契约测试扩面 + 错误码注册扫描** | 把"新增错误码必须注册"变成 CI 门禁;当前靠约定与人肉 | **M3** |
| OPT-9 | **审计补全 + 入库各阶段耗时** | 动作分类补齐(40+ 为目标);耗时需逐阶段时间戳(新表/JSONB) | **M3→M4**;前端不显示耗时文案 |
| OPT-10 | **ReAct 运行时 + `search_knowledge` 工具注册表 + 工具输出防护** | 对话页 Agent 工具卡的**真实**数据源;提示注入对策(设计 §8.3) | **M4** |
| OPT-11 | **Go-Live 14 项翻转 + 备份恢复演练 + 冒烟** | 上线门禁 | **M4** |
| OPT-12 | **可信代理解析 X-Forwarded-For** | 当前 `last_login_ip`/审计 `ip` 取直连地址,挂网关时显示代理 IP(前端已用中性文案规避) | **M4**(Go-Live 翻转项 #8) |

### 4.2 触发式(规模或需求到了才做,现在不做)

| # | 项 | 触发条件 |

| OPT-14 | 多副本部署(含事件日志切 Redis、限流走共享存储、worker 并发重算) | 并发超出单机(§11-2/3) |

### 4.3 明确不做(前端不渲染入口)

| 项 | 理由 |
|---|---|
| 审计日志导出 | 产品决定(数据外带风险) |
| 邮箱体系 / SMTP 邀请 | 依赖 SMTP 服务;邀请已改为按注册账号添加 |
| 沙箱 / 代码执行 | 无需求;Agent 仅内置只读工具(§11-7) |
| 网页抓取数据源 | 用户明确暂不需要;引入时 SSRF 统一入口必须先行(§11-8) |
| 分块 `meta.kind` 细分"标题" | 标题已作为面包屑并入分块内容,检索可见 |
| 头像上限写进契约 | FastAPI 无法把运行时配置值写进静态契约(可配项) |

## 5. 后端为前端提供的 L0 能力(契约基线快照)

**认证**:`POST /auth/register|login|refresh|logout|switch-space`
**用户**:`GET|PATCH /users/me`、`POST /users/me/password`、`GET|POST|DELETE /users/me/avatar`
**模型**:`GET /models`
**空间**:`GET|POST /spaces`、`GET|PATCH|DELETE /spaces/{id}`、`POST /spaces/{id}/leave`、`GET /spaces/{id}/ingestion-progress`
**成员**:`GET|POST /spaces/{id}/members`、`PATCH|DELETE /spaces/{id}/members/{user_id}`
**审计**:`GET /spaces/{id}/audit-logs`(支持 `action`/`actor_id`/`since`/`until` 筛选)
**知识库**:`GET|POST|PATCH|DELETE /spaces/{id}/knowledge-bases[/{kb_id}]`(含聚合统计)
**文档**:`GET|POST .../documents`、`GET|DELETE .../documents/{doc_id}`、`POST .../reparse`
**分块**:`GET .../documents/{doc_id}/chunks`、`GET .../chunks/{chunk_id}`、`POST /chunks/preview`
**检索**:`POST /spaces/{id}/retrieval/search`(支持请求级调参)
**会话问答**:`GET|POST /spaces/{id}/conversations`、`PATCH|DELETE .../conversations/{cid}`、`GET .../messages`、`POST /spaces/{id}/ask`(SSE)
**系统**:`GET /health`、`GET /system/info`(根路径,不带 `/api/v1`)

逐字段以 `docs/api/openapi.json` 为准;流程与边界见 `docs/api/` 下四份接口文档。

## 7. 维护规则

- **新增优化项** → 加进 §4,写清来源、延后理由、触发条件、归属里程碑;
- **完成优化项** → 从 §4 移除并在提交信息中写明 `OPT-xx`,必要时在 §2 补模块台账;
- **基准裁剪变化** → 同时更新 §11(那里是基准偏离的完整登记)与 §4.2(触发条件的通俗表述);
- **验收数字变化** → 更新 §3(每次大改动后重跑命令核对,勿手改估算值)。
