# 优化台账(有意延后的事项)

> **这份文档回答一个问题**:哪些是**有意延后**的优化点、为什么现在不做、什么条件下必须做。
>
> **只看优化**:本文是 V1 之后所有"知道该做但决定先不做"事项的登记处。
> **已交付什么、验收状态如何**不看这里,见 **`docs/V1交付台账.md`**。
> 基准裁剪的完整登记见 `docs/架构设计.md` §11(阈值口径的权威来源)。
>
> 最后核对日期:2026-09-18(基线 `main` 提交 `c065407`,含审计动作契约对齐)

---

## 0. 编号与使用规则

- 编号规则:`OPT-xx`,连续编号,不回收已用编号。
- 每条必须写清:**来源/理由**、**为什么现在不做**、**什么条件下必须做**、**归属里程碑**。
- **未列入本表或 `docs/架构设计.md` §11 的工作,视为不在计划内** —— 不做"顺手优化"。
- 判断准入:凡属"产品不需要""引入新部署依赖""等评测数据才准的调参""当前规模用不上",
  一律进 §2 触发式或 §3 明确不做,不进里程碑内。

## 3. 明确不做(前端不渲染入口)

| 项 | 理由 |
|---|---|
| 审计日志导出 | 产品决定(数据外带风险) |
| 邮箱体系 / SMTP 邀请 | 依赖 SMTP 服务;邀请已改为按注册账号添加 |
| 沙箱 / 代码执行 | 无需求;Agent 仅内置只读工具(§11-7) |
| 网页抓取数据源 | 用户明确暂不需要;引入时 SSRF 统一入口必须先行(§11-8) |
| 分块 `meta.kind` 细分"标题" | 标题已作为面包屑并入分块内容,检索可见 |
| 头像上限写进契约 | FastAPI 无法把运行时配置值写进静态契约(可配项) |

## 4. 维护规则(优化侧)

- **新增优化项** → 按 §0 的格式加进 §1 或 §2,写清来源、延后理由、触发条件、归属里程碑;
- **完成优化项** → 从本表移除,提交信息写明 `OPT-xx`,并在 `docs/V1交付台账.md` §2 补模块台账;
- **基准裁剪变化** → 同时更新 `docs/架构设计.md` §11(完整登记)与本表 §2(触发条件的通俗表述);
- **前端不受影响是硬约束** → 会改契约的项先确认前端 L0 已达标,否则推迟(见 §1.1)。
