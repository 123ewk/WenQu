## 1. 事实来源与裁决规则(冲突时怎么判)

优先级:

1. **`docs/api/openapi.json`**(机器契约)——字段名、端点、枚举、必填性以此为准;
2. **后端 `docs/api/*.md`**(`m1-接口说明` / `m2-接口说明` / `契约补充对接说明` / `前端对接文档-*` / `m3-*`)——流程、边界、前端要点;
3. **`docs/design/*.html`** 原型——视觉与交互基准。

裁决规则:

- 冲突时 **契约 > 说明文档 > 原型**;原型中契约不支持的部分**不实现**,记入 §11 缺口台账(不得用假数据补齐);
- 契约与说明文档都可能滞后于实现,**拿不准就以实测为准**,并把实测结果写回 §11(例:说明文档称模型未配置返回 `502`,实测为 `500`,后端随后改成 **503** 并纳入统一错误壳,而说明文档至今仍写 502 —— 以后端源码为准);
- 说明文档的"已闭合"结论**需要复核**,不能直接采信(例:曾把缺口 #8 标为"已由上传接口满足",直到第二轮补 `/ingestion-progress` 才真正闭合);
- 后端侧的权威登记是 **`docs/V1交付台账.md`**(交付、验收基线、失实记录)与 **`docs/优化台账.md`**(延后项,`OPT-xx`)。两者与本文冲突时以台账 + 实测为准;本文 §2 的分层只是这两份台账的**前端视角映射**,不新增台账里没有的承诺;
- ⚠️ **契约也可能落后于源码**:例 `AuditAction` 曾在契约导出 20 值而源码 23 值(`73bd910` 后已一致)。对枚举这类"新增即向后兼容"的内容,**以源码为准并原样展示未映射值**。

### 2.4 L3 —— 后端不提供(前端不渲染入口)

| 项 | 理由 | 前端处理 |
|---|---|---|

| 邮箱体系 / SMTP 邀请 | 依赖 SMTP,邀请已改为按注册账号 | 邀请用账号,不写"邮件链接"文案 |
| 查看他人头像 | 需"按用户 id 取头像"接口(OPT-19 触发式);`MemberOut.avatar_url` 恒为 `/users/me/avatar`,渲染他人会显示成自己(源码 `spaces.py:114`) | 成员列表不渲染他人头像 |
| 入库各阶段耗时 | 可观测性建设(OPT-9 后半) | 不显示"12.4s"类耗时 |
| `meta.kind` 细分"标题" | 标题已作为面包屑并入分块内容 | 分块类型只呈现 段落/表格 |
| 头像上限写进契约 | FastAPI 无法把运行时配置写进静态契约 | 上限值(2MB/单边 4096px)写在前端校验里 |
| 权重和 ≤ 1 的契约级约束 | OpenAPI 表达不了跨字段约束 | 前后端各写一份,文案保持一致 |

**硬约束**:只有 **L0** 允许进入实现;L1/L2 做占位空态,**不得渲染假列表/假数据冒充真实功能**;L3 一律不渲染入口。

### 2.5 流式链路的既知约束(OPT-1 / OPT-2 / OPT-3 已交付)

- **心跳帧**:生成等待期发 `: ping` 注释行;解析时**跳过所有不以 `data: ` 开头的行**即可;
- **失败必发 `error` 且不发 `done`**(`f4a1478`):检索失败带 `code`,检索兜底与模型调用失败只有人话 `message`
  (源码 `server/src/app/application/service/qa.py`)→ **按 code 分支前先判空**,且**不要拿 `done` 当唯一结束信号**;
- **断线续流已交付**:断开连接后后端**宽限 5 秒**继续生成(`APP_STREAM_GRACE_SECONDS` 可配),期间重连取消宽限;
  耗尽无人回来才中止:close 上游 + 部分答案落库 + 流内 `done(partial=true)` 收尾;
  **所有事件载荷带单调 `seq`**(从 1 起,按生成流独立计数)——前端续流的游标;
- **OPT-12 未做**:`last_login_ip` 与审计 `ip` 取直连客户端地址,挂网关时显示代理 IP —— 前端维持中性文案("上次登录来源"),后端修正后前端无需改动。

## 3. 对接流程(固定 5 步,不跳步)

1. **同步契约** —— 以 `docs/api/openapi.json` 为准(当前基线 **33 路径 / 49 方法**);后端重导后随其提交同步;确认目标端点/字段已在契约中(L0 判据);
2. **类型与 API 层** —— 先在 `src/api/types.ts` 与 `src/api/*.ts` 落地类型与函数;**只有 `src/api/` 允许 import axios**;401 刷新链等横切逻辑只能有一处实现;
3. **页面接入** —— 组件只调 API 函数,不直接拼 URL;三态(loading/空/错误)与角色显隐一并做,不留"稍后补";
4. **冒烟** —— 按 §7 的环境基线跑真实链路,不满足"只看端口/只看构建通过";
5. **登记** —— 新发现的缺口写进 §11 缺口台账(含证据:实测响应或源码位置);契约与文档的矛盾也记在这里。

**提交粒度**:一个可验证的小功能一个提交,判断标准是该提交**能否独立说清做了什么、怎么验证**;
文档改动与代码改动宜分开;每次提交前跑 §4 第 6 条的构建检查。合并到 `main` 由前端侧直接快进推送
(`git push origin <branch>:main`),不必为前端单独开长期分支或 PR。

1. **识别影响面**:对比 `openapi.json` 差异 → 受影响的类型、API 函数、页面;

5. **回归**:只回归受影响页面 + §7 冒烟,不做全量重测。

## 7. 环境、启动与冒烟

### 7.1 环境变量与代理

`web/.env.development` 仅一行(无密钥,随仓库分发):

```
VITE_API_BASE_URL=/api/v1
```

后端未配置 CORS,开发环境**必须**走 Vite 代理(`web/vite.config.ts`)。代理键必须写 **`'^/api/'`**
(锚定路径段):写 `'/api'` 前缀匹配会把前端路由 **`/api-keys`** 也代理到后端,直接打开或刷新该页会拿到后端 404 JSON 而非 SPA(踩过的真实坑)。禁止前端直连 `:8000` 跨域。

### 7.2 启动

```bash
make compose-dev-up                       # postgres + minio
make db-migrate                           # 迁移到最新
make parser-run                           # 解析服务
make worker-run                           # 入库 worker(不起则文档永远 pending)
make server-run                           # :8000
cd web && npm run dev                     # :5173,经 Vite 代理
```

- **Windows 端口**:50051 落在系统保留段时,parser 改 `--addr 127.0.0.1:50071`,并以
  `PARSER_GRPC_ADDR=127.0.0.1:50071` 启动 server 与 worker(不必改 `server/.env`);
- **真实 Key**:向量化需 `DASHSCOPE_API_KEY`,问答需 `DEEPSEEK_API_KEY`;未配置时上传进死信、检索/问答返回 503 `MODEL_NOT_CONFIGURED`;
- `uv run` 起的后台进程可能被回收,长驻进程建议直接用 `.venv/Scripts/python.exe` 启动。

### 7.3 冒烟最小路径(对接完成的实测依据)

1. 注册 → 自动登录 → 建空间 → 侧栏出现且角色为 Owner;
2. 建知识库 → 上传文档 → 状态走完 `pending → completed`;
3. 检索测试返回融合分与双路排名;对话页流式出答案且引用角标可打开抽屉;
4. 刷新页面(F5)→ 登录态与活动空间保持,历史会话可恢复;
5. 权限:切到低权限账号 → 管理入口消失,直连受限路由被拦;
6. 改密 → 被踢回登录页(会话已吊销)。

> 6 条已于 2026-09-19 全部实测通过(L0 验收依据)。

## 8. 认证链路与 Token 键名

### 8.1 localStorage 键名

| 键 | 内容 |
|---|---|
| `wenqu_access_token` | 访问令牌(请求拦截器自动附带 `Authorization: Bearer`) |
| `wenqu_refresh_token` | 刷新令牌(**一次性**,每次 refresh/switch-space 后立即用新值覆盖) |
| `wenqu_user` | UserOut JSON(F5 恢复登录态;**`current_space_id` 随此键持久化**,活动空间以契约为准) |
| `wenqu_spaces` | SpaceBriefOut[] JSON(含各空间 role) |
| `wenqu_sidebar_collapsed` | 侧边栏折叠状态 |

> 原独立自管键 `wenqu_current_space_id` 已废弃删除,模块加载时对老用户残留做一次性清理。

### 8.2 认证链路(实现于 `src/api/http.ts` + `src/stores/auth.ts`)

1. 请求拦截器统一附带 Bearer access_token;
2. 收到 401 且 `error.code ∈ {AUTH_REQUIRED, TOKEN_EXPIRED}`(或裸 401)→ 用 refresh_token 调 `/auth/refresh` → 成功后**重放原请求(仅一次)**;
3. **并发 401 防抖**:共享 `refreshAccessToken()` 的 refreshing Promise,多个请求同时过期只刷新一次;
4. refresh_token 一次性:刷新/切空间成功后新值**立刻覆盖**旧存储值;
5. 刷新失败(`REFRESH_TOKEN_INVALID`)→ 清空凭据 → 跳登录页(带 `redirect`);网络错误不清凭据;
6. 切换空间:响应是完整 AuthResponse,前端**整体替换** user/spaces/双令牌;令牌轮换类操作在 Store 内**串行执行**(内部函数不叠加串行,防嵌套死锁);
7. 改密成功(204)→ 后端吊销全部会话 → 清凭据并强制回登录页;
8. `/auth/login|register|refresh|switch-space|logout` 自身的 401(如密码错误)不触发刷新链;
9. **活动空间以契约为准**:登录/注册未选空间为 `null`(前端回退第一个空间);`switch-space` 回包即新空间;F5 由 `GET /users/me` 的 `current_space_id` 覆盖本地初值;
10. F5:路由守卫检查登录态;`AppLayout` 挂载时调 `GET /users/me` + `GET /spaces` 静默校验并刷新。

## 9. 各页面对接要点

### 9.1 流式问答(SSE,02 页,`src/api/chat.ts`)

- 用 `fetch` + `ReadableStream` 读取(**不能用 EventSource**:发不了 POST body 与 Authorization 头);
- 五种事件按 `type` 分派:`meta`(新会话 id,同步路由/侧栏)、`citations`、`delta`(**累加**正文)、`done`(`cited_indexes` 决定抽屉展示哪几条)、`error`(展示错误、停 loading,**HTTP 仍 200**);
- `error` 的 `code` **可选**(§2.5):按 code 分支前判空;**失败路径不发 `done`**,收尾按 `done`/`error`/都没有三种情况处理;
- 错误文案:503 `MODEL_NOT_CONFIGURED` → "联系管理员检查服务端模型密钥";502 `MODEL_CALL_FAILED` → "稍后重试",勿混;
- **断线续流已接入**(OPT-3):事件携带单调 `seq`,组件记录最后收到的 `seq`;流中断且已有 `seq` 时自动调
  `GET .../conversations/{cid}/stream?after=<seq>` 精确补播(服务端按 seq 续,前端无需去重),
  不可续(404 `STREAM_NOT_RESUMABLE`)或续流再失败 → 回退既有收尾(重拉 messages / 提示);
- `done` 可能带 `partial=true`(宽限耗尽中止):正文是已生成的部分答案,消息尾部显示"连接中断,以上为已生成的部分回答"提示;
- 首次提问由后端新建会话:`router.replace` 会触发历史重拉,而失败/中断路径后端**不一定**存助手消息
  (中断且宽限耗尽时会存部分答案)→ 用 `skipReloadId` 对刚流式结束的会话跳过一次重拉;
- 流无声结束(网关掐断/断网):自动续流;失败且有部分正文 → 保留正文 + partial 提示;无正文 → 重拉历史,取不到给可读提示,不得留白;
- 引用角标 `[n]` 打开 380px 抽屉;"查看完整原文"按 `chunk_id` 调单块全文接口(限高滚动,缓存;404 → "原文档已删除");
- 停止生成:`AbortController`;断线恢复逻辑不变(回退重新拉取,不做 resume UI);
- 会话重命名:`title` 1–128 字,成功后就地更新列表项(不整表重拉);重命名后按 `updated_at` 排最前属预期;
- 模型选择器:清单来自 `GET /models`(提交 `id` 字段,`provider` 做分组);默认"默认模型"不传 `model_id`,
  显式选择即生效(后端已修 model_id 语义冲突:检索向量化改取目标 KB 的 `embedding_model`,
  `SearchRequest.model_id` 废弃不再使用)。

### 9.2 上传与入库状态机(03/04 页)

- `POST .../documents` 只负责存文件与入队(`pending`);前端轮询 `GET .../documents`(2s,页面不可见暂停),全部终态后自动停止;
- 状态展示:排队 → 解析 → 分块 → 向量化 → 完成;失败行展开显示**任务侧真实 `error_message`**(可能偏运维向,内部工具直显)+ "重新解析"按钮(Editor+);
- 重新解析:仅终态可调(非终态 409 `DOCUMENT_BUSY`);成功后行回 `pending`,轮询自动恢复;
- 旧版 `.doc/.xls/.ppt` 不支持(415),提示另存为新格式;
- 顶栏浮层(全局):上半是浏览器上传进度(`onUploadProgress`),下半是空间级入库进度
  `GET /spaces/{sid}/ingestion-progress` —— `total_active > 0` 时 2.5s 轮询、归零停止、打开浮层即刷新一次;
  `has_failure` 独立警示(不从 `index_status` 推);失败项点击跳对应知识库详情。

### 9.3 检索测试(04 页 Tab B)

- RRF 融合分(`score` ≈ 0.016 量级,**不是相似度**、不可跨查询比较、别当百分比);
- `vector_rank`/`fulltext_rank` 可为 `null`(单路命中),双路标记判空;
- 请求级调参(仅本次生效,不写回空间配置):`vector_weight`/`fulltext_weight` 成对且和 ≤ 1(前端先拦、后端 422 兜底)、`min_score`、`rrf_k`;调完可核对 `GET /spaces/{id}` 的 `retrieval_params` 未变。

### 9.4 知识库列表与详情(03/04)

- 卡片统计四项 + `index_status` 四态:empty 灰"暂无文档" / processing 蓝点脉冲"索引中" / ready 绿"就绪" / degraded 橙"部分失败";
  优先级 `empty → processing → degraded → ready` 是**后端**判序,前端直接渲染;"有失败"提示用顶栏 `has_failure`;
- `size_bytes` 前端格式化;模型徽章过长时省略模型名、保住维度数字(flex 子项需 `min-width:0`);
- ⋯ 菜单定位:`el-dropdown` 的包装元素是零尺寸 `position:relative`,`absolute` 要加在包装元素上而非内部按钮(踩过的坑)。

### 9.5 分块预览(05 页)

- 列表显示 `tokens`(入库算好,可 null → 回退字符数);`meta.kind` 只有 `text`/`table`,无"标题"类型。

### 9.6 空间管理(06 页)

- 检索参数表单(Admin+):五参数(`rrf_k` 1–1000、两权重 0–1、`min_score` 0–1、`default_top_k` 1–50),权重和 ≤ 1 超限禁用保存;
  **真实驱动检索,保存立即生效,无需重建索引**;
- ⚠️ `PATCH /spaces/{id}` 字段语义:`name` 必填;`description` **省略会被清空**;`retrieval_params` 省略 = 不改动。
  保存检索参数时把当前 name/description 一并提交(防清空描述)。

### 9.7 审计日志(08 页)

- 筛选:`action`(下拉按前缀分组,选项与契约 23 值同源;非法值 422)/`actor_id`(成员下拉;自由文本昵称搜索契约不支持)/`since`/`until`
  (闭区间;日期范围转 UTC ISO,`until` 取次日零点含结束日整天);`total` 为筛选后总数;
- `result` 枚举(`success`/`denied`)直接渲染绿/红点;`actor_name` 直显(null → 短 UUID+"已注销");
- 筛"被拒记录"用 `action=access.denied`(`result` 不是筛选参数)。

### 9.8 个人中心(09 页)

- 头像三端点:读取**必须带 Authorization** → blob + `createObjectURL` + `revokeObjectURL`(变更与卸载双清理);
  上传 FormData(axios 自定边界);前端校验 PNG/JPEG/WEBP、≤2MB、单边 ≤4096px(运行时配置,契约表达不了);415/413 人话提示;
  **只能渲染自己的头像**;
- 上次登录:`last_login_at`/`last_login_ip` 直显,中性文案"来源"(X-Forwarded-For 未开,OPT-12);
- 昵称空白 422(前端先拦);改密成功 → 吊销全部会话 → 清凭据回登录页。

### 9.9 API Key(07 页,M3)

- 列表(含已吊销置灰,Viewer+)/ 创建(Editor+,`plaintext` **仅此一次**)/ 吊销(Editor+,幂等 204);
- 能力两值:`chat`(对话检索)/ `documents`(文档管理);`kb_ids` 空数组 = 全部知识库;
- 新建两步弹窗(表单 → 一次性明文展示);吊销确认写明"立即 401、不可恢复";
- 程序侧用 `X-API-Key` 头(不是 Bearer);错误码:401 `API_KEY_INVALID` / 403 `API_KEY_CAPABILITY_DENIED` / 403 `API_KEY_SCOPE_DENIED`;
- ⚠️ Element Plus 陷阱:能力/KB 多选必须用 `el-checkbox-group`(独立 `el-checkbox` 只收布尔值);
  且 `.el-checkbox-group` 自带 `font-size:0/line-height:0`,**自定义文案放进组内必须重置这两个属性**,否则行盒塌成 0 导致文字重叠。

### 9.10 角色显隐(体验层,后端 403/404 兜底)

角色数值:Viewer=10 / Editor=20 / Admin=30 / Owner=40,来源 `SpaceOut.role` / `spaces[].role`。

| 能力 | 门槛 |
|---|---|
| 查看知识库 / 文档 / 分块 / 检索测试 / API Key 列表 | 任意成员 |
| 新建知识库、改名改描述、上传/删除文档、重新解析、创建/吊销 API Key | Editor(20)+ |
| 删除知识库、邀请成员、改角色、移除成员、空间设置、审计日志 | Admin(30)+ |

`FORBIDDEN` → 提示无权限;`SPACE_NOT_FOUND` → 引导回工作台。
