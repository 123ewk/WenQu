# 对接说明(web 前端 ↔ 后端)

> 本阶段交付:Vue 3 + TypeScript + Element Plus 复刻 `docs/design/` 原型,全量对接 M1(账号体系 + 多空间管理)与 M2(知识库 / 入库 / 检索 / 流式问答);仅 API Key 页占位。接口契约唯一事实来源:`docs/api/openapi.json`。
> M1 细节见 `docs/api/m1-接口说明.md`,M2 的流程与顺序约束见 `docs/api/m2-接口说明.md`。

## 1. 环境变量

`web/.env.development`:

```
VITE_API_BASE_URL=/api/v1
```

后端未配置 CORS,开发环境**必须**走 Vite 代理(`web/vite.config.ts`):`/api → http://localhost:8000`。禁止前端直连跨域。

## 2. 启动方式

```bash
# 依赖与后端(仓库根目录)
make compose-dev-up        # postgres + minio
make db-migrate            # 迁移
make parser-run            # 文档解析服务(:50051),worker 依赖它
make worker-run            # 入库流水线 worker(不起则文档永远停在 pending)
make server-run            # 主服务 http://localhost:8000,/docs 有 Swagger

# 前端
cd web
npm install
npm run dev                # http://localhost:5173
npm run build              # vue-tsc 类型检查 + 构建,必须零错误
```

**Windows 端口提示**:若 50051 落在系统保留段(`netsh interface ipv4 show excludedportrange protocol=tcp` 可查),
启动 parser 时换端口 `cd parser && uv run python -m parser_service.server --addr 127.0.0.1:50071`,
并用环境变量覆盖后端配置(不必改 `server/.env`):

```bash
cd server && PARSER_GRPC_ADDR=127.0.0.1:50071 uv run uvicorn app.main:app --port 8000
cd server && PARSER_GRPC_ADDR=127.0.0.1:50071 uv run python -m app.worker
```

**真实 Key**:向量化需 `DASHSCOPE_API_KEY`,问答需 `DEEPSEEK_API_KEY`;未配置时上传会进死信、问答流回 `error` 事件。

## 3. Token 存储键名(localStorage)

| 键 | 内容 |
|---|---|
| `wenqu_access_token` | 访问令牌(请求拦截器自动附带 `Authorization: Bearer`) |
| `wenqu_refresh_token` | 刷新令牌(**一次性**,每次 refresh/switch-space 后立即用新值覆盖) |
| `wenqu_user` | UserOut JSON(F5 恢复登录态) |
| `wenqu_spaces` | SpaceBriefOut[] JSON(含各空间 role) |
| `wenqu_current_space_id` | ⚠️ **已被契约取代,待移除**:后端已提供 `AuthResponse.current_space_id` / `UserOut.current_space_id`,应以契约值为准并删除此自维护键,否则会出现"前端以为在 A 空间、token 实际在 B"的错位(见 `契约补充对接说明.md` §2 与 `对接缺口清单.md` §2.1) |
| `wenqu_sidebar_collapsed` | 侧边栏折叠状态 |

## 4. 认证链路(实现于 `src/api/http.ts` + `src/stores/auth.ts`)

1. 请求拦截器统一附带 Bearer access_token;
2. 收到 401 且 `error.code ∈ {AUTH_REQUIRED, TOKEN_EXPIRED}`(或裸 401)→ 用 refresh_token 调 `/auth/refresh` → 成功后**重放原请求(仅一次)**;
3. **并发 401 防抖**:共享 `refreshAccessToken()` 的 refreshing Promise,多个请求同时过期只刷新一次,其余挂起等待后重放;
4. refresh_token 一次性:刷新/切空间成功后新值**立刻覆盖**旧存储值;
5. 刷新失败(`REFRESH_TOKEN_INVALID`)→ 清空凭据 → 跳登录页(带 `redirect`);网络错误不清凭据;
6. 切换空间:响应是完整 AuthResponse,前端**整体替换** user/spaces/双令牌;令牌轮换类操作在 Store 内**串行执行**,避免并发使用已作废的 refresh_token(且内部函数不叠加串行,防嵌套死锁);
7. 改密成功(204)→ 后端吊销全部会话 → 前端清凭据并强制回登录页;
8. `/auth/login|register|refresh|switch-space|logout` 自身的 401(如密码错误)不触发刷新链;
9. F5:路由守卫检查登录态;`AppLayout` 挂载时调 `GET /users/me` + `GET /spaces` 静默校验并刷新。

> **活动空间**:后端已提供 `AuthResponse.current_space_id`(登录/注册为 `null`,`switch-space` 后为新空间,`refresh` 延续原绑定)。
> 待接入后应改为以契约值为准;注意 `refresh` 响应也带该值,`session.saveAuth()` 需一并持久化。

## 5. M2 对接要点

### 流式问答(SSE,`src/api/chat.ts`)

- 用 `fetch` + `ReadableStream` 读取(**不能用 EventSource**:它发不了 POST 请求体与 Authorization 头);
- 五种事件按 `type` 分派:`meta`(记录新会话 id 并同步路由/侧栏)、`citations`、`delta`(**累加**正文)、`done`(`cited_indexes` 决定抽屉展示哪几条)、`error`(展示错误、停 loading,**HTTP 仍 200**);
- 校验类错误(401/404/422)发生在流开始前,能正常拿到状态码;流内 401 复用同一套一次性 refresh 轮换后重发一次;
- 引用角标:正文里的 `[n]` 渲染为可点击角标,点击打开 380px 引用抽屉,展示 `excerpt` 与 `filename/breadcrumb/page`(M2 不提供"查看完整原文块"接口,抽屉内容即 excerpt);
- 停止生成:`AbortController` 中断流,已生成内容保留;刷新页面后由 `GET /conversations/{cid}/messages` 恢复历史(assistant 消息自带 citations,角标与抽屉可直接复现)。

### 上传与入库状态机(Tab A)

- `POST .../documents` 只负责**存文件与入队**,返回 `status=pending`;
- 前端轮询 `GET .../documents`(2s,页面不可见时暂停)刷新状态;全部终端态后自动停止轮询;
- 状态展示:排队 → 解析 → 分块 → 向量化 → 完成;`failed` 行可展开查看原因(`error_code=INGEST_FAILED`,文案按接口文档约定);
- 上传按钮走统一 axios 通道(带 401 链),进度用 `onUploadProgress` 反映在顶栏上传浮层;入队后的解析进度在文档列表查看;
- 旧版 `.doc/.xls/.ppt` 不支持(`UNSUPPORTED_FORMAT`),提示另存为新格式。

### 检索测试(Tab B)

- `POST /retrieval/search` 展示 RRF 融合分与 `vector_rank`/`fulltext_rank` 双路命中排名;仅检索当前知识库。

## 6. 角色显隐(体验层,后端 403/404 兜底)

角色数值:Viewer=10 / Editor=20 / Admin=30 / Owner=40,来源 `SpaceOut.role` / `spaces[].role`。

| 能力 | 门槛 |
|---|---|
| 查看知识库 / 文档 / 分块 / 检索测试 | 任意成员 |
| 新建知识库、改名改描述、上传/删除文档 | Editor(20)+ |
| 删除知识库 | Admin(30)+ |
| 邀请成员、改角色、移除成员、空间设置、审计日志 | Admin(30)+ |
| 删除空间 / 转让所有权 | Owner(40) |
| 退出空间 | 任意成员(Owner 不可,先转让或删空间) |

`FORBIDDEN` → 提示无权限;`SPACE_NOT_FOUND` → 引导回工作台。

## 8. 与原型的刻意差异

- Element Plus 组件按设计令牌换肤(主色 #4F6EF2、边框 #E5E7EB、圆角 8/12px、表格行高 44px);
- 原型演示用的"原型状态切换"浮条、假数据列表全部移除;
- 契约不支持的能力未渲染假交互:知识库卡片文档/分块统计、嵌入模型选择与重建索引、**检索测试 Tab 的向量权重/阈值/Rerank**(`SearchRequest` 仍无这些参数,空间级默认参数是另一件事)、文档重新解析、会话重命名。逐条依据见 `对接缺口清单.md`。
