# 对接说明(web 前端 ↔ M1 后端)

> 本阶段交付:Vue 3 + TypeScript + Element Plus 复刻 `docs/design/` 原型,全量对接 M1(账号体系 + 多空间管理);未上线页面一律占位空态。接口契约唯一事实来源:`docs/api/openapi.json`。

## 1. 环境变量

`web/.env.development`:

```
VITE_API_BASE_URL=/api/v1
```

后端未配置 CORS,开发环境**必须**走 Vite 代理(`web/vite.config.ts`):

```
/api → http://localhost:8000
```

禁止在前端直连 `http://localhost:8000` 跨域调用。

## 2. 启动方式

```bash
# 后端(仓库根目录)
make compose-dev-up        # postgres(+minio)
make db-migrate
make server-run            # http://localhost:8000,/docs 有 Swagger

# 前端
cd web
npm install
npm run dev                # http://localhost:5173
npm run build              # vue-tsc 类型检查 + 构建,必须零错误
```

## 3. Token 存储键名(localStorage)

| 键 | 内容 |
|---|---|
| `wenqu_access_token` | 访问令牌(请求拦截器自动附带 `Authorization: Bearer`) |
| `wenqu_refresh_token` | 刷新令牌(**一次性**,每次 `/auth/refresh`、`/auth/switch-space` 后立即用新值覆盖) |
| `wenqu_user` | UserOut JSON(F5 恢复登录态) |
| `wenqu_spaces` | SpaceBriefOut[] JSON(含各空间角色) |
| `wenqu_current_space_id` | 当前活动空间 ID(前端自维护,见缺口清单 #7) |
| `wenqu_sidebar_collapsed` | 侧边栏折叠状态 |

## 4. 认证链路(实现于 `src/api/http.ts` + `src/stores/auth.ts`)

1. 请求拦截器统一附带 Bearer access_token;
2. 收到 401 且 `error.code ∈ {AUTH_REQUIRED, TOKEN_EXPIRED}`(或裸 401)→ 用 refresh_token 调 `/auth/refresh` → 成功后**重放原请求(仅一次)**;
3. **并发 401 防抖**:共享 refreshing Promise,多个请求同时过期只发起一次刷新,其余挂起等待后重放;
4. refresh_token 一次性:刷新/切空间成功后新值**立刻覆盖**旧存储值;
5. 刷新失败(`REFRESH_TOKEN_INVALID`)→ 清空凭据 → 跳登录页(带 `redirect` 参数);网络错误不清凭据;
6. 切换空间:调 `/auth/switch-space`,响应是完整 AuthResponse,前端**整体替换** user/spaces/双令牌;
7. 改密成功(204)→ 后端吊销全部会话 → 前端清凭据并强制回登录页;
8. `/auth/login|register|refresh|switch-space|logout` 自身的 401(如密码错误)不触发刷新链;
9. F5:路由守卫检查 localStorage 登录态;`AppLayout` 挂载时调 `GET /users/me` + `GET /spaces` 静默校验并刷新。

## 5. 角色显隐(体验层,后端 403/404 兜底)

角色数值:Viewer=10 / Editor=20 / Admin=30 / Owner=40,来源 `SpaceOut.role` / `spaces[].role`。

- 空间管理页:所有成员可见;邀请成员、角色下拉、移除仅 Admin+ 渲染;
- 角色下拉只列**严格低于自己**的角色;Owner 额外显示"转让所有权"(role=40,高危二次确认);
- 空间设置 Tab 仅 Admin+;删除空间仅 Owner;退出空间对 Owner 隐藏(接口 403 兜底);
- 审计日志:路由守卫 `meta.adminOnly` + 侧栏入口仅 Admin+ 渲染;
- `FORBIDDEN` → 统一提示"当前角色无权执行此操作";`SPACE_NOT_FOUND` → 引导回工作台。

## 6. 目录结构

```
web/src/
  api/        # http.ts(客户端+401链) session.ts(持久化) auth.ts users.ts spaces.ts types.ts
  stores/     # Pinia:auth.ts(登录态/空间切换/角色)
  router/     # 路由 + 守卫
  layouts/    # AppLayout(侧边栏 240 + 顶栏 56)
  components/ # AppSidebar / CreateSpaceDialog
  views/      # login/ space/ audit/ profile/ placeholder/
  utils/      # roles.ts(角色常量与授权范围) format.ts(时间格式化)
  styles/     # main.css(设计令牌 → Element Plus CSS 变量)
```

## 7. 与原型的刻意差异

- 所有 Element Plus 组件按设计令牌换肤(主色 #4F6EF2、边框 #E5E7EB、圆角 8/12px、表格行高 44px);
- 原型中演示用的"原型状态切换"浮条、假数据列表全部移除;未上线页面见 `对接缺口清单.md`。
