## 二、本轮后端已补齐(前端待接入的具体做法)

### 2.1 当前活动空间(#7)

- `AuthResponse.current_space_id` 与 `UserOut.current_space_id` 已提供;语义:注册/登录未选空间为 `null`,`switch-space` 后为该空间 id,`refresh` 延续原绑定。
- 前端应**改为以契约值为准**,删除自维护的 `localStorage.wenqu_current_space_id`,避免"前端以为在 A 空间、token 实际在 B"的错位。
- 注意 `POST /auth/refresh` 也会带回该值:`session.saveAuth()` 目前只存 user/spaces/双令牌,需一并持久化。
- 角色仍从 `spaces[]` 中该空间的 `role` 读取。

### 2.2 个人中心:上次登录与头像(#9/#6)

- `UserOut.last_login_at` / `last_login_ip`:语义为"最近一次成功登录";失败登录不改写。
- ⚠️ `last_login_ip` 目前取**直连客户端地址**,**尚未解析 `X-Forwarded-For`**(后端 Go-Live 翻转项)。前面挂 Nginx/网关时会显示代理 IP,故 UI 文案用中性表述「上次登录来源」,不写死"IP"。后端开启可信代理解析后前端无需改动。
- 头像:`POST /users/me/avatar`(multipart,字段 `file`,返回 `UserOut`)、`GET /users/me/avatar`(图片字节)、`DELETE /users/me/avatar`(204)。
- **读取必须带 Authorization,不能直接写进 `<img src>`**:取 blob → `URL.createObjectURL`,并在组件卸载时 `URL.revokeObjectURL`(否则每换一次头像泄漏一个对象 URL)。
- 上传用 `FormData`,让 axios 自行设定 multipart 边界。
- 错误:415 `UNSUPPORTED_FORMAT` → "请上传 PNG/JPEG/WEBP 图片";413 `FILE_TOO_LARGE` → 提示上限(默认 2MB)。
- ⚠️ **`UserOut.avatar_url` 是带 `/api/v1` 前缀的服务端路径**(`"/api/v1/users/me/avatar"`),而 http 客户端 baseURL 已是 `/api/v1`,直接交给它拼会得到 `/api/v1/api/v1/...` → 404。应自行取 `'/users/me/avatar'` 或去掉前缀后再用(见 §4.1)。
- 成员列表仍**无法显示头像**:`MemberOut` 没有 `avatar_url` 字段。

### 2.3 空间设置:检索参数(#5)

- `SpaceOut.retrieval_params` = `{rrf_k, vector_weight, fulltext_weight, min_score, default_top_k}`,`PATCH /spaces/{id}`(**Admin+**)可改;参数**真实驱动检索**(`min_score` 过滤候选、`default_top_k` 决定不传 top_k 时的条数),改完立即生效、无需重建索引。
- 表单校验(契约各字段的 `minimum/maximum` 已具备):`rrf_k` 1–1000、三个 0–1、`default_top_k` 1–50;另外**两权重之和 ≤ 1**,越界均 422。
- ⚠️ **`PATCH /spaces/{id}` 字段语义差异**:`name` 必填(`UpdateSpaceRequest.required=['name']`,省略 422);`description` 省略会被**重置为空串**(不是保持不变);`retrieval_params` 省略才是不改动。
  因此只改检索参数时,必须把当前表单的 `name`/`description` 一并带上,否则会清空空间描述。
- 建议交互:向量/全文权重做成联动滑块(此消彼长),从交互上避免非法组合。

### 2.4 审计日志:筛选 / 结果 / 操作人(#1/#3/#4)

- 新增查询参数 `action`(非法值 422)、`actor_id`、`since`、`until`(`limit`/`offset` 原有,`total` 为**筛选后**总数)。
- `since`/`until` 均为**闭区间**;日期控件给的是当天 00:00,若要"包含整天"需把 `until` 设为所选日期的 `23:59:59.999`。
- `AuditLogOut.result`:`"success"` / `"denied"`,可直接渲染成功/拒绝圆点。历史记录全为 `"success"`,老数据不会显示成异常。
- `denied` 仅记录 **403 越权**与登录/注册接口的 401 失败;普通 401(未登录、token 过期)不落审计。被拒记录的 `action` 恒为 `"access.denied"`,细节在 `detail.{method,path,code,message}`。
- `AuditLogOut.actor_name` 为操作人昵称冗余,前端**可弃用**"拉成员列表自建 UUID→昵称映射";为 `null`(账号已删除)时兜底显示短 UUID 或"已注销用户"。

## 三、仍然存在的缺口

### 3.1 #8 顶栏全局上传进度 —— 本轮被误判为已闭合

说明文档 §0 将其标为"✅ 后端在 M2 已提供文档上传接口",这**不成立**:该缺口的含义是"顶栏进度浮层需要一个**跨页面聚合**的入库进度来源"。
M2 的上传接口返回的是入队后的 `status`(`pending`),而后续 `parsing/chunking/embedding` 的推进只能在**每个知识库各自的文档列表**里轮询获得,
没有任何空间级的入库任务/进度查询接口。前端现状:浮层只反映浏览器上传阶段(axios `onUploadProgress`),入队后提示用户去文档列表查看。
—— 若产品需要真正的全局进度,后端需提供空间级入库任务列表(含各任务阶段与失败原因)。
