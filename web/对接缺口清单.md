## 三、本轮新发现的缺口 / 后端缺陷(含证据)

### 3.1 `/ask` 的 `model_id` 语义冲突 —— 后端缺陷,待修 ⚠️

**现象**:对话页显式选择任何对话模型(如 `deepseek/deepseek-chat`)提问 → 必然 503
`MODEL_NOT_CONFIGURED`("模型 ... 不是 embedding 类型")。

**根因**(源码证据):`server/src/app/application/service/qa.py:163` 把 `model_id` 同时传给
`retrieval.search()`(→ `model_client.embed`,第 84 行要求 `kind == "embedding"`)和
`chat_stream()`(要求 chat 类型)。**单一 id 不可能同时满足两个阶段**,任何显式模型都失败。

**前端处理**:选择器默认"默认模型"(**不传 model_id**,行为与后端默认一致,实测全链路可用);
用户显式选择才提交 id —— 后端修复(检索阶段应使用空间 embedding 配置,`model_id` 只驱动回答)
后**前端无需改动即生效**。

### 3.2 损坏图片上传返回 500,契约应为 415 —— 后端小缺陷

损坏 PNG(校验和错)→ PIL `SyntaxError` 未包装 → 500 INTERNAL_ERROR
(源码 `server/src/app/application/service/profile.py:111` `_detect_format` 的 `image.verify()`)。
按契约"非图片或格式不支持"应为 415 `UNSUPPORTED_FORMAT`。前端对 415/500 均有人话兜底,不阻塞。

### 3.3 知识库"换嵌入模型"契约不支持

工单 3.4 提到 04 页换嵌入模型,但 `UpdateKBRequest` 仅 `name/description`
(`CreateKBRequest` 同),无 `embedding_model` 字段。按红线不编造字段,04 页不渲染该入口;
嵌入模型当前由服务端配置。**需后端明确**:是否提供该能力(含重建索引流程),提供时补契约。

### 3.4 `ChunkOut.tokens` 实测均为 null(数据现象)

txt 文档入库后分块的 `tokens` 实测全为 null(批量与单块均如此)。契约允许 null,
前端已做回退(显示字符数)。**建议后端核查**流水线是否漏算 tokens(或仅特定格式计算)。

### 3.5 沿袭未变

- 审计"按昵称搜索"仍只有 `actor_id`(自由文本搜索契约不支持,前端用成员下拉等价实现);
- 他人头像(OPT-19 触发式)、各阶段耗时(OPT-9 后半)、续流 UI(OPT-3,后端事件日志模块
  `c7be07b` 已开工,交付时按新对接文档**可选**接入,前端现在不预留)。
