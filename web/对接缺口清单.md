## 二、本轮 M3 已交付(前端已对接的部分)

### 2.1 API Key(原型页 07,`OPT-6`,提交 `50ee21a`)

端点(均挂空间下,需登录态;与页面权限一致):`GET` 列表 Viewer+ / `POST` 创建 Editor+ / `DELETE` 吊销 Editor+。

- **能力只有两个值**:`chat`(对话检索,覆盖 `/ask` 与 `/search`)、`documents`(文档管理);空 `capabilities` 合法但等于"什么都不能做"(后端 fail-closed);
- **明文仅一次**:`POST` 的 201 响应含 `plaintext`,列表接口**没有**该字段;服务端只存 SHA-256 与 `key_hint`,关掉弹窗后无法找回;
- **`kb_ids` 空数组 = 全部知识库**;非空 = 只能碰这些库,且范围必须在本空间内(否则 404);
- **吊销是软删除且幂等**(重复吊销仍 204),列表**包含已吊销项** —— 前端置灰展示;
- 程序侧用 `X-API-Key` 请求头(不是 Bearer);用 Key 访问未开放路由(如 `/users/me`)得 401 `AUTH_REQUIRED`;
- 错误码:401 `API_KEY_INVALID`(重试无用)、403 `API_KEY_CAPABILITY_DENIED`、403 `API_KEY_SCOPE_DENIED`。

### 2.2 对话页 SSE 两个变化(`OPT-1`/`OPT-2`,提交 `b92d7ac`)

- **心跳帧**:生成等待期约 15s 一条 `: ping` 注释行;解析时跳过所有不以 `data: ` 开头的行即可(现有实现已满足,实测确认);
- **断线不再丢答案**:生成中途断线时,已生成的部分答案会存成 assistant 消息,重拉 `GET .../messages` 可见;仍**没有续流**。

### 2.3 审计新增动作值(提交 `8865bd8`)

`user.updated`、`user.avatar_uploaded`、`user.avatar_deleted`,加上 API Key 的 `api_key.created`/`api_key.revoked`。
⚠️ **契约落后于源码**:`openapi.json` 只导出到 20 个动作值(缺 3 个 `user.*`),源码 `domain/enums.py` 已是 **23** 个。
前端映射表按源码补齐;等后端重导契约后一致。已记入 §四。

### 2.4 个人中心昵称校验

`PATCH /users/me` 现在校验昵称非空(空白 → 422),且该操作进审计。前端已有"昵称不能为空"的前置校验,行为一致。

## 三、本轮前端实测结果(可复核)

浏览器实测(真后端 + 真库,`:8000` 与 `:5173`):
