# 前后端对接标准(v1)

> **适用范围**:`web/` 前端与后端接口的全部对接工作(接口选用、改造、验收、缺口登记)。
> **版本与修订规则**:本版为 **v1(2026-09-17 定稿)**。规则:以"够用"为界,**非必要不改**;确需修改见 §9。
> **机器契约**:`docs/api/openapi.json`(字段、端点、枚举的唯一事实来源)。
> **后端进度快照**:M0/M1/M2 已交付,M3/M4 未开始(`VERSION` = 0.1.0)。详见 §3。

---

## 1. 三份文档的分工(不要互相掺内容)

| 文档 | 职责 | 不该写什么 |
|---|---|---|
| `web/对接标准.md`(本文) | 规则、流程、达标判据、后端能力分层 | 不写环境变量细节、不写逐条缺口 |
| `web/对接说明.md` | 环境变量、启动与联调步骤、token 键名、认证链路实现 | 不写缺口台账、不写标准 |
| `web/对接缺口清单.md` | 后端未提供能力的逐条台账(含证据与影响) | 不写流程标准 |

判断某条内容该写哪里:**"以后每次都这么做"→ 标准;"怎么跑起来"→ 说明;"后端现在没这个"→ 缺口清单。**

## 2. 事实来源与优先级(冲突时的裁决顺序)

1. **`docs/api/openapi.json`**(机器契约)——字段名、端点、枚举、必填性以此为准;
2. **后端 `docs/api/*.md`**(`m1-接口说明` / `m2-接口说明` / `契约补充对接说明` / `前端对接文档-*`)——流程、边界、前端要点;
3. **`docs/design/*.html`** 原型——视觉与交互基准。

裁决规则:

- 冲突时 **契约 > 说明文档 > 原型**;原型中契约不支持的部分**不实现**,记入缺口清单(不得用假数据补齐);
- 契约与说明文档都可能滞后于实现,**拿不准就以实测为准**,并把实测结果写回缺口清单(例:v2 文档声称模型未配置返回 `502 MODEL_NOT_CONFIGURED`,实测为 `500 INTERNAL_ERROR`);
- 说明文档的"已闭合"结论**需要复核**,不能直接采信(例:曾把缺口 #8 标为已闭合,实际未闭合)。

## 3. 后端能力分层(决定某个功能现在能不能动手)

**结论先行:M1、M2 已全量交付;M3(体验与治理)、M4(Agent 与上线)尚未开始。** 依据:提交历史、`docs/架构设计.md` §10 路线图、`VERSION`。

> 注:`README.md` 的里程碑勾选状态已过期(仍把 M1/M2 标为未完成),以路线图与提交为准。

### 3.1 L0 —— 现在就能对接(可直接进入实现)

| 原型页 | 状态 | 说明 |
|---|---|---|
| 01 登录/注册 | ✅ 可对接 | M1 |
| 02 对话 | ✅ 可对接 | M2 SSE;**Agent 工具调用的真实事件属 L2**,当前工具卡只能由 `citations` 合成,不承诺等同 M4 的 Agent 行为 |
| 03 知识库列表 | ✅ 可对接 | M2 + 第二轮聚合统计(`document_count`/`chunk_count`/`size_bytes`/`index_status`) |
| 04 知识库详情 | ✅ 可对接 | 文档状态机 + 检索测试(含请求级调参)+ 空间级检索参数 |
| 05 分块预览 | ✅ 可对接 | 分块列表含 `tokens`;单块全文接口已提供 |
| 06 空间管理 | ✅ 可对接 | M1 + 检索参数 |
| 08 审计日志 | ✅ 可对接 | 筛选(`action`/`actor_id`/`since`/`until`)、`result`、`actor_name` 已补;**导出属 L3** |
| 09 个人中心 | ✅ 可对接 | 头像三端点、`last_login_at/ip`、`current_space_id` 已补 |

**L0 判据**:端点已在 `openapi.json` 中、且后端已实现并有集成测试。满足即可动手,不需要"等后端确认"。

### 3.2 L1 —— 等 M3 才能做(现在做占位空态)

M3「体验与治理」范围(架构设计 §10):

- **API Key**(原型页 07)→ 目前唯一占位空态页,等 M3;
- **父子分块**(检索命子块、返回父块)→ 可能改变引用的载荷形态,届时需重新回归对话页引用抽屉;
- **问答插件链化** → 检索/问答流水线重构,可能影响 SSE 事件形态;
- **会话历史完善** → 具体形态待后端文档(可能涉及重新生成/编辑/分页);
- **审计补全**、**凭据加密完善**、**契约测试扩面**。

### 3.3 L2 —— 等 M4 才能做

M4「Agent 与上线」范围:

- **ReAct 运行时 + 工具注册表(`search_knowledge`)+ 工具输出防护** → 对话页 Agent 工具卡的**真实数据源**,届时以事件形式推送工具调用过程;
- **断线续流**:`docs/架构设计.md` ADR-3 已定设计(事件日志 + offset 增量拉取),但**代码里没有实现**(无事件日志模块、无 resume 路由),`m2-接口说明` 明确"续流在 M4 前随多副本一起上"。**在它交付前,前端不得依赖续流**:断线一律回退到 `GET /conversations/{cid}/messages` 重新拉取;
- **Go-Live 14 项翻转、备份恢复演练、冒烟**。

### 3.4 L3 —— 后端明确不实现(前端不渲染入口)

| 项 | 理由 | 前端处理 |
|---|---|---|
| 审计日志导出 | 产品决定不做(数据外带风险) | 不渲染"导出"按钮 |
| 邮箱体系 / SMTP 邀请 | 依赖 SMTP,邀请已改为按注册账号 | 邀请用账号,不写"邮件链接"文案 |
| 查看他人头像 | 需新增"按用户 id 取头像"接口,`avatar_url` 只对自己有意义 | 成员列表不渲染他人头像 |
| 入库各阶段耗时 | 属可观测性建设,随 M3 流水线一起做 | 不显示"12.4s"类耗时 |
| `meta.kind` 细分"标题" | 标题已作为面包屑并入分块内容 | 分块类型只呈现 段落/表格 |
| 头像上限写进契约 | FastAPI 无法把运行时配置写进静态契约 | 上限值(2MB/单边 4096px)写在文档与前端校验里 |
| 权重和 ≤ 1 的契约级约束 | OpenAPI 表达不了跨字段约束 | 前后端各写一份,文案保持一致 |

**分层判据(硬约束)**:只有 **L0** 允许进入实现;L1/L2 页面做占位空态,**不得渲染假列表/假数据冒充真实功能**;L3 一律不渲染入口。

## 4. 对接流程(固定 5 步,不跳步)

1. **同步契约** —— 从后端 worktree 取最新 `docs/api/openapi.json`;确认目标端点/字段已在契约中(L0 判据)。
2. **类型与 API 层** —— 先在 `src/api/types.ts` 与 `src/api/*.ts` 落地类型与函数;**只有 `src/api/` 允许 import axios**;401 刷新链等横切逻辑只能有一处实现。
3. **页面接入** —— 组件只调 API 函数,不直接拼 URL;三态(loading/空/错误)与角色显隐一并做,不留"稍后补"。
4. **冒烟** —— 按 §8 的环境基线跑真实链路,不满足"只看端口/只看构建通过"。
5. **登记** —— 新发现的缺口写进 `对接缺口清单.md`(含证据:实测响应或源码位置);契约与文档的矛盾也记在这里。

## 5. 达标判据(对接完成的定义)

**以下 7 条全部满足,即视为该页面对接完成。** 达标后**不再做视觉/交互打磨**——打磨属设计迭代,另开任务,不占对接工期。

- [ ] 1. **无假数据**:页面数据全部来自接口;全局搜索 `mock`/`fake`/`dummy`/硬编码数组零命中;
- [ ] 2. **三态齐备**:列表类页面有 loading(骨架)、空态、错误态,不白屏;
- [ ] 3. **权限正确**:按 `role` 隐藏入口,且收到 `FORBIDDEN`/`SPACE_NOT_FOUND` 时有人话提示兜底;
- [ ] 4. **错误可读**:统一按错误壳渲染;能按 `error.code` 分支的走分支,422 给字段级提示;
- [ ] 5. **破坏性操作有确认**:二次确认且文案说明后果(级联范围、不可恢复);
- [ ] 6. **构建零错误**:`npm run build`(含 `vue-tsc` 类型检查)通过;
- [ ] 7. **冒烟走通 + 缺口登记**:§8 对应路径实测通过,新缺口已入清单。

> 这 7 条是"达标线",不是"优化方向"。超过这条线的工作(动效、留白、文案润色)不作为对接验收内容。

## 6. 契约变更处理(后端前进时的固定动作)

后端改动契约后,前端按此顺序跟进,不逐次重谈流程:

1. **识别影响面**:对比 `openapi.json` 差异 → 受影响的类型、API 函数、页面;
2. **类型优先**:先改 `types.ts`,让 `vue-tsc` 把受影响页面全部报出来(这是类型检查的主要价值);
3. **新增枚举必须同步**:后端每新增一个动作码/状态值,前端对应映射表必须补齐(例:审计 `AuditAction` 已从 16 → 17 → **18** 项,新增 `access.denied`、`document.reparsed`);**未映射的值必须原样展示而非留空**;
4. **破坏性变更**:字段改名/删除、语义变化,须在缺口清单登记并复核受影响页面;
5. **回归**:只回归受影响页面 + §8 冒烟,不做全量重测。

## 7. 缺口处理规范

- **不编造端点**、不修改 `docs/api/openapi.json`、不自行补后端;
- **不渲染假数据**冒充真实功能(L1/L2 一律占位空态);
- 每条缺口必须带**证据**:实测响应片段,或源码文件:行号;
- 缺口条目写清**影响**(哪个页面哪个交互做不了),而不只是"缺接口";
- 后端补齐后,把条目从"仍缺"移到"已就绪/待接入",并注明后端提交号。

## 8. 联调环境基线(每次冒烟都按这套来)

```bash
make compose-dev-up                       # postgres + minio
make db-migrate                           # 迁移到最新
make parser-run                           # 解析服务
make worker-run                           # 入库 worker(不起则文档永远 pending)
make server-run                           # :8000
cd web && npm run dev                     # :5173,经 Vite 代理 /api → :8000
```

- **Windows 端口**:50051 落在系统保留段时,parser 改 `--addr 127.0.0.1:50071`,并以
  `PARSER_GRPC_ADDR=127.0.0.1:50071` 启动 server 与 worker(不必改 `server/.env`);
- **真实 Key**:向量化需 `DASHSCOPE_API_KEY`,问答需 `DEEPSEEK_API_KEY`;
- **代理**:后端无 CORS,前端禁止直连 `:8000`。

**冒烟最小路径(对接完成的实测依据)**:

1. 注册 → 自动登录 → 建空间 → 侧栏出现且角色为 Owner;
2. 建知识库 → 上传文档 → 状态走完 `pending → completed`;
3. 检索测试返回融合分与双路排名;对话页流式出答案且引用角标可打开抽屉;
4. 刷新页面(F5)→ 登录态与活动空间保持,历史会话可恢复;
5. 权限:切到低权限账号 → 管理入口消失,直连受限路由被拦;
6. 改密 → 被踢回登录页(会话已吊销)。

## 9. 本标准的修订规则

- 本版为 **v1**,目标是"够用":**非必要不改**;篇幅、措辞、示例的优化不构成修订理由;
- 仅在下列情形修订:分层判据变化、达标判据增减、流程步骤增减、事实来源优先级变化;
- 修订需写明**理由与影响面**;L0/L1/L2/L3 归属变化必须依据后端已合并的提交或契约。
